# 지식그래프 P3 갱신·재개 구현 기록

작성일: 2026-10-11. [상세 구현 계획](지식그래프_온톨로지_상세구현계획_2026-10-11.md)의 P3를 [P2 구조 투영](지식그래프_P2_구현기록_2026-10-11.md) 위에 구현했다. 모델 추출·그래프 검색·판정 UI·인계 v2는 이 단계에 포함하지 않는다.

## 변경과 현재 근거

`app/db/knowledge_dirty.py`의 SQLite 트리거는 원본 변경과 같은 트랜잭션에서 관련 문서·업무 job의 wanted revision을 올리고, 해당 파티션의 support 및 게시 세대를 즉시 무효화한다. 다른 DB 연결이나 직접 SQL 변경도 같은 경계를 거친다. 문서–업무 의존성은 투영 때 저장하고 기존 배정·근거·Case의 basis 문서도 함께 확인한다. 삭제는 FK CASCADE/SET NULL 이전에 의존성을 확인한다.

해시·분석 본문·파서·누락·배정·원본 항목·절차·수행 건·실행·산출물 변경은 재처리 대상이다. 실제 값이 같은 UPDATE, last_seen·진행 상태·교체 시각만 바뀐 UPDATE는 재투영하지 않는다. 이전 소속과 새 소속 모두 갱신한다. 색인 revision은 증가 여부와 관계없이 값의 변경을 비교해 rollback도 처리한다.

`kg_current_claims`는 게시된 활성 세대의 유효 support가 있고 거절되지 않은 주장만 제공한다. 마지막 유효 support를 잃으면 즉시 stale이며, 다른 파티션의 독립 근거가 남으면 현행 자격을 유지한다. 원본이 바뀐 이전 세대는 obsolete로 보존하며 재게시하지 않는다. 원본·Case·승인·실행 기록, 불변 인용 스냅샷과 사람의 판정 원장은 삭제하지 않는다.

파일 이동·이름 변경은 같은 문서 UUID를 유지한다. 해시가 바뀌면 새 DocumentVersion을 만들고, 재파싱은 같은 판본에서 인용과 parse fingerprint를 다시 확인한다. 재색인·rollback은 원문 위치·인용을 확인한 뒤 transient chunk만 연결한다. 누락 후 mark_seen은 자격을 복원하지 않으며 worker 재검증을 거친다.

실제 삭제된 Task/Case/Step/Artifact 및 항목 값 binding은 tombstone으로 남긴다. 정수 ID가 재사용되더라도 새 UUID를 발급하며, 삭제된 문서 ID의 메타 UUID도 폐기한다. 과거 주장과 스냅샷의 UUID는 유지한다. 앱이 만든 업무 정리본(`notebook_sources.origin='task'`)은 원문 인용의 독립 근거로 인정하지 않는다.

## 큐와 게시

v13은 job에 lease 만료 시각, 획득 당시 revision, 마지막 오류를 추가한다. v12→v13은 기존 SQLite 백업과 단계별 트랜잭션으로 수행하며, 실패 시 옛 버전·원장·열 정의를 되돌린다. 구조 투영 버전은 2다.

`app/core/knowledge/lifecycle.py`는 job 하나를 원자적으로 획득한다. 살아 있는 다른 worker의 lease는 회수하지 않는다. 만료된 lease만 회수하며, 초기 시도와 재시도 합계 최대 3회 뒤 failed로 보류한다. 실패한 문서가 다른 업무 처리를 막지 않는다. 명시적 cancel은 cancelled로 보존하며 resume으로 재개한다. 앱 종료·분석 중지의 협조 취소는 미완료 작업을 dirty로 돌려 다음 실행에서 자동 재개한다.

원문 인용 매칭은 쓰기 트랜잭션 밖에서 준비한다. 문서/업무 하나를 게시할 때 writer를 확보하고 입력 스냅샷을 재확인한다. 원본 fingerprint, wanted revision, lease token·만료, 취소 여부를 검사하며 게시 직전에도 검사한다. 바뀐 입력은 rollback하고 최신 job을 남긴다. 현재 단계는 모델 없는 구조 투영이므로 DB를 잡은 채 파서나 모델을 실행하지 않는다. 작업 시간 예산은 파티션 사이에서 적용하며, 한 파티션의 게시가 끝날 때까지 강제 잘라내지 않는다.

원본이 그대로인 예약·실패·취소는 이전 검증 세대를 보존한다. 원본 변경으로 이미 무효화된 세대는 실패해도 현행으로 복원하지 않는다. 전역 kg revision은 근거 무효화·세대 게시·사람 결정·사람 별칭 변경 때 증가한다. 사람 판정을 최종 게시 때 재생해 자동 재발견이 거절을 덮지 못하게 한다. undo의 undo도 원장 순서대로 적용한다.

이전 세대의 PRECEDES/SUPERSEDES를 새 후보의 순환 검사에 섞지 않는다. 새 후보와 다른 현재 파티션의 유효 관계를 합쳐 게시 전에 검사하므로, 과거 주장 UUID를 재사용해 만든 순환도 차단한다.

## 자동 실행과 동일성

분석 파이프라인 종료와 노트북 읽기 worker 종료 때 큐를 처리한다. 앱 셸은 2초마다 대기·만료 작업을 확인하고, 분석이 쉬는 동안 별도 SQLite 연결의 Qt worker로 처리한다. worker 한 번의 시간 예산은 2초이며 남은 큐는 다음 실행으로 이어진다. 앱 종료 시 함께 중지한다. 파생 그래프 오류는 진단으로 남겨 기존 분석·노트북 처리를 계속 사용할 수 있게 한다.

`resolution.canonical_entity()`는 명시적 identity merge/separate 판정과 정본 `tasks.merged_into`만 따라간다. 동명 후보를 자동 병합하지 않는다. 같은 유형의 서로 다른 UUID만 병합하며 순환은 거부한다. 원래 Claim 끝점·Case task_id·실행·승인·산출물 소속은 바꾸지 않는다. separate와 undo로 뷰를 되돌릴 수 있다. 업무 split은 기존 정본의 배정 변경만 다시 투영하고 Case를 복제하지 않는다.

내부 명령으로 큐 상태·오류를 확인하고 취소·재개할 수 있다. 기존 `project.db`가 있는 폴더만 연다.

```powershell
.\.venv\Scripts\python.exe -m app.tools.knowledge_project --project D:\경로\기존프로젝트 --jobs --seconds 5
.\.venv\Scripts\python.exe -m app.tools.knowledge_project --project D:\경로\기존프로젝트 --cancel task:1
.\.venv\Scripts\python.exe -m app.tools.knowledge_project --project D:\경로\기존프로젝트 --resume --jobs
```

## 검증과 다음 단계

최종 관련 회귀 **344건 통과(100.26초)**. 지식그래프 schema/projection/lifecycle/eval, migration, notebook_ingest, pipeline/coverage, action_runner, taskedit/refresh_integrity, reindex, workstore, transfer, crash_resume, UI smoke 및 job_lifecycle을 함께 실행했다. 보고서는 `.test_runs/knowledge-p3-final.xml`이다. 전체 저장소 회귀를 새로 실행한 결과와 합산하지 않는다.

개발 전용 RDF/SHACL 표준 검증 **27건 통과(4.54초)**. 표준 파일 재생성 대조, 런타임 잠금 파일 대조, `git diff --check`, 개발 환경 자체 점검도 통과했다. 저장소 guard는 이전부터 추적된 `.analysis_audit/` 파일 **1,981건**으로 실패한다. 이번 작업에서 이 파일을 삭제하거나 추적 해제하지 않았다.

Windows 실행물은 `PyInstaller --clean --noconfirm NunchiCoach.spec`로 최종 코드를 빌드해 통과했다. 번들의 투영 버전 2·스키마 버전 13·lifecycle/resolution/dirty 트리거/Qt worker 포함과 RDF/SHACL 개발 모듈 제외를 코드 객체 및 번들 SQL에서 확인했다. EXE의 `selftest tests/fixtures/sample_tree`는 합성 파일 77개 파싱과 복원→수행 기록→그래프 게시·원본 누락 제외·복귀 재검증→복원본→묶음→가져오기→재연결을 통과했다. 실제 HWP 및 실제 기관 자료 정확도는 이 결과에 포함하지 않는다.

검증은 합성 문서와 임시 SQLite 프로젝트를 사용한다. 원본 변경/누락/삭제의 즉시 제외, 원본 복귀, 다른 연결의 직접 쓰기, 정수 ID 재사용, 같은 해시의 이동, 재색인 rollback, 살아 있는 lease 보호, 실제 프로세스 비정상 종료 후 회수, 동시 dirty·사람 거절·스냅샷 경쟁, 실패 한도·취소·재개, 순서 반전·재사용 주장 순환, 동일성·업무 merge/split의 Case/실행 보존, 원문이 사라진 추출 Step, 백그라운드 연결과 Qt 종료를 확인한다.

다음은 P4 범위·검색이다. 선택 자료·업무·연도 범위, 그래프 검색과 RAG shadow 비교는 아직 연결하지 않았다. P5 판정 UI, P6 실제 자료·품질·규모 평가, P7 그래프 사람 판정의 인계 v2도 남아 있다. P0의 독립 정답 검토·실자료 확보 및 출하 게이트는 별도다. 현재 RAG에는 그래프를 섞지 않는다.
