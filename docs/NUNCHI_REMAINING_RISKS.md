# 남은 검증과 후속 단계

> **갱신일:** 2026-11-10

이 문서는 눈치코치(NunchiCoach)의 구현 완료 범위와 구분하여 **실제 기관 환경·실문서에서 추가로 확인해야 하는 검증 과제와 현재 동작의 구체적 한계**를 관리합니다.

## 1. 다음 착수 우선순위

1. **온나라 문서등록대장 실환경 검증 (`G1~G5`, `V1`, `P6` — 최우선 외부 대기):**
   - `onNara.sAIde`의 문서등록대장 머리글(`문서번호`·`단위과제`·`생산/접수`·`기안자`) 추출, 라벨 기반 검색 폼 조건 채우기(`search-form.ts`), 전체 페이지 순회(`inbox-pages.ts`), 50건 단위 꾸러미 분할 내보내기(`download.ts`) 및 눈치코치 브리지 수집 요청(`P2`)은 합성 DOM·단위 시험으로 검증되었다.
   - 실제 기관 온나라 화면 HTML 표본과 보안 정책(연속 열람·첨부 다운로드 제한 여부, 후임자 권한의 전임자 대장 조회 범위)을 확인한 뒤 셀렉터를 최종 보정하고 `live_verified=True`로 전환해야 한다.
2. **사무분장 기준 자료 분류 실자료 정확도 검증 (S7):**
   - 자료 단위(공문·폴더·낱장) 기반 탑다운 분장 분류(P1~P5)가 합성 표본에서는 구현·시험을 마쳤으나, 실제 기관 자료(규제개혁 1,044건 등) 및 담당자 정답 라벨셋 기반의 `classify_eval` 실측이 남아 있다.
3. **대표 업무 정의·실자료 평가셋 확정:**
   - 공문 기준 업무 골격(`P3`)과 로컬 PC 파일 5단계 대응(`P4a`), 공문↔로컬 비교(`P5`)의 실제 기관 폴더 정밀도·재현율을 담당자 라벨셋으로 측정한다.
4. **지식그래프 검색 실문서 정밀도 게이트:**
   - 합성 동결 질문 재현율(0.80)과 10,000문서 지연시간(p95 4.7ms)은 충족했으나, 실제 공문에서의 오탐률과 LLM 답변 A/B 비교를 마친 뒤 기본 검색 옵션을 켠다.
5. **대규모 성능·독립 PC 번들 운영 검증:**
   - 1만 파일 장시간 분석, 사본 인계 폴더(`P4b`) 대량 복사, 네트워크 공유 폴더 지연, 깨끗한 Windows PC에서의 번들 실행 및 인계자/인수자 사용성 시험이 남아 있다.

## 2. 현재 동작의 구체적 한계

- **사무분장 기준 탑다운 분류 (P1~P5):**
  - 분석의 기준이 되는 전임자 사무분장은 사용자가 직접 온보딩/설정에서 입력해야 한다(필수).
  - 이름 규칙 및 생성 모델 판정으로 분류되지 못한 자료 단위는 `판단 불가` 또는 `분장 밖`으로 분류되며, 사용자가 '자료 분류 확인' 화면에서 검토·교정해야 한다.
  - 작은 생성 모델이 근거로 분장 목록을 되풀이 인용하는 현상은 v2 프롬프트와 확신도 강등(`medium`)으로 보완했으나, 복잡한 비정형 문서에서의 모델 오판 가능성은 상존한다.
- **공문 기준 업무 발견(`P3`·`P4a`):**
  - 온나라 수집본이 없거나 분석 전이면 기존 폴더·본문 군집화 경로로 동작한다.
  - 5순위 임베딩 유사도 대응(`0.72` 이상 단독 1위)은 로컬 임베딩 모델(`bge-m3`)이 켜져 있어 문서 대표 벡터가 생성된 경우에만 작동한다.
- **공문 ↔ 로컬 비교(`P5`):**
  - `회신·결과 공문 미확인`(`unanswered_official`), `시행 등록 미확인`(`unregistered_final`), `공문 붙임 누락`(`missing_attachment`)은 수집된 공문 범위와 파일명·본문 신호로 추정한 확인 항목이며, 시스템 밖(우편·메신저·타 시스템)에서 처리된 내역까지는 알 수 없다.
- **조각 색인 및 파싱 한계:**
  - 파싱 자체에서 빠진 내용(손상된 파일, 암호화된 DRM 문서)은 색인으로 복원할 수 없으며 화면에 미추출·보호 상태를 명시한다.
  - 작명/일치성 모델은 예산 안의 대표 발췌만 읽으며 문서 전부를 검토하지 않는다.
- **사용자 결정 보존:**
  - 과거 사용자 해제 기록이 있는 문서는 자동 재배정하지 않는다.
  - 조사에서 제외한 기존 문서의 분석 이력은 보존되며 원본 삭제와 혼동해 이력을 지우지 않는다.
- **법령·지침 효력:**
  - 법령·지침의 현행 효력과 행정 절차의 공식성을 자동 보증하지 않으며, 명시 근거와 과거 수행 사례를 구분해 표시한다.
- **원본 불변성 및 출력 경계:**
  - 원자적 내보내기와 경로 재검증(`output_policy`), 사본 인계 폴더(`handover_folder`)는 원본 자료원 및 프로젝트 폴더 내부로의 출력을 거부한다.

## 3. 실제 자료 검증 시 필요한 입력

원본을 외부에 전송하지 않는 로컬 환경, 형식·업무 크기·연도별 대표 자료, 온나라 문서등록대장 HTML 표본, 담당자가 확인한 업무/문서 배정/핵심 사실/절차 정답이 필요하다. 실제 자료가 없으면 없는 상태를 유지하며 가상 수치나 합성 결과로 실환경 인수 기준을 채우지 않는다.
