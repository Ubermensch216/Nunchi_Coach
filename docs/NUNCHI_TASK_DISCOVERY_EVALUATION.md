# 업무 발견 반례 평가

기준일: 2026-10-10. 기준 코드 `73145c2`의 대표 벡터 군집과 새 전체 조각 후보 경로를
같은 합성 입력·임계값 0.82·최소 군집 3건으로 비교했다. 파일명 기반 보완 및 생성 모델의
작명 품질까지 포함한 과거 전체 파이프라인의 성적은 아니다.

## 평가 단위와 제한

7문서 = 보조금 정산 3 + 정보공개 청구 3 + 소방 점검 1.
모든 문서의 본문 앞 1,200자는 같으며 파일명은 `자료_001.txt`와 같이 정답을 숨긴다.
후반에 실제로 서로 다른 행정행위를 기술했다. `app/tools/discovery_eval.py:TOPICS`에
원문과 정답을 고정했다. 두 경로는 같은 원문과 같은 임베딩 모델을 사용한다.

기본 모드는 정답 방향을 의도적으로 구성한 제어 벡터다. 통합 동작 반례만 검증한다.
`--live` 모드는 실제 로컬 `bge-m3`로 벡터를 생성한다. 생성 모델의 작명은 비교에서 제외했다.

## 측정

| 모드 | 경로 | 발견 후보 | 같은 업무 짝 TP / 잘못 합친 짝 FP / 놓친 짝 FN | 짝 정밀도 | 짝 재현율 |
|---|---|---:|---|---:|---:|
| 제어 벡터 | 앞부분 대표 벡터 | 1 | 6 / 15 / 0 | 0.286 | 1.000 |
| 제어 벡터 | 전체 조각 + 개별 후보 | 3 | 6 / 0 / 0 | 1.000 | 1.000 |
| 로컬 bge-m3 | 앞부분 대표 벡터 | 1 | 6 / 15 / 0 | 0.286 | 1.000 |
| 로컬 bge-m3 | 전체 조각 + 개별 후보 | 3 | 6 / 0 / 0 | 1.000 | 1.000 |

제어 벡터 실험 0.704초, 로컬 임베딩 실험 24.336초. 측정 범위는 도구의 생성·색인·분류·
집계이며 실제 대규모 인수인계 전체 처리시간이 아니다. 환경은 Python 3.14.6,
Windows 11 build 26200, Intel Core i5-13500. 합성 원본 바이트 불변 검사를 통과했다.

원본 결과:

- `.test_runs/nunchi-discovery-controlled-20261010/result.json`
- `.test_runs/nunchi-discovery-live-20261010/result.json`

재개 후 v10 및 다른 작업의 `full-chunks-softidf-v2` 가중치 개선을 보존한 현재 코드에서도
같은 7문서 반례를 재실행했다. 짝 TP/FP/FN은 이전 6/15/0 → 개선 6/0/0, 후보 1 → 3으로
동일했고, 이번 실행은 13.956초였다. 결과는 `.test_runs/nunchi-discovery-resumed-live/result.json`,
읽기 전용 진단 출력은 같은 폴더의 `coverage.json`이다. 7문서·14부모 조각 모두 해당 모델로
색인됐고, 파싱 완전성은 미검증으로 출력했다. 작명 모델은 이 비교에서 호출하지 않았다.

**이 수치는 업무 발견 정밀도/재현율 95% 달성을 뜻하지 않는다.** 표본은 7건이며
21개 문서 짝은 서로 독립이 아니다. 독립 표본을 전제로 한 이항 신뢰구간을 붙이지 않는다.
실제 기관 문서·평가 전용 보류 세트·독립 라벨러는 사용하지 않았다.

## 함께 고정한 반례

`tests/test_discovery_coverage.py`에서 다음을 검증한다.

- 동일 앞부분·상이한 후반 업무의 분리와 후반 근거 역추적.
- 본문이 있는 단일 문서의 낮은 확신 후보 생성.
- 모델이 같은 이름을 제안해도 별도 군집 자동 병합 금지.
- `coherent=false` 시 보류·미배정 유지.
- 취소 시 기존 업무·배정 보존, 모델 호출 중 다른 DB 연결에서 사용자 교정 가능.
- 사용자가 해제한 배정을 단일 후보로 재생성하지 않음.
- 일부 임베딩 누락 시 앞부분 대체 경로를 명시.
- 실제 모델에 제공한 조각과 발췌 제공 표시 일치.
- 노트북 업로드 문서를 전임자 업무로 자동 발견하지 않음.
- 화면에서 후반 분류 근거 확인, 원문 변경 시 오래된 근거 재확인 표시.

## 대표 평가셋 확정 계획

업무 유형 / 사업·연도별 수행 사례 / 처리 단계를 별도로 라벨링하고, 다중 업무 문서는
다중 라벨을 허용한다. 정답은 이름 일치보다 업무 목적·행정행위·사업·기관·관계 근거를
우선한다. 복사본·수정본·연도 재사용본은 같은 계열로 묶어 개발/평가 세트 유출을 막는다.

단일 문서 업무, 이질 서식의 동일 업무, 공통 양식의 다른 업무, 비업무 자료, 업무가 여러
개인 문서를 포함한다. 독립 평가자는 같은 단위 정의로 정답과 근거를 확인한다.
업무 단위 정밀도/재현율, 문서 배정, 미분류, 병합/분할, 업무 크기별 결과를 따로 보고한다.
신뢰구간은 업무/문서 계열 단위 재표집을 검토한다. 대표 평가가 끝나기 전 확신 등급을
확률로 표시하거나 0.82를 새로운 전역 최적값으로 주장하지 않는다.
