# 화면 캡처 — 촬영 조건

최신 갱신일: **2026-11-10** · 소스 기준: 전임자 업무 분장 필수 입력, 시작 잠금 사유 인라인 표시, 자료 단위(공문·폴더·낱장) 분장 분류(P1~P5), 자료 분류 확인 대화상자, 업무 개요 종합 요약(`overview_summary`) 반영 상태. · 루트 [README](../../README.md)(사용 설명서)가 이 폴더의 이미지를 씁니다.

## 촬영 조건

- 현재 소스의 `MainWindow`·대화상자를 Windows에서 실제 PySide6 위젯으로 그려 `QWidget.grab()`으로 저장했습니다. 다시 그린 시안이나 생성 이미지가 아닙니다. 창은 화면에 띄우지 않고 오프스크린(`QT_QPA_PLATFORM=offscreen`)으로 렌더링했습니다.
- Pretendard 번들 글꼴 및 FreeType 벡터 글꼴 엔진(`text_rendering.configure()`)을 적용하여 렌더링했습니다.
- 자료는 합성 자료 및 시나리오 픽스처 기준이며 실제 기관 자료·개인정보는 포함되지 않았습니다.
- 주 화면 1440×960, 자료 폴더 연결 화면 1120×720, 대화상자는 각자의 규격 크기(720×480 ~ 880×640). 글자 크기 ‘보통’, 테마 ‘밝게’(23번만 어두운 테마).

## 2026-11-10 촬영 및 화면 현행화

1. **온보딩 화면 (`02-onboarding.png`) 현행화:**
   - 전임자의 업무 분장이 분석의 필수 기준으로 지정됨에 따라, 분장 입력란이 비어 있으면 '분석 시작' 단추가 잠기고 단추 옆에 이유(예: *"전임자의 업무 분장을 입력하세요"*, *"자료 폴더를 하나 이상 추가하세요"*)가 실시간으로 안내되는 최신 동작을 반영했습니다.
   - 스캔 직후 바로 확인할 수 있는 **자료 지도 (개괄)** 카드(폴더 트리, 문서 수, 연도 띠, 업무 비중)를 포함했습니다.
2. **설정 › 자료 폴더 (`21-settings-sources.png`) 현행화:**
   - 기존의 전임자 이름 입력란이 제거되고, 내가 맡은 업무 체계를 관리·저장할 수 있는 **전임자의 업무 분장** 카드가 추가된 최신 UI를 렌더링했습니다.
3. **업무 개요 종합 요약 (`30-work-guide.png`, `08-work-statements.png`):**
   - 개별 문장을 수십 줄 나열하던 기존 방식에서, 문장을 종합한 400자 이내의 **종합 요약**과 **핵심 키워드**(3~8개)를 업무 개요 맨 위에 먼저 배치하고, 원문 문장은 **근거 문장 N건 펼치기/접기**로 제공하는 최신 UI 구조를 반영했습니다.
4. **자료 분류 확인 대화상자 (`55-classification-review.png`) 신규 추가:**
   - P1~P5 프로세스에 따라 자료 단위(공문 건, 폴더 묶음, 낱장)가 사무분장 항목에 분류된 결과를 확인하고 사람이 직접 교정할 수 있는 대화상자 화면을 추가했습니다.
5. **업무 홈 및 상세 (`03-tasks.png`, `29-work-home.png`, `04~07`):**
   - 상단 4대 주 메뉴(업무·챙길 일·업무노트·인수인계)와 Pretendard FreeType 렌더링, 일정/진행 및 업무 자료(근거) 탭 통합 구조를 완결되게 반영했습니다.

## 촬영하지 않은 것

- **분석 상태 대화상자** — 단계별 결과는 그 창을 띄운 실행에서 돈 분석만 보여 줍니다. 촬영은 분석을 마친 프로젝트를 다시 열어서 했으므로 모든 단계가 ‘아직 시작하지 않았습니다’로 나와 싣지 않았습니다.
- 온나라 수집 — 앱에 화면이 없습니다.
- 전임자 검토 인계본 발행, 묶음 가져오기 결과, 값 고치기 같은 확인·입력 창 — 싣지 않았습니다.

## 다시 찍을 때

2026-10-12 UI01 추가: `27-initial-analysis.png`(라이트·기본 글자)와 `28-initial-analysis-paused.png`(다크·큰 글자)는 1120×720에서 `InitialAnalysisView`와 `TopBar`를 실제 Qt 위젯으로 조립해 오프스크린 `QWidget.grab()`으로 렌더링했다. 합성 DB에 문서 1건·업무 1개를 넣고 실행·중단 상태를 지정했으며, 진행 건수 12/40도 촬영용 값이다. 실제 파이프라인의 소요 시간이나 기관 자료의 분석 결과를 촬영한 것이 아니다. 최초 흐름·중단·결과 진입은 별도의 UI/서비스 시험으로 확인한다. 로컬 일회용 스크립트는 `.test_runs/render_ui01.py`다.

2026-10-09 추가: `24-notebook.png`는 통합 보고서 반영 작업 트리에서 촬영했다. 1700×980, 합성 TXT 1건(예산요구 안내), 모델 OFF 검색 전용 상태다. 분석 단계 자동 재개와 모델 예열을 막고, 실제 노트북 서비스의 검색 결과를 UI에 렌더링해 `QWidget.grab()`으로 저장했다. 기존 1~23번 화면의 90건/모델 촬영 조건과 다르다.

같은 날 노트북 개편 뒤 `24-notebook.png`를 다시 찍고 `26-notebook-home.png`를 추가했다. 1440×960, 테마 ‘밝게’. `tests/fixtures/전임자업무_샘플`의 프로젝트 DB **사본**에서 합성 행정사무감사 문서 5건을 연결했다. 대화의 답과 스튜디오의 업무 브리핑 초안은 이 PC의 `gemma4:e2b`·`bge-m3`로 실제 실행한 결과이고 주입하지 않았다. 세 번째 질문(전체 정리)의 보류는 프롬프트를 고치기 전 실행의 결과가 대화에 남은 것이다. 홈 화면의 나머지 노트북 4개는 촬영용으로 만든 빈 대화 노트북이다. 예열을 막고 `WA_DontShowOnScreen`으로 그려 `QWidget.grab()`으로 저장했다. `25-source-conflict.png`는 개편 전 화면 그대로다.

같은 날 `25-source-conflict.png`를 추가했다. 1700×1000, 개발 평가의 실습장 예약 안내 TXT 두 건을 연결한 별도 합성 프로젝트다. 로컬 모델 상태를 확인한 뒤 실제 노트북 질문 경로의 상충 판정을 렌더링했다. 생성 모델이 상충 판정을 만든 것은 아니다. 예열을 막고 `QWidget.grab()`으로 저장했으며, 근거 두 건 선택·노트 저장 거부는 UI/서비스 시험으로 확인했다.

1. 합성 자료로 새 프로젝트를 만든다. 실제 업무 프로젝트를 쓰지 않는다.
2. 분석이 끝난 것과 모델 상태를 확인하고, 사람의 입력 없이 찍거나 입력한 것을 이 문서에 적는다.
3. 화면을 바꾸면 이 목록, 촬영일·소스 기준, 루트 README의 설명을 함께 고친다.

저장소에 촬영 스크립트는 없습니다. 이번에는 `MainWindow._resume_if_pending`을 막아 분석이 다시 돌지 않게 하고, 화면을 차례로 열어 `grab()`으로 저장하는 일회용 스크립트로 찍었습니다.

캡처는 화면이 이렇게 생겼다는 기록입니다. 실제 사용자의 사용성, 기관 자료에서의 품질, 저사양 PC의 성능을 확인했다는 뜻이 아닙니다. 2026-09-15의 이전 캡처는 [`doc/screenshots/`](../../doc/screenshots/README.md)에 그대로 있습니다.

위와 같은 합성 DB 사본을 사용했다. 기본 크기는 제목 24/Bold, 구획 20/SemiBold, 카드·주요 값 17/SemiBold, 본문 15/Regular, 보조 13/Regular(논리 px)이다. 번들 Pretendard 실제 굵기와 안티앨리어싱 선호를 지정하고, 일정 셀도 표의 폰트를 사용한다. 10px로 고정됐던 월 숫자를 공통 보조 크기로 바꿨으며 카드 높이는 줄바꿈에 따라 늘어난다.

업무 홈·업무 안내·일정·문서·노트북 홈·설정을 렌더링해 확인했다. 추가로 `QT_SCALE_FACTOR=1/1.25/1.5`와 작게/보통/크게의 9개 조합에서 카드 설명 높이와 일정 표의 스크롤 범위를 검증했다. 이는 Qt 오프스크린 배율 검증이며 실제 모니터의 ClearType·다중 모니터 이동을 검증한 결과는 아니다. 렌더링은 PNG 원본 크기로 확인하며, 미리보기 확대·축소로 인한 보간은 글꼴 원본과 구분한다.

## 2026-10-20 Windows 글꼴 엔진·벡터 확대 비교

41번은 기존 DirectWrite 렌더링, 회색조 FreeType 렌더링, 기존 PNG 3배 확대, 72px 실제 재렌더링을 비교한다. 42번 SVG는 글자를 실제 벡터 path로 저장한 예시이며 비트맵이 없다. 43~45번은 이전과 같은 합성 DB 사본을 Windows FreeType 엔진·숨겨진 Qt 위젯으로 렌더링한 홈/업무 안내/어두운 테마·큰 글자 화면이다. 38~40번 이전 엔진의 기록은 유지한다.

별도 Windows 프로세스의 샘플에서 RGB 색 번짐 픽셀이 1,578개에서 0개로 감소했다. Windows 플랫폼의 배율 100/125/150%와 글자 크기 3단계도 조합해 확인했다. 실제 모니터의 확대 도구나 원격 화면 보간을 검증한 것은 아니다. 자세한 조건과 한계는 [폰트 벡터 렌더링 검토](../현재구현_및_검증현황.md)에 적었다.

## 2026-10-20 근거 탭
