# 수량 질문의 부재·단위 검증 후속 기록

2026-10-09. [앞선 질문 품질 평가](QUESTION_QUALITY_STAGE_2026-10-09.md)에서 남은 수량 부재 실패를 개선했다. 온나라 실연동 보류를 유지하며 커밋·푸시는 하지 않았다.

## 바뀐 동작

`정수기 수량은 몇 대야?`에 "수량에 대한 기록이 있습니다"라고만 답하던 경로를 수정했다. 기존 숫자·인용·속성 검증을 통과해도, 질문한 수량이 없으면 답변을 보류한다. "기록이 있다"를 수량 답변으로 저장하거나 지식으로 승격하지 않는다.

- `app/search/quantity.py`에서 답변의 수량·단위를 인용 원문과 대조한다. 인용하지 않은 다른 문서의 숫자는 사용하지 않는다.
- 연도·날짜는 수량으로 읽지 않는다. 층·관리번호 등은 그 단위를 직접 물었을 때만 수량 후보로 사용한다. `4층`을 근거로 `4대`를 답할 수 없다.
- `0건`, 부호·쉼표가 있는 숫자, `한 대`·`두 건` 등 지원하는 한글 수량 표현을 보존한다. "한 건도 없었다"는 1건이 아니며, "수량 정보가 없다"는 0건이 아니다.
- `명/사람`, `곳/개소`, `%/퍼센트` 등 같은 단위 이름을 대조한다. 다른 단위의 값을 임의로 환산하거나 합산하지 않는다.
- 이름표·표 칸에 묶인 무단위 숫자는 기존 속성 대조를 통해 보존한다. 원문에 묶인 수량이 없으면 단위 없는 관리번호를 대신 쓰지 않는다.
- 이 모듈이 아직 읽지 않는 `kg`·`km` 등의 측정 단위는 기존 검증에 맡긴다. 날짜·이유·산문 질문에도 수량 검사를 적용하지 않는다.
- 검증 때문에 모델을 추가 호출하지 않는다. 원문에 값이 있는데 모델이 답을 못 만들었을 수 있으므로, 보류 안내는 원문에 수량이 없다고 단정하지 않고 원문 확인·재질문을 안내한다.

진단은 `quantity_missing`(수량 없음), `quantity_unit_mismatch`(답변 단위 불일치), `quantity_unsupported`(수량을 원문에서 뒷받침하지 못함)로 남긴다. 기존 숫자 검증을 완화하지 않았으므로 한글 수량을 숫자로 바꾼 모든 모델 출력이 새로 허용되는 것은 아니다.

## 평가 자료와 해석

이전 2차 최종 세트는 이제 개발용이다. 원래 JSON과 동결 원장은 바꾸지 않고, 그 자료를 새 개발 묶음으로 가져왔다. 새 최종 20문항은 코드 변경 전에 별도로 동결했다.

- [최초 동결 원장](../tests/fixtures/rag_quantity_2026_10_09/frozen_manifest.json): 수량 수정 전 검색 코드 전체 해시와 개발/최종 자료 해시.
- [현재 개발 16문항](../tests/fixtures/rag_quantity_dev_v2_2026_10_09/dev.json): 이전 실패와 실제 수량 12·7·0·45의 양성 대조.
- [최종 20문항](../tests/fixtures/rag_quantity_2026_10_09/holdout.json): 새 업무·새 원문에서 수량 부재 8문항, 답할 수 있는 수량 10문항, 일반 질문 대조 2문항.

첫 개발 자료에는 실제 수량이 있는 별관 원문을 넣어, 같은 공간을 물었던 기존 음성 질문의 "수량 부재" 조건이 깨졌다. 모델이 별관 원문을 인용해 12대라고 답했기 때문에 이 실패 수치는 수정 효과의 비교에 사용할 수 없다. 개발 v2에서는 양성 대조를 별도 업무인 교육기자재의 모니터·프로젝터 수량으로 분리했다. 최초 자료·로그는 오류 진단 기록으로 남겼다. **최종 20문항의 원문·질문·채점 조건은 변경하지 않았고**, 개발 v2에 복사한 최종 파일도 최초 동결본과 바이트 단위로 같다.

개발 v2는 씨앗 0·1·2로 3회 모두 16/16, 합계 **48/48 통과**했다. 수량 부재를 보류하면서 수량이 있는 양성 답변과 0건을 보존했다. 이후 지원하지 않는 측정 단위를 기존 검증에 맡기는 경계를 정리하고 해당 회귀를 추가했다. 마지막 코드의 기능 시험은 208개가 통과했다. 현재 코드의 최종 20문항 평가와 전체 회귀는 아래에 별도로 기록한다.

문항과 정답은 같은 구현 작업에서 작성한 합성 자료다. 독립 작성자·기관 실자료·큰 잡음 자료에서의 성능으로 일반화하지 않는다. 생성 `gemma4:e2b`, 임베딩 `bge-m3`를 사용했고 각 최종 실행의 모델 프로필·설치 모델 digest·코드 해시·답변·진단을 JSON에 남긴다.

## 검증 기록

- 수량·단위·부호·제로/정보 부재·원문 범위·기존 RAG·노트북 관련 시험 208개 통과.
- 실제 모델 개발 평가: 48/48 통과. 최초 혼합 개발 세트의 수치는 개선률 비교에서 제외했다.
- 최종 20문항을 씨앗 0·1·2로 실행해 매회 19/20, 합계 **57/60 통과**했다. 아래 수치는 매회 동일하다.

세 번 모두 같은 `n-q07`이 실패했다. **“2026년 시설방문 담당 인원은 몇 명이야?”**에 `구민상담_접수결과.txt`의 방문상담 인원 19명을 인용했다. 해당 수량·단위는 인용 원문에 실제로 있으므로 이번 수량 검사를 통과하지만, 질문한 업무와 담당 인원을 뒷받침하지 않는다. 다음 과제는 이 대상 업무·역할 연결 결함이다. 최종 결과를 본 뒤 코드나 채점 조건을 바꾸지 않았고, 평가 JSON의 검색 코드 해시와 종료 시 코드가 일치함을 확인했다.

- 최종 전체 회귀: **1,335개 통과·1개 건너뜀·경고 1개**, 529.87초. 실제 모델 접속 시험을 포함했다. 기관 실문서 표본은 미제공이며, 경고는 기존 Qt 마우스 이벤트 생성자의 폐기 예정 안내다.

- 잠금 환경 검사 통과. 저장소 guard는 기존 `.analysis_audit` 추적 파일 1,981개 때문에 실패했다. Git 인덱스·이력은 변경하지 않았다.
- 로그: `.test_runs/quantity-holdout-final-20261009.json`, `.test_runs/quantity-holdout-final-20261009.log`, `.test_runs/quantity-full-final-validation-20261009.txt`, `.test_runs/quantity-bundle-validation-20261009.txt`, `.test_runs/quantity-bundle-selftest-20261009.txt`.

## 남은 범위

검사 대상은 지원하는 단위의 수량 질문과 원문에 묶인 수량이다. 문서 우선순위·효력, 일반 의미 충돌, 범위/비율의 모든 계산, 산문에서 대상과 수량을 연결하는 일반적인 의미 판정은 여전히 별도 작업이다. 기존 큰 질문 평가의 정답률 69.7%·근거 없는 확정 8.9%를 이번 작은 평가 결과로 대체하지 않는다. 기관 실자료와 저장소 guard 문제도 남아 있다.

다음에는 현재 최종 세트를 개발용으로 전환하고 새 최종 세트를 먼저 동결한 뒤, 질문의 대상 업무·역할과 인용 수량을 연결하는 검증을 개선한다. 그 뒤 노트북의 명시적 후속 질문 연결·파일/메모 추가·복제·변경 판본 재검토 화면을 구현한다. 실제 온나라 연동은 계속 보류한다.
