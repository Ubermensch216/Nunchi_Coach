# 눈치코치 업무 홈·업무별 매뉴얼 중심 개편계획서

작성일: 2026-10-10 · 기준: `dee8898` 작업 트리와 이번 사용자 결정

상태: **사용자 확정 방향을 반영한 설계·구현 계획. 구현 전.** 이번 작업에서는 문서만 작성·갱신했으며 제품 코드나 데이터는 변경하지 않았다.

**이번 갱신:** 최초 폴더 지정→분석 완료→큰 업무 폴더 카드→좌측 업무 목록과 우측 상세 화면의 흐름을 확정하고, 최초 처리 상태·화면 전환·시각·애니메이션·구현 단위·검증을 구체화했다. 세부 구현 기준은 12~16절이다.

본 문서는 기존 메뉴 재검토와 통합계획의 **홈·메뉴·일정·자료·매뉴얼 구성**을 대체한다. 실행 수명, 명시적인 업무 맥락 연결, 근거 판본, 승인 통제 등 기존 기술 원칙은 이어받는다. 아래 1절은 사용자 확정 사항이고, 나머지는 이를 실현하기 위한 구체 설계안이다.

## 1. 확정 방향

1. **첫 화면과 홈 메뉴는 ‘업무’다.** 홈에는 업무카드와 전체 업무의 연간 일정 대시보드를 함께 배치한다.
2. **일정 대메뉴는 만들지 않는다.** 일정은 개별 업무에서 다루고, 홈은 업무별 일정을 모아 연간 흐름을 보여 준다.
3. **자료 대메뉴는 만들지 않는다.** 자료는 분석 단계에서 업무와 연결하고, 해당 업무 페이지에서 조회한다.
4. **전임자 자료와 온나라 수집·동기화 자료를 함께 분석해 업무별 매뉴얼을 만든다.** 매뉴얼은 처음 맡는 사람이 업무를 이해하고 시작할 수 있는 안내여야 한다.
5. **업무별 매뉴얼을 노트북 소스로 활용한다.** 업무 설명에서 질문·비교·정리·초안 작성으로 이어지게 한다.
6. **최초 폴더 분석이 끝나면 업무 홈에 큰 폴더형 업무카드를 제공한다.** 카드를 한 번 클릭하면 좌측 업무 목록과 우측 상세 화면으로 들어간다.
7. **상세 화면의 좌측 목록에서 업무를 바꾸면 우측 내용이 바뀐다.** 선택 상태는 계속 표시하며, 디자인은 정돈된 여백·옅은 색면·짧고 절제된 애니메이션을 사용한다.

전임자가 없는 후임자가 얻어야 할 결과는 다음과 같다.

> “내가 해야 할 업무는 이것들이다. 연중 이 시기에 하고, 이 업무는 이런 결과물을 만드는 일이다. 지금은 이것부터 시작하면 된다.”

## 2. 전체 구조

```text
[프로젝트]   [업무 — 홈]   [노트북]                 [자료 연결·동기화] [설정]

업무 홈
 ├─ 업무카드: 업무 설명 · 결과물 · 시기 · 다음 행동
 ├─ 전체 업무 연간 일정 대시보드
 └─ 필요한 경우: 챙길 일 · 분석 상태 · 분류 확인 안내

개별 업무 페이지
 ├─ 업무 안내       업무의 목적·결과물·전체 흐름·첫 행동
 ├─ 일정·진행       해당 업무의 시기·기한·수행 건·준비 작업·체크리스트
 ├─ 업무 자료       전임자 원문·온나라 본문/붙임·서식·과거 결과·생성 문서
 └─ 매뉴얼          전체 내용·근거·적용 범위·판본·변경 이력
     └─ 노트북에서 묻기: 매뉴얼과 허용된 관련 원문을 소스로 연결
```

노트북의 별도 진입은 유지한다. 여러 업무를 비교하거나 업무와 무관한 자료를 조사할 수 있다. 다만 첫날의 기본 흐름은 업무 홈에서 시작하며, 매뉴얼을 활용하기 위해 사용자가 먼저 노트북을 만들 필요는 없다.

‘자료 연결·동기화’는 자료원 설정과 처리 상태를 여는 보조 동작이다. 전체 파일을 섞어 탐색하는 새로운 자료 대메뉴로 만들지 않는다. ‘오늘’도 별도 메뉴로 두지 않고 홈의 필요한 알림과 해당 업무의 진행 화면에 연결한다.

## 3. 업무 홈: 업무와 연간 흐름을 한 화면에서 이해

### 3.1 배치

홈의 주요 두 영역은 **업무카드와 연간 일정 대시보드**다. 하나를 보기 위해 다른 메뉴로 이동하지 않는다.

```text
업무
연결한 자료에서 파악한 업무입니다. 업무 하나를 열면 처리 방법을 안내합니다.

┌────────────────┬────────────────┬────────────────┐
│ 행정사무감사   │ 분기 실적 보고 │ 보조금 정산    │
│ 어떤 일인가   │ 어떤 일인가   │ 어떤 일인가   │
│ 주요 결과물   │ 주요 결과물   │ 주요 결과물   │
│ 시기/첫 행동  │ 시기/첫 행동  │ 시기/첫 행동  │
│ [업무 보기]   │ [업무 보기]   │ [업무 보기]   │
└────────────────┴────────────────┴────────────────┘

연간 일정                          [대상 연도 선택]
업무                  1월  2월  3월 ... 10월 11월 12월
행정사무감사                    업무별 시기·기한 표시
분기 실적 보고                  업무별 시기·기한 표시
보조금 정산                     업무별 시기·기한 표시

범례: 확인된 기한 / 준비 권고 / 과거 반복 패턴
```

업무명과 구성은 예시이며 실제 담당 업무나 일정이 아니다. 기본 데스크톱 창에서 카드 첫 줄과 연간 대시보드가 함께 발견되도록 높이와 간격을 설계한다. 업무가 많으면 카드 목록과 일정 행을 홈 안에서 확장·스크롤하고, 일부만 보이는 경우 표시 범위를 알린다. 화면이 좁아지면 위아래 배치를 유지하며 글자와 월 표시를 과도하게 축소하지 않는다.

### 3.2 업무카드 내용

카드에는 업무명, 쉬운 설명 한 문장, 주요 결과물, 시기 요약, 다음 행동 또는 현재 확인할 정보를 표시한다. 자료 수와 AI 분석 상태는 보조 정보다. ‘업무 후보’와 담당 여부가 확인된 업무를 구분한다.

확인된 임박 기한이 있으면 우선 표시한다. 그런 근거가 없으면 대표 결과물과 절차가 있어 이해하기 좋은 업무를 추천하고 이유를 적는다. 후임자에게 처음부터 업무 이름과 주기를 맞다고 확인하도록 요구하지 않는다.

### 3.3 연간 일정의 동작

- 행은 업무, 열은 1~12월이다. 현재 월과 선택 연도를 명확히 표시한다.
- **확인된 날짜·기한**, **준비 권고**, **과거 반복 패턴**은 기호·모양·문구로 구분한다. 과거 문서의 발생 시기를 올해 확정 일정처럼 표시하지 않는다.
- 여러 자료가 말하는 적용 연도와 기한을 확인한다. 문서 작성 연도를 제출 연도로 자동 대입하지 않는다.
- 업무카드를 한 번 클릭하면 해당 업무 상세를 연다. 카드에 마우스나 키보드 초점을 두면 일정의 해당 행을 강조할 수 있다. 일정 항목을 선택하면 **해당 업무의 일정·진행**에서 그 연도·수행 건·근거를 연다.
- 월을 선택하면 관련 업무를 강조하거나 필터링하며 선택 상태와 해제 방법을 보여 준다. 클릭 없이 전체 연간 흐름을 볼 수 있어야 한다.
- 시기를 파악하지 못한 업무도 카드에 남기고 ‘시기 확인 필요’로 안내한다. 일정에 표시할 수 없다고 업무 자체를 숨기지 않는다.
- 기한이 다른 반복 회차는 개별 수행 건으로 표시하고, 반복 패턴은 배경 정보로 둔다.

홈 대시보드와 업무 상세는 같은 일정 객체를 읽는다. 홈에 별도의 기한을 입력·저장하는 구조는 만들지 않는다.

### 3.4 자료 준비 전과 이후

처음에는 업무 홈 안에서 전임자 폴더 연결을 안내한다. 최초 분석 중에는 진행 화면을 제공하고, 분석 결과가 저장된 뒤 업무 폴더 카드와 연간 대시보드가 있는 홈으로 이동한다. 이번 확정 흐름에서는 분석 중 변하는 후보 카드를 기본 홈으로 먼저 노출하지 않는다. 일부 자료를 읽지 못한 채 결과를 제공하는 경우에는 ‘일부 자료 미분석’을 명시한다. 아직 일정을 찾지 못하면 ‘일정 없음’ 대신 확인할 자료를 안내한다.

자료가 전혀 없으면 업무와 매뉴얼을 만들어 낼 수 없으므로 필요한 자료 유형을 설명한다. 노트북만 사용하려는 사람은 별도 진입으로 바로 시작할 수 있다. 홈 이름과 기본 목적지는 항상 업무로 유지한다.

## 4. 개별 업무 페이지: 이해와 수행의 완결 단위

개별 업무 화면은 **좌측 업무 목록 + 우측 메인 화면**으로 구성한다. 좌측에서 선택한 업무를 강조하고, 다른 업무를 누르면 같은 자리의 우측 내용이 바뀐다. 우측 상단에는 업무명·짧은 목적·선택 연도/수행 건·현재 확인된 기한·다음 행동을 둔다. 자료와 절차를 읽을 때만으로 올해 수행 건이 자동 생성되지는 않는다. 실제 준비·수행을 시작할 때 필요한 수행 건을 연결한다.

| 화면 | 기본 내용 | 대표 행동 |
|---|---|---|
| **업무 안내** | 목적, 대상, 최종 결과물 예시, 시작 계기, 전체 처리 흐름, 현재 자료에서 확인된 위치, 첫 행동 | 대표 결과물 보기, 진행하기, 노트북에서 묻기 |
| **일정·진행** | 업무별 연간 시기, 선택 연도/회차의 기한·단계·준비 작업·승인·체크리스트·수행 결과 | 근거 확인, 준비 작업 시작·재개, 단계 기록 |
| **업무 자료** | 대표 자료, 전임자 원문, 온나라 본문/붙임, 서식, 과거 제출본, 생성 결과 | 업무 안 검색·필터, 원문 보기, 연결 교정 |
| **매뉴얼** | 해당 업무의 전체 매뉴얼, 근거, 적용 범위, 자료 누락·상충, 판본·변경 이력 | 내용 확인·보충, 갱신 내용 보기, 노트북 소스로 사용 |

‘업무 안내’는 매뉴얼과 업무 상태의 핵심을 읽기 쉽게 보여 주는 기본 화면이다. 별개의 AI 요약을 계속 생성해 매뉴얼과 서로 다른 설명을 하지 않도록 **같은 구조화된 내용에서 요약과 전체 보기를 제공**한다. 수시로 변하는 진행률·승인 상태는 수행 기록에서 조회한다.

업무 안내에서는 목적부터 첫 행동까지 탭을 바꾸지 않고 파악할 수 있어야 한다. 상세 근거·모든 원문·판본 이력은 필요할 때 확장한다. 담당자·관계 부서·제출처는 자료의 기준 시점을 함께 표시하며 현재 유효성이 불명확하면 그렇게 알린다.

과거 사례와 올해 수행은 연도·회차로 구분한다. ‘최근 기록 이후 자료 없음’을 ‘아직 처리하지 않음’으로 단정하지 않는다. 자료가 불충분한 영역은 확인할 내용과 다음 확인 방법으로 표시한다.

## 5. 업무별 자료 구성과 분류 예외

### 5.1 분류와 연결

전임자 폴더와 온나라 자료는 공통 문서 등록·내용 분석을 거쳐 업무에 연결한다. 파일명·폴더 경로는 단서로 사용하되 본문·문서 역할·업무 목적·연도·문서 관계를 함께 살핀다.

한 자료가 여러 업무에 쓰이면 각 업무에 **동일 문서 ID를 연결**한다. 업무별로 원본 파일을 복사하지 않는다. 본문과 붙임은 관계를 보존하고, 붙임이 다른 업무에도 해당하면 별도 업무 연결을 허용한다.

기존 `task_docs`는 업무와 자료의 다대다 관계와 AI/사용자 연결 정보를 보유하므로 우선 재사용한다. 사람이 고친 연결·대표 자료 지정·업무 이름을 재분석이 덮어쓰지 않도록 한다.

### 5.2 업무 자료 화면

상단에는 ‘먼저 읽을 자료’와 추천 이유를 제공하고, 아래에서 업무 자료를 검색한다. 필터는 자료 출처, 대상 연도, 역할, 판본, 분석 상태를 중심으로 한다.

- 전임자 자료 / 온나라 자료는 출처 필터이며 서로 다른 저장소처럼 분리하지 않는다.
- 원문·서식·과거 결과물과 **이번에 만든 문서**는 구별한다. 생성 문서를 자동으로 1차 근거 자료에 편입하지 않는다.
- 최신 판본과 올해에 적용되는 기준은 별개로 표시한다.
- 다른 업무에도 연결된 자료는 해당 관계를 표시한다.
- 원본 없음·읽기 실패·일부 분석 상태를 조회와 매뉴얼 근거에 반영한다.

### 5.3 미분류·잘못 분류된 자료

초기 분석에서 모든 자료가 정확히 분류되었다고 가정하지 않는다. 그렇다고 전 자료 메뉴를 다시 만들지도 않는다.

- 분류가 애매하면 `업무 연결 확인 필요`로 남기고 후보 업무와 이유를 제시한다.
- 업무 홈의 작은 ‘분류 확인 N건’ 안내에서 **예외 자료만** 확인하는 패널을 연다. 시작 안내를 완료하기 위한 필수 관문으로 만들지 않는다.
- 업무 안에서는 ‘다른 업무에도 연결’, ‘연결 해제’, ‘잘못 분류됨’ 등을 통해 교정한다. 처음 업무를 모르는 후임자는 보류할 수 있다.
- 분류가 안 된 자료를 숨기거나 임의의 업무에 강제 배정하지 않는다. 검색으로 찾은 미연결 자료는 검토 후 해당 업무에 연결할 수 있게 한다.
- 연결 변경·업무 합치기·나누기는 영향받는 일정·매뉴얼·노트북 연결을 다시 평가하고 변경 전 이력을 남긴다.

분류 근거가 약한 자료는 매뉴얼의 확정 근거로 무조건 사용하지 않는다. 후보 연결 상태를 표시하고 중요한 수치·기한이 그 자료에만 의존할 경우 공백·확인 항목으로 다룬다.

## 6. 업무별 매뉴얼

### 6.1 목적과 구성

매뉴얼은 **처음 맡은 사람이 실제 업무를 시작할 수 있도록, 원문에서 복원한 업무 지식을 구조화한 결과물**이다. 업무마다 다음 항목을 같은 순서로 제공한다.

| 항목 | 담을 내용 |
|---|---|
| 업무 개요 | 쉬운 설명, 목적, 담당 범위, 적용 대상 |
| 결과물 | 무엇을 만들어 어디에 전달하는지, 실제 예시·서식 |
| 시작과 시기 | 시작 계기, 반복 시기, 연도별 확인된 기한과 근거 |
| 준비사항 | 준비 자료, 서식, 관련 규정, 협조 부서·담당 역할 |
| 처리 절차 | 단계별 입력·행동·결과·근거. 공식 절차/과거 사례/제안 구별 |
| 유의사항 | 자료에 나타난 오류·반려·누락 사례와 적용 범위 |
| 과거 수행 | 연도별 실제 처리 사례, 결과물, 확인 가능한 차이 |
| 현재 시작점 | 지금 확인할 정보, 첫 행동, 진행 화면으로 가는 길 |
| 근거와 공백 | 원문 위치·판본, 상충 내용, 자료 부족, 다음 확인 방법 |

알 수 없는 항목은 비워 두는 대신 ‘현재 자료에서 확인되지 않음’과 가능한 다음 행동을 제공한다. 문서 속 상충을 그럴듯한 단일 설명으로 합치지 않는다. 사람에게 검수를 모두 끝내야 읽을 수 있다고 요구하지 않는다.

### 6.2 생성 파이프라인

```text
전임자 폴더 + 온나라 수집·동기화 자료
   → 문서 등록·출처·본문/붙임·판본 확보
   → 내용 분석·업무 연결·문서 역할·적용 연도 판별
   → 업무별 사실·절차·일정·결과물·공백 정리
   → 근거가 연결된 구조화 매뉴얼 생성
   → 업무 안내/매뉴얼 화면 제공
   → 매뉴얼 판본을 노트북 소스로 연결
```

기존 `core/workcard.py`의 업무 항목과 `core/notebook_tasks.py`의 업무 정리본을 확장한다. 지금도 설명·주기·준비·처리 순서·확인할 정보와 근거를 노트북 자료로 만드는 기반이 있다. 다만 이를 **매뉴얼의 내용 계약·판본·구간별 출처·갱신 정책**까지 갖춘 계층으로 발전시켜야 한다.

추출 가능한 값과 상태는 규칙·기존 구조를 우선 사용하고, 모델은 쉬운 설명과 근거 있는 문장 정리에 사용한다. 생성 후 핵심 날짜·숫자·기관명·적용 연도와 인용 연결을 검증하며, 자동 검사만으로 의미 정확성을 모두 보장했다고 표시하지 않는다.

### 6.3 판본과 갱신

매뉴얼에는 업무 ID, 판본, 적용 범위/연도, 입력 자료 ID·해시, 구간별 근거, 생성 방식·시점, 사람의 보충·수정 이력을 보존한다. 구체 표 이름은 구현 설계에서 정하되 기존 문서·인용 ID를 재사용한다.

- 새 자료·변경된 원문·업무 연결 교정이 생기면 영향받는 업무와 매뉴얼만 갱신 대상으로 표시한다.
- 짧은 시간의 연속 동기화는 묶어 처리하고, 동일 입력으로 동일 판본을 반복 생성하지 않는다.
- 새 판은 이전 판을 덮지 않고 비교 가능한 이력으로 남긴다. 새 판 생성에 실패하면 마지막 정상 판과 갱신 필요 표시를 유지한다.
- 사람이 보충한 내용은 출처와 함께 별도로 보존하고 자동 생성으로 지우지 않는다. 새 원문과 충돌하면 차이를 보여 준다.
- 근거가 없는 상태를 숨기지 않는 자료 기반 매뉴얼은 사람이 모든 항목을 확인하기 전에도 제공한다. ‘읽을 수 있는 매뉴얼’과 ‘사람이 확인한 매뉴얼’을 구분한다.
- 실시간 체크리스트·승인·완료 상태는 수행 데이터로 관리한다. 매뉴얼의 과거 수행 사례는 작성 당시의 기록으로 표시한다.

## 7. 매뉴얼을 노트북 소스로 활용

업무에서 ‘노트북에서 묻기’를 누르면 해당 업무의 기본 노트북을 열거나 만든다. 소스 목록에 **업무 매뉴얼·판본·적용 범위**가 보여야 한다. 필요한 관련 원문은 범위를 명시해 함께 연결한다.

| 기능 | 동작 |
|---|---|
| 업무 이해 질문 | 매뉴얼의 설명·절차를 활용하고 원근거를 열 수 있게 함 |
| 올해/작년 비교 | 대상 연도와 관련 판본·자료를 명시하여 비교 |
| 문서 초안 | 매뉴얼의 업무 구조와 허용된 원문 근거를 사용, 미확인 항목 표시 |
| 여러 업무 비교 | 사용자가 선택한 업무의 매뉴얼을 함께 연결하고 답변의 업무별 근거 구별 |
| 새 매뉴얼 판 도착 | 사용 가능한 새 판을 알리고 갱신 시점과 차이 표시. 진행 중 질문의 소스는 고정 |

매뉴얼은 파생 지식이므로 AI 답변이 매뉴얼을 인용할 때 해당 구간의 원문까지 추적할 수 있어야 한다. 매뉴얼과 원문을 독립된 두 증거처럼 중복 계산하지 않는다. 숫자·기한·의무를 설명할 때 현재 적용 가능한 근거가 없으면 그 한계를 답한다.

원문 연결이 현재 선택·허용 범위 밖이면 조용히 범위를 넓히지 않는다. 소스를 추가할 수 있는 경로를 제공하거나 현재 범위에서 확인할 수 없다고 알린다. 매뉴얼만 선택한 질문에서는 원문을 직접 확인한 것처럼 표현하지 않는다.

과거 대화·산출물은 사용 당시 매뉴얼과 원문 판본을 보존한다. 새 판을 연결해도 옛 인용이 다른 내용으로 바뀌지 않게 한다. 업무 맥락은 자료에 업무 정리본이 들어 있다는 사실만으로 추정하지 않고 명시적으로 연결한다.

**업무 원문 → 매뉴얼 → 노트북**의 파생 관계를 유지한다. 매뉴얼·노트북 답변·생성 초안을 업무 발견의 원자료로 재투입하는 순환은 만들지 않는다. 사람이 검토한 지식의 업무 반영은 기존 별도 절차를 따른다.

## 8. 온나라 동기화와 현재 구현의 연결

현재 [온나라 연결 프로필](온나라_연결프로필.md)과 코드는 실제 기관 연결이 미확보·미검증임을 명시한다. 수집 계약·합성 연결부·수집본 가져오기와 공식 출처 연결은 있으나 **실제 기관 동기화가 완료된 상태는 아니다.**

이번 계획에는 온나라 자료를 업무 중심으로 받는 경로와 실제 연결 검증을 모두 포함한다.

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 공통 수집 경로 | 기존 수집본 가져오기를 특정 노트북 없이 프로젝트 자료에 등록할 수 있게 분리 | 전임자 자료와 같은 업무 분류·매뉴얼 파이프라인에 연결 |
| 기관 연결 검증 | 실제 제공되는 접근 방식, 인증, 작성자·부서·기간 범위, 본문/붙임 확보 방식 확인 | 제한된 표본으로 원문·메타데이터·누락/실패를 대조 |
| 증분 동기화 | 새 문서·판본 변경 감지, 중복 방지, 인증 만료·실패 재개 | 같은 자료를 다시 받아도 중복 업무·매뉴얼 생성 없음 |
| 업무 반영 | 영향받는 업무 자료·일정·매뉴얼의 변경을 알림 | 사용자가 어떤 업무에 무엇이 바뀌었는지 확인 |

문서 식별은 기존 기관·시스템·문서 ID와 본문/붙임 관계를 활용한다. 동기화 시각과 문서의 작성·시행·제출 시점은 구별한다. 온나라에 등록되었거나 결재가 완료되었다는 사실만으로 올해 업무에 적용된다고 단정하지 않는다.

수집 목록에서 사라진 문서는 권한·검색 범위·원문 변경 여부가 불명확할 수 있으므로 기존 근거·매뉴얼·대화를 즉시 삭제하지 않는다. 마지막 확보 범위·성공 시점·일부 실패를 표시한다. 실제 동기화 화면에서는 검증된 연결 방식만 활성화하고, 수집본 가져오기와 실제 접속을 구분해 설명한다.

기관 연결 사양이 없어도 홈·업무 자료·매뉴얼·노트북 연결은 전임자 자료와 확보된 수집본으로 구현·검증할 수 있다. 실제 동기화 완료 여부는 별도 결과로 보고한다.

## 9. 단계별 구현 계획

| 단계 | 주요 작업 | 우선 재사용할 기반 | 완료 기준 |
|---|---|---|---|
| **P0: 업무 데이터 정합성** | 업무 자료 연결·분류 예외·일정 공통 조회·매뉴얼 내용 계약과 근거 모델 정리 | `task_docs`, 업무 발견·복원, 일정 계산, `workcard` | 한 업무의 자료·일정·설명이 같은 업무/연도를 가리킴 |
| **P1: 업무 홈** | 업무카드+연간 대시보드, 교차 강조·업무 이동, 일정/자료 대메뉴 제거 | `TasksView`, `CalendarView`의 조회·격자, 셸 | 홈에서 업무와 연간 흐름을 함께 보고 해당 업무로 이동 |
| **P2: 개별 업무 페이지** | 업무 안내·일정/진행·업무 자료·매뉴얼 영역 구성, 수행 건·연도 전달, 작업 지속성 | 기존 업무 상세·문서 목록·실행 서비스 | 업무 밖의 전체 자료 화면을 거치지 않고 이해·자료 확인·진행 가능 |
| **P3: 매뉴얼 생성과 노트북** | 업무별 매뉴얼 생성·판본·출처·갱신, 노트북 연결과 과거 인용 보존 | `notebook_tasks`, 수집 워커·노트북·출처 검사 | 실제 생성된 업무 매뉴얼로 질문하고 원문까지 확인 |
| **P4: 온나라 실제 동기화** | 공통 수집 경로, 기관 연결 검증, 증분 수집·업무별 변경 반영 | 기존 온나라 계약·수집·`provenance` | 실환경의 새 자료가 해당 업무와 매뉴얼에 추적 가능하게 반영 |
| **P5: 통합 검증·문서** | 처음 맡는 사용자 과제, 회귀·이전·배포 검증, 설명서·화면 현행화 | 기존 시험·표본 프로젝트 | 전임자 없이 업무 파악→첫 행동→결과 재조회 흐름 검증 |

P4의 기관 사양 확인은 초기에 병행한다. 수집본을 업무 분석에 연결하는 공통 경로는 P0~P3에서도 사용하며, P4 전체 완료를 앞 단계의 조건으로 두지 않는다. 실제 코드 분할 순서는 데이터·실행 서비스의 의존성을 우선한다.

기존 파일을 옮기는 것으로 끝내지 않는다. `documents.py`는 업무 범위가 고정된 자료 패널로 재사용하고, `calendar.py`는 홈의 집계와 개별 업무의 일정 표현으로 분리한다. 업무 ID 필터를 UI에만 적용하지 않고 조회·검색·동작 계층에서도 유지한다.

기존 메뉴 단축키·내부 이동 요청은 새 목적지에 맞춰 갱신한다. 과거 일정 링크는 홈 대시보드 또는 해당 업무 일정으로, 문서 링크는 연결된 업무의 자료 또는 근거 패널로 연결한다. 여러 업무에 걸친 원문은 현재 업무 맥락을 우선하며, 미분류 자료는 예외 확인 경로로 연다. 사용자가 별도 일정·전체 자료 메뉴로 되돌아가게 하지 않는다.

## 10. 데이터 보존과 검증

기존 프로젝트·업무 ID·문서·대화·메모·근거·승인·생성 결과를 보존한다. 매뉴얼과 맥락 연결을 위한 스키마 변경은 백업과 마이그레이션으로 수행한다. 기존 업무 정리본은 과거 판으로 열 수 있게 하고 새 매뉴얼을 생성할 때 명시적으로 연결한다.

| 검증 영역 | 필수 시나리오 |
|---|---|
| 홈 | 카드와 연간 일정 함께 노출, 업무 많음/없음, 일정 불명, 분석 중, 좁은 창·배율·키보드 |
| 일정 | 동일 기한의 홈/상세 일치, 올해 기한과 과거 패턴 구분, 연도·회차를 보존한 이동 |
| 업무 자료 | 단일/다중 업무 연결, 미분류·오분류·분석 실패, 본문/붙임 관계, 사람 교정 보존 |
| 업무 분리 | 다른 업무 자료가 무단으로 섞이지 않음, 공유 자료는 명시적 연결일 때 조회 |
| 매뉴얼 | 근거 없는 기한 생성 금지, 상충 유지, 사람 보충 보존, 부분 자료·생성 실패, 변경 시 영향 업무만 갱신 |
| 노트북 | 매뉴얼이 실제 소스로 조회됨, 원근거 추적, 소스 범위 유지, 새 판 적용 후 과거 인용 보존 |
| 온나라 | 동일 자료 재수집, 부분 실패·인증 만료·재개, 출처 ID 유지, 변경/누락 문서 처리, 실제 연결 결과 구분 |
| 수행 | 메뉴 이동 중 실행 유지, 정확한 수행 건, 승인 유효성, 중단·종료·재개, 산출물 업무 귀속 |
| 이전·배포 | 기존 DB 재개, 백업·승격, 기존 정리본·노트북·출력 파일 보존, 번들 구동 |

사용자 시험에서는 ① 맡을 업무 설명 ② 전체 업무의 연간 흐름 설명 ③ 업무 하나의 결과물·첫 행동 선택 ④ 해당 업무 자료 찾기 ⑤ 매뉴얼을 소스로 질문 ⑥ 올해와 과거 정보 구분을 확인한다. 클릭 수나 확인 체크 수를 업무 이해도라고 표시하지 않는다.

제품 코드 변경 후 관련 시험과 단계별 전체 회귀를 실행한다. 본 계획 수립에서는 코드를 변경하지 않았으며 통과 수·효과를 새로 측정하지 않았다.

| 구분 | 내용 |

## 12. 최초 사용 프로세스와 화면 상태

### 12.1 기본 흐름

```text
프로젝트 열기
  → 전임자 자료 폴더 지정
  → 선택 경로 확인·분석 시작
  → 자료 읽기·업무 파악·일정/절차 정리
  → 분석 결과 저장
  → 업무 홈: 큰 폴더 카드 + 연간 일정
  → 카드 클릭
  → 업무 작업 화면: 좌측 업무 목록 | 우측 업무 정보
  → 좌측의 다른 업무 선택 → 우측 내용 전환
```

폴더 선택은 기존 로컬·USB·공유 폴더 선택기를 재사용한다. 한 폴더로 바로 시작할 수 있고 추가 폴더 연결도 허용한다. 선택 경로·접근 가능 여부·읽을 수 있는 자료 범위를 확인하고 ‘업무 분석 시작’을 주 행동으로 제공한다. 생성된 업무 폴더는 화면 안의 논리적 묶음이며 실제 원본 폴더를 재배치하지 않는다.

최초 실행에서 온나라 설정을 필수 단계로 요구하지 않는다. 전임자 자료로 먼저 업무를 파악하고, 추후 연결한 온나라 자료는 같은 업무에 증분 반영한다. 기존 프로젝트는 저장된 업무 홈을 바로 열며 추가 분석 때문에 초기 진행 화면으로 돌아가지 않는다.

### 12.2 분석 중 표시

사용자에게는 ‘자료를 읽고 있습니다 → 업무를 나누고 있습니다 → 일정과 처리 방법을 정리하고 있습니다 → 업무 화면을 준비하고 있습니다’처럼 목적 중심으로 설명한다. 기존 실제 처리 단계를 이 표현에 연결하고, 실행하지 않은 단계를 완료로 표시하지 않는다.

단계·처리 건수·실패 건수와 중단·재개 경로를 제공한다. 전체 소요량을 알 수 없으면 불확정 진행 표시를 쓰고, 임의의 백분율·예상 시간을 만들지 않는다. 진행 중 앱을 껐다 켰을 때는 저장된 결과와 기존 재개 규칙을 활용한다.

### 12.3 분석 완료와 예외

‘완료’는 모든 정보를 알아냈다는 뜻이 아니다. 분석 대상과 완료·실패·보류 결과가 저장되고, 업무 목록과 그 업무의 설명·자료·시기 또는 확인할 공백을 조회할 수 있는 상태를 뜻한다. 업무 분류 핵심 단계가 실패했는데 빈 목록만 있다는 이유로 성공 처리하지 않는다.

| 상태 | 제공할 화면/행동 |
|---|---|
| 자료 선택 전 | 폴더 지정과 분석 시작 |
| 분석 중 | 단계·처리 범위·중단·재개 |
| 정상 완료·업무 있음 | 최초 분석 진행 화면을 보고 있다면 업무 홈으로 한 번 이동 |
| 일부 파일 실패·업무 있음 | ‘일부 자료를 분석하지 못했습니다’와 결과 보기·실패 자료 확인. 성공한 업무 결과는 사용 가능 |
| 읽을 자료 없음·접근 불가 | 폴더 수정·다시 선택. 가짜 업무카드 생성 금지 |
| 분석했으나 업무를 파악하지 못함 | 원인·자료 보완·다시 분석 경로. ‘맡은 업무 없음’으로 단정 금지 |
| AI 연결 문제로 업무 파악 불가 | 연결 상태와 재시도, 확보된 자료·처리 결과 보존 |
| 사용자가 중단함 | 중단 위치·이어서 분석하기. 정상 완료와 구분 |

완료 시 사용자가 노트북 등 다른 화면에 있다면 화면을 강제로 바꾸지 않고 ‘업무 분석 결과 보기’를 제공한다. 매뉴얼의 문장 정리나 노트북 질문 준비가 추가로 필요하면 해당 업무 안에 준비 상태를 표시하고, 이미 확보한 업무 설명·자료·일정을 제공한다.

## 13. 폴더형 업무카드와 좌우 업무 작업 화면

### 13.1 홈의 큰 업무 폴더

사용자가 제시한 노트북 카드의 ‘큼직한 묶음을 선택해 들어가는 방식’을 반영한다. 업무마다 옅은 표지색·작은 폴더 탭 형태·큰 업무명을 사용한다. 실제 폴더 경로보다 업무의 의미가 먼저 보여야 한다.

- 카드의 기본 정보는 **업무명 → 어떤 일인지 1~2문장 → 주요 결과물 → 시기 또는 다음 행동** 순서다.
- 자료 수·분석 상태는 작은 보조 정보로 두고, 확인 필요 배지를 모든 카드의 가장 강한 요소로 만들지 않는다.
- 카드 전체는 단일 진입 대상으로 동작한다. 마우스 한 번 클릭 또는 키보드 Enter/Space로 업무를 연다. 더블클릭을 요구하지 않는다.
- 이름이 길어도 최소 두 줄은 읽을 수 있게 하고 전체 제목에 접근할 수 있도록 한다.
- 카드 순서와 표지색은 업무 ID를 기준으로 안정적으로 유지한다. 분석 갱신 중 읽던 카드가 임의로 이동하지 않게 한다.
- 초기 제안 크기는 폭 280~340, 높이 200~240 논리 픽셀, 간격 16~24다. 실제 글자 배율과 창 폭에 맞춰 조정하며 고정 크기 때문에 내용을 자르지 않는다.
- 기본 창은 3열을 우선 검토하고 좁은 창에서는 2열 또는 1열로 바꾼다. 카드 수가 많으면 홈 안에서 ‘더 보기’ 또는 목록 확장으로 접근한다.

연간 대시보드는 홈에서 계속 제공한다. 첫 화면의 카드가 너무 커서 일정의 존재를 발견하지 못하는 일이 없도록 카드 첫 줄과 일정 영역의 배치를 함께 검증한다. 장식용 표지가 카드 높이 대부분을 차지하지 않도록 한다.

### 13.2 폴더를 연 뒤의 배치

```text
┌───────────────────┬──────────────────────────────────────────────┐
│ ← 업무 홈         │ 행정사무감사                                  │
│ 업무 찾기         │ 어떤 업무인지 · 선택 연도/수행 건              │
│                   │ [업무 안내] [일정·진행] [업무 자료] [매뉴얼]    │
│ ▌행정사무감사 ✓   ├──────────────────────────────────────────────┤
│   분기 실적 보고  │ 어떤 일을 하는가                              │
│   보조금 정산     │ 무엇을 만들어야 하는가  [지난 결과물 보기]     │
│   …               │ 어떤 순서로 하는가                            │
│                   │ 언제 하는가 · 현재 확인된 상태                 │
│                   │ 지금 먼저 할 일  [첫 행동]                     │
│                   │ 먼저 읽을 자료 · 확인할 정보                   │
└───────────────────┴──────────────────────────────────────────────┘
```

예시 업무명은 실제 담당 업무를 뜻하지 않는다. 좌측 목록은 업무 작업 화면에 상주하고 우측만 전환한다. 업무 홈으로 돌아오면 원래 카드·검색 조건·스크롤 위치를 복원한다.

좌측 패널은 초기 폭 240 논리 픽셀을 제안하며 약 220~300 범위에서 사용자가 조절할 수 있게 한다. 좁은 창·큰 글자에서는 패널을 접되 ‘업무 목록’ 버튼과 현재 업무명을 남긴다. 본문 글자를 강제로 줄여 공간을 맞추지 않는다. 좌측 목록과 우측 본문은 각각 스크롤하고 제목·탭은 고정한다.

선택된 업무에는 **옅은 배경 + 왼쪽 강조선 + 굵은 글자/선택 표시**를 적용한다. 마우스 호버·키보드 초점·현재 선택은 서로 구분한다. 색만 바꿔 현재 위치를 알리는 방식에 의존하지 않는다. 업무 검색은 목록을 좁히며, 선택 업무가 결과에 없더라도 우측 내용을 임의로 다른 업무로 바꾸지 않는다.

### 13.3 우측 기본 화면의 정보 순서

| 구역 | 내용 | 설계 의도 |
|---|---|---|
| 상단 고정 머리 | 업무명·쉬운 설명·연도/수행 건·노트북에서 묻기 | 현재 무엇을 보는지 계속 알림 |
| 업무 목적과 결과물 | 목적 2~3문장, 주요 결과물, 대표 제출본 링크 | 처음 맡은 사람이 업무의 끝모습부터 이해 |
| 전체 처리 흐름 | 핵심 단계의 간결한 흐름과 단계별 근거 | 구체적 행동의 순서를 파악 |
| 일정·현재 위치 요약 | 확인된 기한/과거 패턴, 최근 기록, 현재 수행 상태 | 올해 해야 하는 일과 과거 사례 구분 |
| 먼저 할 일 | 추천 행동 하나와 이유, 필요한 준비 자료 | 첫 행동을 선택하고 시작 |
| 관련 자료·확인할 정보 | 대표 자료 몇 개와 읽는 이유, 중요한 공백 | 자료 더미 대신 필요한 근거로 안내 |

업무 안내의 짧은 단계 흐름은 전체 절차를 대신하지 않는다. 세부 절차는 매뉴얼에서, 실제 진행 체크는 일정·진행에서 다룬다. 긴 안내는 구획을 나누고 첫 화면에 목적·결과물·첫 행동이 발견되도록 배치한다. 실제 기한이 임박한 경우에는 상단 요약에도 표시한다.

### 13.4 업무 전환 규칙

1. 처음 여는 업무는 ‘업무 안내’로 연다. 홈 일정의 기한을 누른 경우처럼 목적지가 지정된 진입은 해당 탭·연도·수행 건을 우선한다.
2. 이미 본 업무로 돌아오면 그 업무에서 보던 탭·연도·스크롤을 복원한다. ‘처음부터 안내 보기’로 업무 안내의 맨 위로 갈 수 있다.
3. 좌측 선택을 바꾸면 새 업무명·선택 상태를 즉시 표시한다. 조회가 필요하면 새 업무의 준비 표시를 사용하고 이전 업무 내용을 새 제목 아래 남겨 두지 않는다.
4. A→B→C를 빠르게 선택했을 때 뒤늦게 도착한 A·B 결과를 C 화면에 표시하지 않는다. 선택 업무 ID와 요청 세대를 검증한 결과만 반영한다.
5. 업무를 바꾸면 기존 근거 패널을 닫거나 새 맥락에 맞춰 갱신한다. 다른 업무의 인용이 남지 않게 한다.
6. 진행 중인 준비 작업은 화면 전환으로 취소하지 않는다. 작업의 업무·수행 건 ID를 유지하고 실행 서비스에서 계속 처리한다.
7. 작성 중인 편집 내용은 임시 저장·복원한다. 임시 저장이 불가능한 변경만 해당 전환 시 저장 여부를 다루고, 단순 열람 전환마다 확인창을 띄우지 않는다.
8. 비동기 완료가 현재 업무 선택이나 키보드 초점을 빼앗지 않게 한다. 선택된 업무가 삭제·합쳐진 경우에는 명확한 상태와 이동 경로를 제공한다.

## 14. 시각 디자인과 절제된 애니메이션

### 14.1 시각 기준

밝은 중성 배경, 흰색 또는 테마에 맞춘 본문 표면, 옅은 업무별 표지색, 충분한 여백과 얇은 경계를 사용한다. 기존 Pretendard·테마·다크 모드 기반을 확장한다. 강한 그라데이션·반복적인 큰 그림자·복잡한 3D 폴더 표현은 이번 디자인의 중심으로 삼지 않는다.

업무명은 크게, 설명과 다음 행동은 선명하게, 자료 수·판본·상태는 보조 위계로 둔다. ‘옅은 디자인’이 본문의 낮은 대비나 흐릿한 글자를 뜻하지 않도록 한다. 홈 카드의 표지색과 좌측 선택 표시를 연결하되 상태의 의미와 장식색을 혼동하지 않는다.

### 14.2 동작별 모션 명세

아래 수치는 **구현 초깃값**이며 측정된 성능 수치가 아니다. 실제 렌더링·배율·PC 환경에서 조정한다.

| 동작 | 효과 | 초기 시간 |
|---|---|---|
| 카드 호버/키보드 초점 | 테두리·배경 강조, 필요시 아주 약한 그림자 변화 | 120~160ms |
| 카드 누르기 | 즉시 눌림 상태 표시 | 60~80ms |
| 홈→업무 화면 | 새 본문이 짧게 나타남, 필요시 최대 6~8px의 작은 이동 | 180~220ms |
| 좌측 업무 선택 | 선택 배경 전환, 새 우측 본문 짧은 등장 | 100~150ms |
| 세부 탭/접기·펼치기 | 해당 영역에 한정한 짧은 전환 | 120~180ms |
| 일반 데이터 갱신 | 필요한 값만 교체 | 기본적으로 모션 없음 |

좌측 업무를 바꿀 때 전체 창이나 사이드바를 다시 등장시키지 않는다. 애니메이션이 끝날 때까지 클릭·키보드 입력을 막지 않으며, 연속 입력 시 기존 모션을 취소·정리하고 최신 선택으로 수렴시킨다. 기존 업무와 새 업무의 텍스트를 겹쳐 읽게 하는 긴 교차 페이드는 피한다.

시스템의 동작 줄이기 설정을 지원 가능한 방식으로 확인하고 앱 설정에도 ‘애니메이션 줄이기’를 제공한다. 줄이기 모드에서는 이동·페이드를 없애고 선택·로딩·완료 상태는 정적으로 분명히 표시한다. 키보드 초점 테두리는 모션에 의존하지 않는다. 반복 반짝임·유휴 상태의 움직임·매 갱신마다 카드 순차 등장 효과는 사용하지 않는다.

실행 중인 로컬 AI와 경쟁하지 않도록 큰 표·전체 창에 비싼 그림자나 화면 캡처 효과를 반복 적용하지 않는다. 애니메이션 품질과 관계없이 업무 전환의 데이터 정확성·입력 반응·읽기 쉬움이 우선이다.

## 15. 코드 구성과 구현 작업

### 15.1 현재 기반과 분리 방향

현재 `OnboardingView`는 폴더 선택과 분석 시작을, `TasksView`는 목록·상세를 하나의 클래스 안에서, `TaskCard`는 클릭 가능한 카드를 제공한다. `NotebookHome`에는 큰 카드 격자와 표지 표현이 있다. 이 기반을 재사용하되 업무 홈·업무 목록·상세 본문의 수명을 분리한다.

아래 모듈 이름은 설계 제안이며 아직 생성되지 않았다.

| 구성 | 역할과 적용 위치 |
|---|---|
| `WorkHomeView` | 업무 폴더 그리드와 연간 일정 대시보드. 기존 목록·일정 조회를 조합 |
| `WorkWorkspaceView` | 좌측/우측 영역을 유지하고 선택 업무와 화면 상태를 관리 |
| `WorkSidebar` | 업무 목록·검색·선택·키보드 탐색. 본문 조회나 실행을 소유하지 않음 |
| `WorkDetailView` 및 각 내용 패널 | 업무 안내·일정/진행·업무 자료·매뉴얼 표시 |
| `WorkFolderCard` | 큰 폴더형 카드. 기존 `TaskCard`·노트북 표지 패턴의 필요한 부분 재사용 |
| 공통 업무 조회 모델 | 홈·사이드바·상세가 같은 업무 ID·제목·상태를 사용 |
| `MotionController` | 전환 시간·취소·정리·동작 줄이기 적용을 공통화 |
| 기존 프로젝트 실행 서비스 | 화면 밖에서 실행을 유지. 업무 전환 시 구독 대상만 변경 |

현행 PySide6 Widgets를 유지한다. 홈/상세 전환은 스택, 좌우 조절은 `QSplitter`, 짧은 속성 변화는 Qt 속성 애니메이션을 사용한다. 패널 조절과 속성 애니메이션의 도구 기반은 Qt 공식 [QSplitter](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QSplitter.html), [QPropertyAnimation](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QPropertyAnimation.html) 문서에 따른다. 특정 시간·색·배치는 본 계획의 디자인 제안이다.

조회·분석·매뉴얼 생성은 UI 렌더링에서 분리한다. 화면을 열 때마다 모델을 다시 호출하지 않는다. 저장된 결과를 먼저 표시하고 오래 걸리는 갱신은 기존 워커 경로를 사용한다. 현재 `TasksView.refresh()`처럼 전체 본문을 재조립하는 경로는 선택·스크롤·초점이 필요한 만큼만 갱신하도록 분리한다.

업무별 UI 상태는 프로젝트와 업무 ID를 키로 보관한다. 업무 ID가 다른 프로젝트와 겹쳐도 탭·연도가 섞이지 않게 한다. 업무 페이지 캐시는 제한된 수로 관리하고, 전체 업무의 모든 원문·위젯을 한꺼번에 만들지 않는다.

### 15.2 이번 UI 구현의 순서

9절의 전체 계획 안에서 최초 사용자 흐름을 다음 작은 작업 단위로 구현한다. 각 단계에서 시각·키보드 상태를 함께 확인한다.

| ID | 구현 작업 | 완료 조건 |
|---|---|---|
| UI01 | 최초 분석 상태와 결과 진입 계약 | 폴더 지정→분석→결과 홈, 실패·중단·재개가 서로 구분됨 |
| UI02 | 폴더형 업무카드·홈 그리드·연간 대시보드 | 업무의 의미가 읽히는 큰 카드, 일정 접근 유지, 한 번 클릭으로 진입 |
| UI03 | 좌측 업무 목록·우측 상세 컨테이너 | 모든 업무를 홈으로 돌아가지 않고 전환, 정확한 선택 표시 |
| UI04 | 우측 업무 안내·일정/진행·자료·매뉴얼 패널 연결 | 실제 업무 데이터로 이해→첫 행동→원문 확인 가능 |
| UI05 | 업무별 상태 복원·비동기 전환·실행 지속 | 빠른 전환·뒤늦은 응답·진행 중 작업에서 업무 혼선과 유실 없음 |
| UI06 | 표지·여백·색·모션·동작 줄이기 조정 | 라이트/다크·키보드·큰 글자에서도 선명한 선택과 안정적 동작 |
| UI07 | 매뉴얼·노트북 경로와 통합 검증·설명서 | 선택 업무의 매뉴얼로 질문하고 해당 업무의 결과를 다시 찾음 |

매뉴얼·실행 서비스의 데이터 기반이 필요한 작업은 원 계획 P0~P3의 해당 항목을 먼저 수행한다. UI04의 완료를 정적인 가짜 내용으로 판정하지 않는다. 온나라 실제 기관 연결은 기존 P4에서 검증하며 이 UI의 최초 폴더 분석 경로를 막는 선행 조건으로 두지 않는다.

## 16. 추가 검증과 납품 기준

기존 10절의 데이터·근거·승인 검증에 다음을 더한다.

| 검증 | 필수 확인 |
|---|---|
| 최초 흐름 | 폴더 미선택·읽기 불가·빈 폴더·정상 완료·부분 실패·업무 0개·중단/재개 |
| 카드 | 큰 업무명·장문 제목·한 번 클릭·Enter/Space·3/2/1열·다수 업무·연간 일정 발견 |
| 좌우 화면 | 정확한 선택 표시, 좌측 독립 스크롤·검색·폭 조절·접기·홈 복귀 |
| 전환 정확성 | A→B→C 연속 선택, 늦은 결과, 열린 근거, 작업 중 편집, 삭제/합쳐진 업무 |

| 모션 | 빠른 재입력, 전환 취소, 애니메이션 줄이기, 일반 갱신 때 불필요한 반복 없음 |
| 접근성과 화면 | 현재 최소 창 1120×720 및 대표 1366×768·1920×1080에서 확인, Windows 125/150% 배율·앱 큰 글자·다크 모드·키보드 탐색 |
| 성능 | 최초/반복 업무 열기와 연속 전환을 실제 저장 데이터로 측정, 분석·모델 동작 중 입력 지연·누적 메모리·워커 중복 확인 |

화면 시험은 전임자 없이 처음 보는 업무를 대상으로 ‘무슨 일인가 → 무엇을 만들어야 하나 → 언제 하나 → 지금 무엇부터 하나 → 원문은 어디 있나’를 설명하고 직접 이동하는 과제로 진행한다. 자동 시험은 기존 `test_onboarding.py`, `test_pipeline.py`, `test_ui_smoke.py` 등을 재사용하고, 상태 전환·데이터 혼선·실행 지속에 필요한 시나리오를 보강한다. 스타일 수치만 다시 단언하는 시험은 추가하지 않는다.

개발 완료 시 실제 앱 화면 캡처, 업무 전환·모션 확인 기록, 회귀 결과, 남은 실환경 한계를 함께 남긴다. 이 계획 단계에서는 렌더링 성능이나 사용자 이해도 향상이 검증됐다고 주장하지 않는다.
