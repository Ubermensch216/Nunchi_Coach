# 후속 개선 1차 구현·검증

2026-10-10. 기존 다른 AI의 행동 도구·문서 역할·연도 비교 작업을 보존하면서 진행했다.
변경 파일은 적용 직전에 SHA-256으로 동시 변경을 검사했다. 교체 전 사본은
`.test_runs/followup-originals-20261010/`에 남겼다. 실제 기관 원본이나 사용자 프로젝트로
합성 검증을 수행하지 않았다. 이번 작업이 잔여 과제 전체의 완료를 뜻하지 않는다.

## 구현한 범위

### PDF·Excel 추출 범위와 누락 판정

- PDF: 전체/방문/텍스트 확보/텍스트 없는/읽기 실패/미방문 페이지 수를 기록한다.
  글자 한도로 잘린 페이지와 방문하지 못한 마지막 페이지 범위를 구분한다.
  진단의 페이지 표본은 이유별 100개까지이며 실제 개수와 표본 완전 여부를 함께 남긴다.
  모든 페이지 읽기가 실패했을 때 빈 조각 때문에 성공처럼 보이던 동작을 고쳤다.
- XLSX/XLSM: 방문한 시트·행·셀, 비어 있지 않은 셀, 선언된 행·열 크기를 기록한다.
  시트별 셀 상한을 행 중간에서도 넘지 않도록 제한하고 남은 행·열/미방문 시트를 알린다.
  글자 상한에 걸린 결과를 `partial`로 표시한다. 정확히 마지막 글자/셀까지 읽은 결과에는
  상한에 도달했다는 이유만으로 누락 경고를 만들지 않는다.
- PDF 텍스트 레이어 및 Excel 캐시 값의 방문 범위가 완전한 시각 구조·수식 검증을 보증하지 않는다.
  `extraction_complete_documents`는 여전히 미확인(`null`)이다. 행·열 선언값은 실제 유효 셀
  전체 개수로 해석하지 않는다. 남은 행 수를 모르면 임의의 숫자 대신 `null`을 기록한다.

### 저장과 재개

DB v11은 `documents.extraction_coverage` 열만 추가한다. 기존 업무·사용자 교정·행동 기록을
수정하는 데이터 이동은 없다. 기존 프로젝트 승격 전에 SQLite 백업을 생성한다.
자동 조사와 노트북 업로드 경로가 파싱 결과와 진단을 같은 트랜잭션에 저장한다.
원문 변경이나 재파싱으로 이전 분석을 무효화할 때 진단도 비운다.
PDF 파서 5, Excel 파서 6으로 해당 형식의 기존 성공/부분 추출 문서만 재처리 대상으로 만든다.
읽기 전용 진단 도구는 새 열이 없는 v9/v10 프로젝트도 업그레이드 없이 조회할 수 있다.

사용 예:

```powershell
python -m app.tools.coverage <project.db> --output <자료원 밖의 coverage.json>
```

파일별 `extraction_coverage`, 집계의 `extraction_scope_measured_documents`와
`extraction_known_omission_documents`에서 계측 여부와 알려진 누락을 확인한다.
아직 다시 읽지 않은 기존 문서는 계측 결과를 소급 생성하지 않는다.
상태 화면에도 계측한 문서와 누락이 확인된 문서 건수를 표시한다.
합성 PDF 프로젝트를 Qt 오프스크린으로 렌더링하여 글자 잘림과 카드 배치를 확인했다.

### 업무 평가 단위 확장

`app/tools/task_assignment_eval.py`는 기관 담당자가 독립적으로 만든 업무 키와 문서별
다중 라벨을 읽는다. 제품의 업무 발견 코드에 정답을 공급하지 않는다.
평가 전에 발견한 후보를 정답의 업무 키로 담당자가 대응시켜야 한다.
평가셋에 없는 문서, 미대응 업무 키, 중복 라벨은 오류로 거부한다.

문서-업무 배정 정밀도/재현율/F1, 문서별 완전 일치, 업무 문서 발견 범위,
비업무 자료의 오배정, 다중 업무 문서의 완전 일치, 업무별 지표와 발견된 업무 비율을 낸다.
없는 예측 행은 빈 배정으로 평가하고 목록도 출력한다. 분모가 없으면 지표는 `null`이다.

```json
{"tasks":["보조금정산","정보공개"],"documents":{"문서1":["보조금정산"],"문서2":["보조금정산","정보공개"],"참고자료":[]}}
```

```powershell
python -m app.tools.task_assignment_eval <gold.json> <predicted.json>
```

출력은 표준 출력이며 입력을 덮어쓰지 않는다. 동일 양식의 다른 업무, 다른 양식의 같은 업무,
단일 문서 누락, 다중 업무 일부 누락, 참고자료 오배정을 합성 반례로 검증했다.
이 검증은 지표 계산의 검증이며 발견 모델이 이러한 문제를 해결했다는 뜻은 아니다.

### 1만 건 군집 성능 측정

```powershell
python -m app.tools.clustering_bench --documents 10000 --dimension 1024
```

고정 시드의 합성 벡터를 사용한다. 문서 식별자의 중복·누락과 제어된 군집의 순도를 별도로 검사한다.
파일 읽기·파싱·임베딩·업무 작명·복구를 포함하지 않는다. 측정된 시간과 배열 크기를 구분하고,
배열 크기를 프로세스 최대 메모리 측정치로 표시하지 않는다.

## 확보한 증거

- 추출 계측·기존 파서·승격·파이프라인 테스트: 57개 통과.
- 계측 경계와 구형 읽기 전용 진단을 추가한 후 노트북 포함 검증: 35개 통과.
- 저장 중간에 예외를 주입한 뒤 DB를 다시 열어 상태 롤백과 정상 재개 확인:
  최종 계측 및 업무 배정 지표 테스트 19개 통과.
- 합성 파일 234개 중 지원 확장자 224개 파싱: 정상 204, 부분 1, 빈 문서 4, 실패 8,
  미지원 5, 암호화 2. 전후 전체 파일 SHA-256과 파일 목록이 동일했다.
  페이지·시트 범위가 계측된 문서는 80개다. 손상/미지원 표본이 포함되어 있다.
- 1만 개·1,024차원 벡터: 24개 군집, 미배정 0, 약 2.515초.
  식별자 보존과 제어된 군집의 순도 검사 통과. 벡터 배열 40,960,000바이트,
  유사도 블록 배열 추산 20,480,000바이트. Python 3.14.6 / NumPy 2.5.2 / Windows 11.
- 전체 회귀 실행은 840개 통과·4개 건너뜀 이후 온나라 수집에서
  `PermissionError`로 중단됐다. 해당 파일 단독 재검증은 12개 통과했다.
  이후 온나라 파일부터 나머지 테스트와 다른 AI의 행동 도구 테스트를 포함한 실행은
  **848개 통과·1개 건너뜀·Qt API 폐기 예고 경고 1개**, 약 579초로 종료됐다.
  오류 원인은 확정하지 않았으며 한 번의 전체 실행에서 전부 통과했다고 주장하지 않는다.
  분할 실행에는 일부 중복 검증이 있으므로 두 통과 건수를 합산하지 않는다.
- 상태 화면을 포함한 이번 변경의 최종 집중 검증은 **33개 통과**했다.

측정 원장: `.test_runs/followup-clustering-10000.json`,
`.test_runs/followup-smoke-measurement.json`, `.test_runs/followup-full-regression.log`,
