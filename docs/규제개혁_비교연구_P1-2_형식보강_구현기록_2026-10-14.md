# 규제개혁 비교연구 P1-2 형식별 추출 보강 구현 기록

작성일 2026-10-14 · 근거 상세개선계획서 6.1 · 비교연구 R08 · 앞 단계 [P1-1 구현 기록](규제개혁_비교연구_P1-1_건단위_구현기록_2026-10-14.md)

R08은 "추출 누락과 '정보 없음' 안내의 혼동"이다. 실제 스냅샷에서 읽지 못한 문서의 원인을 파일 앞부분(매직 바이트)으로 다시 확인했다.

| 무리 | 건수 | 이전 표시 | 실제 |
|---|---|---|---|
| 구형 `.xls` | 9 | 지원하지 않음 | 진짜 BIFF8(OLE) 통합문서. 우리 기관 규제개선과제 목록 5건, 행정규제 등록 목록 3건 포함 |
| `.xlsx` "File is not a zip file" | 2 | 실패 | DRMONE 암호화 문서 |
| `.hwp` "OLE 복합문서가 아님" | 1 | 지원하지 않음 | DRMONE 암호화 문서(업무매뉴얼이 DRM으로 지목한 심층간담회 결과보고) |
| `.zip` | 15 | 이름만 읽음 | 안에 따로 없는 문서가 있다(F0829 안의 평가 서식 Z097·Z098 등) |

연구 보고서가 함께 지목한 F0769(확장자 `.hwp`인 HWPML)는 10-12 작업에서 이미 형식 판별이 들어가 이 스냅샷에서는 읽혀 있었다. 본문이 없는 스캔 PDF 7건(OCR 필요)은 이번 범위가 아니다.

## 1. 바꾼 것

| 항목 | 조치 | 위치 |
|---|---|---|
| 구형 XLS | 새 의존성 없이 이미 쓰는 `olefile`로 Workbook 스트림의 BIFF8 레코드를 읽는다. 공유 문자열(CONTINUE 경계의 글자 폭 전환 포함), LABEL·NUMBER·RK·MULRK, 수식의 마지막 계산값(STRING), 참거짓, 날짜 서식(내장 영문·CJK 번호와 사용자 서식 `yyyy"년"…`)을 날짜로, 1904 기준. 암호(FILEPASS)는 열지 않는다. openpyxl과 같은 꼴(`worksheets`·`iter_rows`)로 내서 xlsx와 **같은 조각 규칙**으로 싣고, 건 목록 읽기(P1-1)도 같은 길로 연다 | `app/ingest/parsers/xls.py`(신규), `xlsx.parse`·`open_workbook` |
| 보호(DRM) 문서 | 디스패처가 파서보다 먼저 앞 1KB에서 DRM 표시(DRMONE, SCDSA, Fasoo 등)를 찾아 `encrypted` 상태와 "보호(DRM) 문서 — 이 PC에서는 내용을 읽을 수 없습니다. 권한 있는 PC에서 열어 확인하세요."로 돌려준다. 해제를 시도하지 않는다. 글 파일(.txt 등)은 검사하지 않는다 | `parsers/__init__.py` |
| 압축 안의 문서 | 구성원을 **격리된 임시 폴더에 순번 이름으로** 하나씩 꺼내 기존 파서로 읽고 바로 지운다(원본 옆에 풀지 않음, 압축 안 경로가 디스크 경로가 되지 않음). 실행 파일·암호 구성원은 꺼내지 않는다. 한도: 깊이 2, 읽는 구성원 200, 구성원 50MB, 전체 200MB, 압축률 100배(1MB 넘는 것). 넘은 것은 이름과 사유를 남긴다. 옆에 같은 이름의 풀린 폴더가 있으면 **같은 경로·크기의 파일만** 건너뛴다 | `parsers/archive.py` |
| 압축의 조각과 업무 값 | 구성원은 압축 문서 하나의 조각으로 싣고 위치를 `구성원 경로 · 원래 위치`로 적는다. 구성원마다 다른 건·기관의 것일 수 있으므로 **업무 값(기한·금액·절차…)의 근거로 쓰지 않는다**. 검색·열람에는 쓴다 | `reconstruction.read_task` |
| 읽지 못한 문서 다시 시도 | 판 번호(PARSER_REVISIONS)는 이미 읽은(ok·partial) 문서만 다시 읽게 해서, 전에 '지원하지 않음'·'실패'이던 문서는 새 파서가 와도 그대로 남았다. `FAILURE_REVISION`이 바뀌면 실패·지원 안 함·암호 문서를 한 번 `pending`으로 되돌리고 시도 횟수를 지운다. 잘 읽힌 수백 건을 괜히 다시 읽지 않는다 | `parsers/base.py`, `pipeline.retry_failures` |
| 표시 | 문서 상태 `△ 암호·보호 문서`, 준비 상태의 본문 추출 층에 `암호·보호(DRM) N`을 따로 센다 | `ui/views/documents.py`, `initial_analysis.layers`, `actions/tools/discover.py` |

계획서 4.1은 압축 구성원을 `parent_document_id`가 있는 가상 자식 **문서 행**으로 두자고 했다. 그렇게 하면 원본 파일이 없는 문서 행이 생겨 폴더 조사(없어진 문서 판정)·해시·근거 열기·판 묶음·폴더 해석을 모두 바꿔야 한다. 이번에는 압축 문서의 조각으로 싣는 데서 멈췄다. 구성원별 갈래·시점·업무 배정은 가상 자식 행이 있어야 한다(5장).

## 2. 실제 스냅샷 사본 측정

스냅샷 백업 사본에서 파이프라인의 규칙 단계(내용 읽기 → 시점 → 갈래 → 일정 → 처리 순서 → 복원)를 돌렸다. 모델 단계는 돌리지 않았다.

| 무리 | 이전 | 이후 |
|---|---|---|
| 구형 `.xls` 9 | 지원하지 않음 9 | **읽음 9** (한글·작성자·수정일 포함, 파일당 0.01초 안팎) |
| DRM 3 | 실패 2 · 지원하지 않음 1 | **암호·보호 3** — 사유 문구가 보호 문서임을 말함 |
| `.zip` 15 | 일부(이름만) 15 | 전부 읽음 10 · 일부 5. 구성원 208개 본문, 185만 자. F0829 안의 자가채점표 2건(표제 "2024년도", 본문 "2025년") 포함 |
| 내용 읽기 소요 | — | 10.5초(위 27건) |

업무 복원 수치는 P0·P1-1과 같다(항목 691 → 692, 단계 123, 공백 77, 건 30). 늘어난 항목 하나는 이제 읽히는 우리 기관의 과제 목록 `.xls`가 제출 폴더의 결과물로 잡힌 것이다. 새로 읽힌 XLS 목록 9건은 시군구 칸이 없어(제안자 `구분` 칸에 기관명) 건 목록으로 보지 않았다.

재분석할 때 다시 읽힌 문서는 그 업무의 자동 일정·단계를 지우고 뒤 단계가 다시 만든다. 내용 읽기만 돌리고 복원하면 단계가 123 → 46으로 줄어 보이는데, 측정 방법의 착시이고 전 단계를 돌리면 같아진다.

## 3. 시험

`tests/test_legacy_formats.py` 20건: 손으로 만든 BIFF8 스트림(CONTINUE 경계에서 갈리는 한글, 날짜 서식, RK·MULRK, 수식 문자열, 암호), XLS가 xlsx와 같은 조각을 냄, 깨진 XLS는 '실패', 날짜 서식 판별, DRM 세 형식과 글 파일, 압축(구성원 경로·원본 옆에 아무것도 생기지 않음·경로 탈출 이름·실행 파일·깊이 상한·압축 폭탄·풀린 폴더와 중복), 압축 내용이 업무 값이 되지 않음, 실패 문서 한 번 재시도, 준비 상태의 보호 문서 집계. 과부하 합성 자료의 기대값 두 곳(깨진 XLS는 '실패', ZIP은 실행 파일 때문에 '일부')을 고쳤다.
