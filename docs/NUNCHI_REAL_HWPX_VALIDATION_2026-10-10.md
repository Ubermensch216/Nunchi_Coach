## 실제 자료로 발견하고 수정한 문제

1. HWPX 추출 결과에 구조화된 계측이 없었다. XML 파트·문단·텍스트 런·표·물리 셀·병합 셀
   목록 수와 방문/출력 범위, 글자·셀·병합 확장 한도의 생략 사유를 추가했다.
   XML 전체를 검사한 수와 실제 추출에 방문한 수는 별도 필드로 구분했다.
2. HWPX의 속성 `<meta name="CreatedDate">`·`ModifiedDate`·`creator`를 제대로 읽지 못했다.
   현재 파일의 생성일은 2019-01-16, 수정일은 2026-09-30이다. 생성일을 최신 업무 시점으로
   간주하지 않도록 구분해서 읽는다. 기존 날짜 판정은 본문 근거 **2026-09-28**을 선택했고,
   파일명의 2026-09-30이나 오래된 생성일로 덮어쓰지 않았다.
   내부 제목 속성 `□`는 원본 값으로 유지하며 실제 본문 제목으로 임의 교체하지 않았다.
3. HWPX의 넓은 표에서 셀 한도를 한 행 단위로 넘길 수 있던 동작을 고쳤다. 정확히 마지막
   셀/글자까지 읽은 경우에는 한도에 도달했다는 이유만으로 누락 경고를 만들지 않는다.
4. 큰 희소 행·열 좌표가 있는 표는 실제 존재하는 좌표만 순회하도록 바꿨다. 선언된 최대 좌표
   크기만큼 거대한 빈 행·열 범위를 만들지 않는다.
5. HWP 파서에도 본문 스트림 방문·실패·미방문, 미리보기 폴백, 글자 한도를 기록했다.
   표 구조를 보존하지 못하는 기존 한계를 명시했다. 이번 첨부는 HWPX이므로 이 항목은
   합성 OLE 스트림으로 검증했으며 **실제 HWP 검증 완료로 표시하지 않는다**.

기존 다른 AI의 행동 도구·업무 화면 수정은 보존했다. 적용 전 변경 파일의 SHA-256을
대조했고 원래 파일 사본은 `.test_runs/hancom-originals-20261010/`에 저장했다.
DB 스키마는 기존 v11을 그대로 사용하며 파서 버전만 HWP/HWPX 5로 올렸다.
해당 형식의 예전 성공/부분 추출 결과는 다음 처리 때 재파싱 대상으로 선택된다.

## 재현과 회귀

일반 검증 명령:

```powershell
python -m app.tools.hwpx_audit <원본.hwpx> --output <원본 폴더 밖의 새 출력 폴더>
```

이 도구는 원본을 복사하거나 부모 폴더를 훑지 않고, 단일 문서만 격리된 업로드 자료원으로
등록한다. 기존 출력 폴더의 기록은 덮어쓰지 않는다. 보고서는 본문을 담지 않지만 검증용
프로젝트 DB에는 추출문이 저장되므로 로컬 검증 산출물로 관리한다.

실제 최종 산출물은 Git에서 제외되는 `.analysis_audit/real-hwpx-20261010-final/`에 있다:

- `report.json`: 원본 해시·추출 계측·XML 대조·날짜·조각·재접속 결과.
- `project.db`: 로컬 단일 문서 검증용 DB.
- `synthetic_regression.json`: 기존 합성 HWPX 55개 비교 결과. 본문·근거 위치·상태 변화 0건.

추출 한도, 정확한 경계, 병합 셀, 희소 좌표, OPF 속성 날짜, HWP 폴백,
단일 파일 검증 도구와 기존 파서·노트북·조각·날짜·승격·파이프라인 테스트
최종 수정 기준 **159개 통과**. HWP 문자 계측과 XML 실패/미방문 구분도 포함한 결과다.

## 남은 검증

실제 HWP 5.0 파일, 복잡한 중첩 표·각주·그림과 장문 HWPX, 기관별 다양한 문서 및 독립
업무 정답이 필요하다. 현재 파일은 HWPX 기본 본문과 가로/세로 병합 표의 실제 검증 기준으로
사용할 수 있다. 로컬 모델을 통한 질의 응답 및 업무 배정의 정확도는 별도의 평가다.
