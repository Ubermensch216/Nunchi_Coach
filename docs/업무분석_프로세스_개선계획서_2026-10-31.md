# 업무 분석 프로세스 개선 — 단계별 계획서

작성: 2026-10-31 · 대상 저장소: `Nunchi_Coach`
관련 문서: [공문 기준 업무 분석 계획서](공문기준_업무분석_계획서_2026-10-29.md) · [현재 구현 및 검증 현황](현재구현_및_검증현황.md)

> **후속 작업자(사람·AI)에게.** 이 문서는 "개괄 → 체계 수립 → 재배치 → 업무별 집중 분석 → 업무 카드·노트북 = AI 업무 매뉴얼"로
> 분석 순서를 바꾸는 기준이다. 상태 표시는 공문 기준 계획서와 같은 네 가지만 쓴다 — `[완료]` · `[부분]` · `[미착수]` · `[외부 대기]`.

---

## 0. 바꾸려는 프로세스

1. 후임자가 전임자의 폴더를 지정하고 업무 분석을 의뢰한다.
2. **개괄 파악** — 업무분장·업무기술서 같은 자료를 먼저 찾아 업무 분류와 체계를 세운다.
3. **구조 파악** — 폴더명·파일명·생성/수정일·키워드·자료의 양으로 업무를 빠르게 훑는다. 자료가 많은 곳은 업무가 많을 가능성이 높다.
4. **재배치** — 업무 분류가 잡히면 자료를 업무별로 다시 묶는다(물리적으로는 **사본 인계 폴더**).
5. **업무별 집중 분석** — 분류된 업무 하나하나를 깊게 분석한다.
6. **업무 카드 → 노트북 → AI 업무 매뉴얼** — 분석이 끝나면 업무별 카드를 만들고, 각 카드를 그 업무의 노트북에 바로 연결한다.
   노트북은 업무 정리본과 원문을 담아, 묻고 답하는 **AI 업무 매뉴얼**이 된다(제미나이 노트북을 업무별로 만드는 것과 같다).

### 현재와 무엇이 다른가

| 단계 | 현재 구현 | 차이 |
|---|---|---|
| 개괄(업무분장) | 없음. `업무분장`은 안내 문구(`work_brief.py`, `work_instruction.py`)에만 나온다 | 업무 체계의 1차 단서가 빠져 있다 |
| 구조 파악 | `_folder_plan`(`app/ai/discover.py:284`)이 폴더로 업무를 나누지만 **전 파일 파싱·임베딩 뒤**에 돈다. 자료량·연도 분포 개괄 화면 없음 | 사용자가 윤곽을 보기까지 오래 걸린다. 자료량 신호 미사용 |
| 업무 분류 | 공문 → 폴더 → 임베딩 군집(`_discover`) | 업무분장 단서와 "분장 ↔ 자료" 대조가 없다 |
| 재배치 | 사본 인계 폴더(`app/core/handover_folder.py`) `[완료]` | 분류 확정 뒤 바로 이어지지 않고 인수인계 메뉴에 따로 있다 |
| 집중 분석 | 역할·주기·절차·복원·청킹이 **전체 문서 단위**로 한 번에 돈다(`app/jobs/pipeline.py`) | 업무 단위 진행·우선순위가 없다 |
| 카드 → 노트북 | 업무 카드(`workcard.py`)는 있으나 노트북은 사용자가 '업무노트에서 묻기'를 누를 때 만든다(`shell.py:644` → `notebook_tasks.open_for_task`) | 분석이 끝나도 업무별 노트북이 준비돼 있지 않다 |

### 지키는 원칙 (바꾸지 않는다)

- **원본 불변.** 재배치는 사본 인계 폴더로만 한다(NFR-SAF-001, 2026-10-29 결정).
- **사용자 확정 우선.** 분장에서 뽑은 업무 체계·분류는 제안이다. 사용자가 고친 것은 재분석이 덮지 않는다(`decided_by='user'`).
- **근거 역추적.** 분장표에서 온 업무는 분장표의 행·쪽을 근거로 단다.
- **공문이 있으면 공문이 먼저다.** 분장은 공문 다음, 폴더 앞의 단서다.

## 1. 단계 개요

```
S1 빠른 개괄 ─▶ S2 업무 체계(분장) ─▶ S3 분류·대조 ─▶ S4 확인·재배치 ─▶ S5 업무별 집중 분석 ─▶ S6 카드·노트북·AI 매뉴얼
 (파싱 전)       (후보만 먼저 파싱)     (공문>분장>폴더>본문)  (사용자 확정 게이트)   (업무 단위 진행)          (분석 끝난 업무부터 자동)
```

| ID | 단계 | 상태 | 핵심 위치 | 선행 | 비고 |
|---|---|---|---|---|---|
| S1 | 빠른 개괄(자료 지도) | `[완료]` | `app/core/survey.py`(신규), `pipeline.py`, `ui/views/onboarding.py` | — | 폴더 통계, 연도 분포, 자료 지도 시각화 |
| S2 | 업무분장·기술서 탐지와 업무 체계 제안 | `[부분]` | `app/core/charter.py`(신규), `ai/prompts/charter.md`(신규), DB `v14` | S1 | 표 분장표 파싱 및 charter_items 구축. 전임자 지정 필터·줄글 분장 모델 추출 미완 |
| S3 | 분류 단서 순서 확장과 분장 ↔ 자료 대조 | `[부분]` | `app/ai/discover.py` | S2 | charter_plan 분장 대조 및 charter_only/matched/data_only 도출. data_only 자료량 정렬 및 본문 군집 대조 보강 필요 |
| S4 | 분류 확인 게이트와 재배치 연결 | `[부분]` | `ui/views/onboarding.py`, `handover_folder.py` | S3 | 사본 인계 폴더 및 안내문 연동 완료. 온보딩 확인 게이트 UI 미완 |
| S5 | 업무 단위 집중 분석 | `[완료]` | `app/jobs/pipeline.py`, `ui/widgets/work_folder_card.py` | S3 (S4와 병행 가능) | 1차 구현 결함 6종(cycle_day_hint, stale 감지 재분석 루프, relink/autosave/schedule_tasks 복원, checked 메타 플래그 및 StageReport 방출, 전역 복원 사전 1회화 및 common_skeletons 공통 서식 문구 필터링 정상화, evidence 문서 ID 포맷 복원) 개선 완료 |
| S6 | 업무 카드 → 노트북 자동 연결 → AI 업무 매뉴얼 | `[부분]` | `notebook_tasks.py`, `workcard.py`, `ui/views/tasks.py`, `ui/views/notebooks/*` | S5 | 자동 생성, 추천 질문 5종, 카드/작업공간 연동, 업무 합치기/업무아님 시 노트북 보관(archive_for_task) 연동 완료. 판 갱신 알림·대화 반영 미완 |
| S7 | 실자료 검증 | `[외부 대기]` | `tools/quality_gate` | S1~S6 | 규제개혁 1,044파일 픽스처 실측 대기 |

S2, S4, S6이 `[부분]`인 것은 핵심 골격과 DB 스키마는 구현되었으나 전임자 필터·확인 게이트 화면·판 갱신 알림 등 세부 연동이 남아있기 때문이다. S5는 1차 구현 당시 누락/결함이었던 6종의 문제를 모두 개선하여 일괄 분석과 동등한 무결성을 확보하였다.

## 2. 단계별 세부

### S1 · 빠른 개괄 — 자료 지도

**목표.** 폴더를 지정하고 수십 초 안에 "어떤 덩어리가 얼마나 있는지"를 보여 준다. 파싱·임베딩 전에 끝난다.

**할 일**

1. 스캔 직후(`STAGE_SCAN`·`STAGE_HASH` 다음) `survey.build(db)` 실행. 파일 시스템 메타데이터만 쓴다.
   - 폴더별: 파일 수, 문서 수(파싱 대상 확장자), 용량, 생성·수정 연도 분포, 최근 수정일.
   - 폴더명·파일명 토큰 빈도(기존 `folders.parse_part`, `clustering._tokenize` 재사용), 회차·연도 꼬리표.
   - 중복 해시 비율, 그림·글꼴 등 비문서 비율.
2. **자료량 비중**: 폴더(업무 후보)별 문서 수·연도 수를 정규화해 "업무 비중" 점수를 둔다. S5의 분석 순서와 S6 카드 정렬에 쓴다.
3. 결과를 `meta`(또는 `survey` 표)에 저장 — 재스캔 시 차이만 갱신.
4. 온보딩 화면에 **자료 지도** 단계 추가: 상위 폴더 트리 + 막대(문서 수) + 연도 띠. "분석이 진행 중이어도 지금 볼 수 있는 것"으로 표시.

**완료 기준**

- 1,000파일 폴더에서 파싱 없이 10초 안에 지도 표시(합성 픽스처).
- 폴더 트리 문서 수 합계 = 스캔된 문서 수.
- 시험: `tests/test_survey.py`(신규) — 빈 폴더, 평평한 폴더, 깊은 폴더, 중복 해시.

### S2 · 업무 체계 — 업무분장·업무기술서

**목표.** 분장표·기술서가 있으면 그것으로 업무 목록(체계)을 먼저 세운다.

**할 일**

1. **후보 찾기(파싱 전)**: 파일명·폴더명 키워드 — `업무분장`, `사무분장`, `사무분담`, `업무분담`, `업무기술서`, `직무기술서`, `담당업무`, `업무현황`, `인수인계서`, `업무인계`. 확장자는 HWP·HWPX·XLSX·XLS·DOCX·PDF.
2. **후보 우선 파싱**: 파이프라인 `_parse`에서 후보를 맨 앞에 둔다(나머지 파싱은 그대로 이어진다).
3. **추출**
   - 표 문서(XLSX·HWP 표): 머리글에 `담당자`·`성명`·`업무`·`담당업무`·`사무` 열이 있으면 규칙으로 행을 뽑는다.
   - 줄글·개조식: 생성 모델로 `{업무명, 세부업무[], 담당자, 비중(%)}` 추출(`ai/prompts/charter.md`, `schemas.py`에 스키마). 모델이 꺼져 있으면 개조식 머리 줄만 규칙으로.
   - **전임자 행만** 고른다: 프로젝트에 등록한 전임자 이름·직위가 있으면 그 행, 없으면 사용자에게 고르게 한다(분장표에는 과 전체가 들어 있는 경우가 많다).
4. **저장**: `charter_items(id, doc_id, locator, name, parent_id, owner, weight, decided_by)` — DB `v14`. 근거는 문서·행/쪽.
5. 여러 분장표(연도별)가 있으면 최신 연도를 기준으로, 이전 연도에만 있는 항목은 "지난 분장"으로 표시.

**완료 기준**

- 합성 분장표 3종(엑셀 표, HWP 표, 개조식 HWPX)에서 업무 항목 재현율 0.9 이상.
- 과 전체 분장표에서 전임자 행만 고름(다른 담당자 업무 0건 승격).
- 시험: `tests/test_charter.py`(신규).

**주의.** 분장표의 개인정보(성명·연락처)는 `docrole.ROSTER`와 같은 원칙으로 항목 값으로 옮기지 않고 문서만 가리킨다. 담당자 일치 판정에만 쓴다.

### S3 · 분류 단서 순서 확장과 분장 ↔ 자료 대조

**목표.** `_discover`의 단서를 **공문 → 분장 → 폴더 → 본문 군집**으로 늘리고, 분장과 실제 자료가 어긋나는 곳을 드러낸다.

**할 일**

1. `_charter_plan(db, excluded)` 신설 — `_official_plan`과 `_folder_plan` 사이에 둔다.
   - 분장 항목마다 대응 문서 찾기: 폴더명 알맹이 일치 > 파일명 알맹이 일치 > 본문 임베딩 유사(항목명+세부업무 문장).
   - 공문 업무와 이름이 겹치면 공문 업무에 합치고 분장 항목을 별칭으로 단다.
2. 폴더 업무·군집 업무가 분장 항목과 겹치면 **분장 이름을 대표 이름**으로 쓴다(사람이 정한 이름이 아니면).
3. **대조 결과** 세 갈래를 만든다.
   - `charter_only`: 분장에는 있는데 자료가 없음 → "자료를 찾지 못한 업무"(새로 맡은 업무이거나 다른 곳에 자료가 있음).
   - `data_only`: 자료는 많은데 분장에 없음 → "분장 밖 업무 후보"(S1 자료량 비중이 높은 순).
   - `matched`: 둘 다 있음.
4. `Discovery` 요약에 세 갈래 건수를 넣는다.

**완료 기준**

- 분장이 없는 프로젝트는 지금과 결과가 같다(기존 `test_official_discovery.py`, 폴더·군집 시험 회귀 0).
- 합성 픽스처(분장 6건 · 폴더 5개 · 분장 밖 폴더 1개)에서 세 갈래 정확히 분류.
- 시험: `tests/test_charter_discovery.py`(신규).

### S4 · 분류 확인 게이트와 재배치

**목표.** 집중 분석 전에 사용자가 업무 체계를 한 번 확인하고, 확정된 체계로 사본을 재배치한다.

**할 일**

1. 온보딩에 **업무 체계 확인** 단계: 업무 목록(분장·공문·폴더 출처 표시, 자료량 막대), 이름 고치기·합치기·나누기·'업무 아님'. 기존 업무 교정 기능을 재사용하고 `decided_by='user'`로 남긴다.
2. 게이트는 **막지 않는다**: "나중에 확인"을 누르면 제안 그대로 S5로 간다(지금처럼 끝까지 자동으로 도는 흐름을 유지).
3. 확정 직후 **사본 인계 폴더 만들기**를 바로 제안한다. 폴더 구조는 분장 체계를 따른다: `<출력루트>/<대업무>/<세부업무>/<연도>/공문·PC자료`. `handover_folder.py`에 분장 상하 구조 반영.
4. 재배치 안내문(`00_인계_안내.md`)에 `charter_only`·`data_only` 목록을 싣는다.

**완료 기준**

- 확정 → 사본 폴더 → `manifest.json` 해시가 원본과 일치. 원본 변경 0건(`output_policy` 시험).
- 시험: `tests/test_handover_folder.py` 확장, `tests/test_onboarding.py` 확장.

### S5 · 업무 단위 집중 분석

**목표.** 분석을 업무 단위로 돌려, 먼저 끝난 업무부터 바로 쓸 수 있게 한다.

**할 일**

1. 파이프라인 뒤 단계(`STAGE_ROLES`·`STAGE_CYCLES`·`STAGE_STEPS`·`STAGE_RESTORE`·`STAGE_CHUNKS`)를 **업무별 작업**으로 나눠 큐에 넣는다. 순서는 S1 자료량 비중 → 분장 비중 → 공문 건수.
2. 업무별 진행 상태 `task_analysis_state(task_id, stage, state, finished_at)` 기록. 업무 목록·카드에 "분석 중 / 분석 완료"를 표시.
3. 업무 하나가 끝나면 신호(`task_analyzed(task_id)`)를 낸다 — S6이 이 신호를 받는다.
4. 업무에 속하지 않은 문서(미분류)는 마지막에 한꺼번에 처리.

**완료 기준**

- 업무 5개 픽스처에서 첫 업무 완료 신호가 전체 완료보다 먼저 온다.
- 전체 결과는 지금의 일괄 처리와 같다(역할·주기·절차·복원 결과 비교 시험).
- 취소·재개 시 끝난 업무는 다시 돌지 않는다.

### S6 · 업무 카드 → 노트북 자동 연결 → AI 업무 매뉴얼

**목표.** 업무 분석이 끝나면 그 업무의 카드와 노트북이 이미 준비돼 있다. 노트북을 열면 그것이 그 업무의 AI 매뉴얼이다.

**할 일**

1. **자동 생성**: `task_analyzed(task_id)`를 받아 백그라운드에서 `notebook_tasks.open_for_task(db, task_id, client=None)` 실행.
   - 모델 호출 없이 만든다(정리본은 규칙 기반 `brief_markdown`). 출처 요약 등 모델 작업은 노트북을 처음 열 때 한다 — 업무 30개에서 30번의 모델 호출을 미리 하지 않는다.
   - 대상: `origin='ai'`·`status='proposed'` 이상이고 `not_a_task=0`, 묶음(`loose`) 업무 제외, 문서 2건 이상.
   - 사용자가 업무를 합치거나 '업무 아님'으로 하면 노트북은 보관(archive)하고 지우지 않는다.
2. **카드 ↔ 노트북 한 번에**: 업무 카드(`ui/widgets/task_card.py`)에 **AI 매뉴얼 열기** 버튼. 업무 목록에서 카드를 누르면 업무 상세, 버튼을 누르면 노트북. 노트북 쪽 머리에는 **업무 카드로** 되돌아가기.
3. **매뉴얼로서의 첫 화면**(노트북 스튜디오 기본 탭)
   - 업무 정리본(목적·주기·일정·처리 순서·결과물·확인할 것)을 `task_manual.build`와 같은 구획으로 보인다. 화면과 정리본이 같은 말을 하도록 `workcard`/`task_manual` 구조를 그대로 쓴다.
   - **추천 질문**: 업무 종류·다음 일정·공백에서 만든 질문 5개(예: "다음 제출 기한과 제출처는?", "작년에는 어떤 서식으로 냈나?", "회신이 확인되지 않은 공문은?").
   - 분장 출처 업무면 분장 항목 원문을 근거로 함께 보인다. `charter_only`면 "자료를 찾지 못했습니다 — 넣을 자료가 있으면 추가하세요"를 안내.
4. **판본 갱신**: 재분석으로 업무 내용이 바뀌면 `outdated()`로 감지해 정리본 새 판을 넣고(`manual_versions`), 노트북에 "업무 내용 변경 · 판 n → n+1"을 알린다. 지난 답의 인용은 옛 판으로 계속 열린다(기존 동작).
5. **왕복**: 노트북 대화에서 사용자가 확인·교정한 사실(기한, 제출처 등)을 "업무에 반영"으로 업무 항목에 올린다(`decided_by='user'`). 다음 정리본 판에 실린다.
6. **내보내기**: 인수인계 매뉴얼(`.md`)과 사본 인계 폴더의 `00_업무안내.md`가 노트북 정리본과 같은 판을 쓰도록 판 번호를 함께 적는다.

**완료 기준**

- 분석 완료 직후 업무 수만큼 노트북이 있고, 각 노트북에 정리본 1건 + 업무 문서가 연결돼 있다.
- 모델이 꺼져 있어도 노트북이 만들어지고 FTS 검색으로 답한다.
- 같은 내용으로 다시 분석하면 판본이 오르지 않는다(`manual_versions` 해시).
- 업무 합치기 → 노트북 보관, 되돌리기 → 복원.
- 시험: `tests/test_notebook_tasks.py`·`test_notebook_reopen.py` 확장, `tests/test_auto_notebooks.py`(신규), UI 스모크.

### S7 · 실자료 검증

## 3. 진행 순서와 위험

### 권장 순서

1. **S1** — 가장 싸고 효과가 바로 보인다. 다른 단계의 입력(자료량 비중)이 된다.

3. **S2 → S3** — 분류 품질을 올리는 본체.
4. **S5** — 파이프라인 구조 변경이라 가장 크다. S3 이후 진행.
5. **S4, S6 나머지(첫 화면·왕복·판 표시)**.
6. **S7**.

### 위험과 대응

| 위험 | 대응 |
|---|---|
| 분장표가 과 전체·여러 연도·형식 제각각 | 전임자 행 선택을 사용자에게 맡기고, 추출 결과는 제안으로만 둔다. 표 규칙 → 모델 순으로 시도 |
| 분장이 실제 업무와 어긋남(끝난 업무, 분장 밖 업무) | 분장을 정답으로 쓰지 않고 `charter_only`·`data_only`를 드러낸다 |
| 노트북 대량 생성으로 목록이 어지러움 | 업무 노트북을 "업무 매뉴얼" 묶음으로 따로 보이고, 사용자가 만든 노트북과 섞지 않는다 |
| 업무 단위 분석(S5)이 전체 결과와 달라짐 | 일괄 결과와 비교하는 회귀 시험을 먼저 만든다 |
| 재분석 때 노트북 판이 자주 바뀜 | 정리본 해시가 같으면 판을 올리지 않는다(기존 원칙), 바뀌면 무엇이 바뀌었는지 함께 알린다 |
