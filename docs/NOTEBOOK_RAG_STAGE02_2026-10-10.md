# 노트북 RAG 2단계 — 부모·자식 검색 기반

2026-10-10. [고도화 계획](NOTEBOOK_RAG_UPGRADE_PLAN_2026-10-09.md)의 2단계 첫 구현 묶음이다. 2단계 전체 완료나 실문서 검색 정확도 향상을 의미하지 않는다.

## 반영한 동작

기존 `chunks`를 답변·검증·인용에 쓰는 부모로 유지하고 `chunk_children`을 검색용으로 추가했다. 자식은 약 500자 창에서 문장·줄 경계를 우선한다. 탭으로 직렬화된 표는 행 경계에서 나누고 첫 행(시트명 다음 행 포함)을 반복한다. 500자를 넘는 단일 행은 값을 찢지 않도록 보존한다. `start_offset`/`end_offset`는 반복된 머리행을 제외한 부모 원문 범위다.

글자 검색은 자식 FTS에서 부모 ID로 복원한다. 아직 자식이 없는 부모는 기존 FTS에서 검색된다. 선택 문서 범위와 원본 누락 여부를 두 경로에 동일하게 적용한다. 같은 부모의 자식들이 후보 상한을 독점하지 않도록 부모를 중복 제거한 뒤 상한을 적용한다.

의미 검색은 부모에 속한 모든 자식의 해당 모델 임베딩이 준비되고 차원도 일치할 때 자식 벡터로 전환한다. 완성 전에는 기존 부모 벡터를 유지한다. 검색 점수는 자식 최고 점수로 부모를 한 번만 순위화하며 원질문·확장질문에 같은 규칙을 적용한다. 답변 문맥·숫자 검증·저장 인용은 계속 같은 부모 원문과 위치를 사용한다.

노트북 파일 처리와 프로젝트 분석 파이프라인에서 자식 생성·임베딩을 실행한다. 자식 생성은 문서별 트랜잭션, 임베딩은 배치별 트랜잭션이다. 실패·취소 시 완성된 배치는 유지되고 다음 실행에서 남은 자식부터 준비한다. 재개 판정에 누락 자식 임베딩도 포함했다.

## 데이터 보존

스키마는 v7→v8이며 기존 승격 도구가 변경 전 `.bak-v7` 백업을 만든다. 신규 표·FTS·트리거만 추가한다. 이 경로는 기존 부모 ID, 위치, 텍스트, 부모 임베딩, 노트북 대화·메모를 삭제하거나 변경하지 않는다. 부모 청킹 버전 `2`는 유지했으므로 이번 작업 때문에 기존 `sync_chunking_version()`의 삭제 재색인이 발생하지 않는다.

자식만 재구성하는 이번 경로는 저장된 `chunk_id`/`locator`/`exact_quote`를 보존한다. 파일 해시가 달라지면 기존 인용 유효성 검사는 계속 무효로 판정한다. 전체 부모를 교체하는 재색인과 파일 내용 변경 후 이력 보존은 별도 작업이다.

## 검증

기존 개발 평가 자료는 회귀 확인에 사용하며, 새 독립 holdout이나 성능 향상 측정으로 해석하지 않는다.

- 자식 청킹·범위 제한·부모 복원·중복 점수 방지·실패/취소 후 재개·생성 롤백·v7 백업 승격·인용 유효성·삭제 전파·구/신색인 혼용·차원 불일치: 신규 14개 시험 통과.
- 실제 로컬 모델: 기존 개발 시나리오 앞 12개, 15대화 턴, seed=0에서 확장 꺼짐/켜짐 각각 전부 통과. 부모 30개·자식 30개이며 자식 길이 49~62자다. 이 자료는 큰 부모 복원의 효과를 검증하지 않는다. `.test_runs/notebook-stage2-dev.json`에 부분 실행 여부와 모델·코드 해시를 기록했다.
- 긴 DOCX의 실제 업로드→자식 생성/임베딩→검색→수료인원 37명 답변→부모 원문 인용 저장·유효성 대조 시험 1개 통과. 담당인원 2명을 함께 넣었다. `.test_runs/notebook-stage2-long-live.txt`. 한 개의 합성 사례이며 일반 성능을 뜻하지 않는다.
- Windows PyInstaller 빌드와 실행물 자체 점검 통과. 표본 81건 파싱, 복원→수행 기록→복원본→묶음→가져오기→재연결을 확인했다. HWP 표본은 없으며 HWPX는 1건이다. 실행물: `.test_runs/notebook-stage2-bundle/NunchiCoach/NunchiCoach.exe`.

## 남은 2단계 작업

- 제목 계층, 표 ID·병합 셀·단위·OCR 출처 등 파서 구조 메타데이터를 별도 필드로 보존.
- 큰 표가 기존 부모 1,200자 강제 분할에서 이미 잘리는 문제 해결. 이번 자식 분할은 전달받은 부모 내부의 행을 보존하며, 이미 잘린 부모 원문을 복구하지는 않는다.
- 부모 창 800~1,600자와 자식 창 250~500자 비교, 다양한 실제 형식으로 검색·문맥 복원 품질 평가.
- 부모 자체를 교체할 때 구색인 유지, 인용 이력 보관, 검증 후 전환·취소·재개·롤백을 지원하는 전체 재색인 경로.

현재는 새 색인 준비 중 기존 검색을 유지하기 위해 부모와 자식 임베딩을 함께 저장한다. 그만큼 준비 시간과 저장량이 늘어난다. 부모별 전환은 원자적이지만 프로젝트 전체를 한 번에 전환하는 구조는 아니다.
