# 눈치코치(Nunchi_Coach) 단계별 구축 계획서

작성일·개정일: 2026-10-06 · 계획 버전: 3.0 · 목표: 2026년 공공 AI 대전환 챌린지 세션2 ‘업무바통’ 제출

개정 핵심: **온나라에서 전임자 작성 문서를 찾아 본문·붙임·메타데이터를 로컬로 수집하고, 기존 업무 폴더와 함께 출처를 확인할 수 있는 업무 지식으로 활용한다.** 전임자 부재에서도 자료를 복원해 후임자의 파악·판단·수행 부담을 줄이는 기존 목표와 결합한다.

구현 착수: 2026-10-06. 초기 소스 이식·품질 수정·온나라 합성 수집을 시작했으며 실제 완료 범위는 [구현 진행 기록](D:/Dev/Nunchi_Coach/docs/구현진행_2026-10-06.md)에 관리한다. 이 계획의 모든 기능이 완료된 것은 아니다.

## 1. 구축 방향과 계획의 전제

**눈치코치는 온나라의 전임자 작성 문서와 로컬 업무자료를 모아 업무 맥락·처리 절차·현재까지의 기록·다음 행동을 복원하고, 전임자 설명 없이도 후임자가 업무를 이어가도록 돕는 Windows 업무 인수인계·수행 지원 도구다.** 전임자 부재로 후임자에게 집중되는 파악·판단·실행 부담을 시스템이 줄이고, 안정적인 업무 승계를 통해 조직 기능의 연속성과 안정성을 지키는 것을 목표로 한다.

제품의 정체성은 세 축으로 구성한다.

| 축 | 핵심 역할 | 연결되는 가치 |
|---|---|---|
| 온나라 공식 자료 수집 | 전임자 작성 문서의 검색·본문/붙임 다운로드·출처 보존 | 개인 폴더에 남지 않은 공식 업무 기록 보완 |
| 자료 기반 업무 복원 | 온나라 자료와 로컬 파일을 함께 분석하고 충돌·공백 정리 | 전임자 부재에서도 업무 파악 가능 |
| 후임자 수행 지원 | 절차·서식·다음 행동·결과 기록 연결 | 인계 부담 경감과 조직의 업무 연속성 |

온나라 기능은 **기관 환경에 맞는 실제 수집 연결부 1종을 구현할 핵심 기능(P0)**으로 올린다. 실제 시스템 사양·접근 환경은 아직 제공되지 않았으므로 연결 방법은 초기 확인 뒤 확정한다. 가져오기만 구현하고 온나라 직접 수집까지 완성했다고 설명하지 않는다.

전임자가 참여할 수 있으면 설명과 검토를 더해 인계 품질을 높인다. 전임자의 응답·승인·사전 인계본은 프로그램 사용과 업무 복원의 선행 조건이 아니다. 조직의 안정성은 업무 누락·중단·재학습 부담을 줄인 결과로 추구하며, 이 개념을 조직 내 확인 책임 배분이나 공동 승인 절차로 구현하지 않는다.

핵심 사용자 흐름은 두 가지다. 데이터·검색·업무 안내 엔진은 함께 사용한다.

| 사용 상황 | 시작 조건 | 핵심 흐름 | 결과 |
|---|---|---|---|
| 자료만으로 업무 이어받기 | 후임자의 온나라 접근과 남은 자료, 전임자 참여 없음 | 작성자·범위 선택 → 온나라 수집+폴더 분석 → 업무 복원 → 수행 지원 → 결과 기록 | 공식 근거를 보완한 업무 복원본 |
| 전임자와 함께 인계하기 | 전임자의 설명·검토 가능 | 같은 수집·자료 분석 → 전임자 보충·수정 → 인계본 발행 → 후임자 수행 지원 | 전임자 검토가 더해진 인계본 |

두 흐름은 업무별로 병행할 수 있다. 일부 업무만 전임자가 확인했어도 나머지 업무를 사용할 수 있다. 나중에 전임자의 답변을 받으면 해당 항목의 이력에 추가하며 이미 시작한 작업을 다시 만들지 않는다. Gemini의 업무 맥락·현안·검증된 지식이라는 방향은 이 공통 흐름에 맞춰 채택한다.

온나라에 당장 연결할 수 없을 때도 기존 폴더 분석과 이전 수집본을 사용할 수 있다. 연결·수집 실패와 ‘관련 문서 없음’은 별개로 표시한다. 온나라 권한과 기능은 후임자의 현재 사용 환경을 기준으로 이용하며 전임자의 계정·응답을 요구하지 않는다.

이 문서는 **구축 목표와 완료 기준을 정의한 계획**이다. 계획 수립 당시에는 코드 이식·수정·배포·제출을 수행하지 않았다. 후속 구현 착수로 현재 작업 소스는 `D:/Dev/Nunchi_Coach/app`과 `tests`에 있으며 참조 기준은 별도 `D:/Dev/docs_mate`의 커밋 `01a04e2`다. `.analysis_audit/docs_mate`는 이전 검사의 복사본으로 제품 소스의 출발점에 사용하지 않았다. 구현과 실제 기관 검증의 완료 여부는 진행 기록에 따로 남긴다.

### 1.1 판단 근거의 우선순위

| 자료 | 계획에서의 역할 |
|---|---|
| 사용자가 추가·정정한 핵심 컨셉트 | 온나라 전임자 작성 문서의 로컬 수집, 전임자 부재에서의 부담 경감, 업무 연속성으로 조직 안정성을 지키는 목표 |
| 대상 기관 온나라의 실제 화면·사양·내보내기 표본 | 연결 방법·검색 범위·문서 ID·본문 형식·권한을 확정할 구현 근거. 현재 미확보 |
| docs의 대회 안내서 HWPX 2건 | 대회 일정·제출 규격·평가 기준의 근거 |
| 참조 프로젝트 실제 코드와 재현 검사 | 기존 구현과 결함 판단의 근거 |
| Codex 심층분석 보고서 | 코드·원문·실행 결과를 연결한 검증 기록 |
| Claude 분석보고서 | 대회 적합성과 제출 준비 항목의 참고 자료 |
| 업로드한 Gemini 제안서 | 제품 아이디어와 장기 확장 방향의 참고 자료 |

Gemini 문서 안의 ‘필수’, ‘전면 개편’, ‘완벽한 구현’이라는 표현은 사용자가 명령한 구현 범위로 취급하지 않는다. 경쟁사 소개·정책 전망·효과 수치도 그 문서에 적혀 있다는 이유만으로 검증된 사실이 되지 않는다.

일정은 제공된 안내서 기준이다. 이후 운영기관의 변경 공지까지 확인한 일정은 아니므로 제출 준비 단계에서 다시 대조한다. 개발 일정과 품질 수치는 본 계획의 제안이며 대회 규정과 구분한다.

### 1.2 프로젝트의 성공 정의

1. 후임자는 전임자의 작성자 식별자·소속 이력·대상 기간을 선택해 온나라의 조회·다운로드 가능한 문서를 로컬로 수집하고 결과 건수를 확인한다.
2. 개인 폴더에 없는 공식 문서·붙임이 업무 복원과 답변의 근거로 연결되고 온나라 문서 ID·번호·결재 상태·수집 시점으로 출처를 추적한다.
3. 후임자는 사전 설명·인계본 없이 온나라 수집본과 자료 폴더로 주요 업무, 처리 순서, 필요한 입력·서식, 다음 행동을 안내받는다.
4. 시스템이 자료 찾기·연결·비교·절차 정리·수행 기록을 맡아, 후임자가 모든 파일을 먼저 읽고 초안을 직접 만드는 부담을 줄인다.
5. 전임자 확인이 없어도 근거를 볼 수 있고 수행 안내를 사용할 수 있다. 문서의 명시 내용·추정·미상·사람 확인 상태를 구분한다.
6. 불명확한 한 항목 때문에 전체 업무가 멈추지 않는다. 시스템은 관련 자료를 추가 탐색하고, 진행 가능한 준비 작업과 해당 항목에 필요한 구체적인 확인 방법을 제시한다.
7. 전임자가 참여하면 항목별 수정·보충이 가능하며, 그 결과와 후임자의 실제 수행 경험이 다음 인계에 남는다.
8. 다른 PC·드라이브에서도 근거·수정·수행 이력을 이어받는다. 근거 없는 기한·금액·담당자·완료 상태를 확정하지 않는다.
9. 수집 완전성·첫 업무 완료 시간·필수 단계 누락·문서 탐색량을 측정해 공식 자료 보완과 후임자 부담 경감을 검증한다.

### 1.3 시스템이 줄여야 하는 후임자의 부담

| 후임자가 혼자 감당하던 작업 | 눈치코치가 맡을 작업 | 후임자가 받는 도움 |
|---|---|---|
| 온나라에서 전임자 문서를 여러 번 검색·저장 | 작성자 식별·기간별 전체 목록 순회·본문/붙임 다운로드·실패 재개 | 수집 상태와 출처가 보존된 공식 자료 묶음 |
| 폴더 전체를 읽어 업무 범위 파악 | 문서·표·날짜·공통 업무 단서로 업무별 자료 묶음 생성 | 업무 목록과 첫날 브리핑 |
| 어느 자료가 현재 업무에 맞는지 비교 | 대상 연도·문서 버전·관련 근거·상충 내용 정리 | 근거가 연결된 현재 기록과 주의점 |
| 처리 순서와 서식 찾아 조합 | 명시된 절차와 과거 수행 사례를 구분해 정리 | 필요한 입력·서식·처리 단계·예상 산출물 |
| 질문할 내용조차 모르는 상태에서 탐색 | 빠진 필드와 막힌 단계 식별, 관련 자료 재검색 | 알아야 할 질문과 찾아볼 구체적인 자료 |
| 한 번 수행한 과정을 다시 정리 | 단계 완료·사용 문서·새 산출물·해결 내용을 저장 | 재사용 가능한 업무 기록과 다음 인계 자료 |

‘조직 안정성’은 제품의 지향점이다. 제출 시에는 전임자 개입 없이 수행한 업무의 완료율·누락률·소요시간으로 그 기여를 입증한다. 자료에 존재하지 않는 암묵지까지 완전히 복원한다는 성능 보장을 하지 않는다.

## 2. Gemini 분석의 수용·수정·보류

### 2.1 현행 제품 설명에서 바로잡을 부분

Gemini 참고자료 8·9·14의 표기와 URL은 `Ubermensch/myAI`의 `docs/RAG.md`, `public/app.js`, `output/make_manual.mjs`를 가리킨다. 이는 로컬 `docs_mate`와 다른 프로젝트 식별자다. 해당 비공개 저장소 내부의 내용을 검증한 것은 아니지만, 로컬 코드에서 아래 구성은 확인되지 않는다.

| Gemini의 설명 | 실제 docs_mate 기준 | 눈치코치 계획에 미치는 영향 |
|---|---|---|
| 브라우저·암호화 IndexedDB·개인 룸·부서 지식팩 | PySide6 데스크톱, 프로젝트별 SQLite | 웹 전환을 선행 과제로 삼지 않는다 |
| Qdrant + SQLite + graph.sqlite | SQLite FTS5 trigram + NumPy 벡터 검색 + RRF | 기존 검색을 고치고 측정한 뒤 저장소 확장을 판단한다 |
| Level 1~3 RBAC, safeDOC가 구현됨 | 해당 구성 없음, 추출 본문 DB도 암호화되지 않음 | 보안 기능을 구현된 것처럼 홍보하지 않는다 |
| Map-Reduce 장문 요약기가 구현됨 | 해당 파이프라인 없음 | 항목별 증거 집계부터 설계한다 |
| HWPX 파서가 없음 | 파서가 있지만 표 중복·구조 손실 존재 | 신규 전면 개발보다 기존 파서 교정이 우선이다 |
| 시점 인식·온보딩·업무 흐름이 없음 | 날짜 추정, 연도 필터, 타임라인, 첫날·첫주 가이드 존재 | 기존 기능에 유효기간과 검토 상태를 연결한다 |
| 채팅만으로 결과 제공 | 업무·일정·문서·질문 화면, Markdown 보고서 존재 | 검토와 인계 기능을 기존 화면에 통합한다 |

Claude 보고서의 ‘원본 읽기 전용 충족’도 제한해서 해석한다. 분석 파이프라인은 원본을 읽지만, 보고서·감사 CSV 저장 경로를 원본으로 지정하면 덮어쓸 수 있는 문제를 후속 검사에서 재현했다. 기존 보고서의 결론보다 재현 결과를 우선한다.

### 2.2 제안 기능의 채택 방식

| 제안 | 판단 | 제출 버전에서 구현할 형태 |
|---|---|---|
| HWPX 표·문단 구조 보존 | 즉시 채택 | 중복 제거, 행·열·머리글·단위 연결, 근거 위치 표시 |
| 시간 맥락과 최신 규정 판단 | 수정 채택 | 작성일·대상연도·시행일을 구분하고 확인된 대체 관계만 적용 |
| 전임자에게 확인 질문 | 선택 경로로 채택 | 참여 시 보충 질문. 부재 시 자료 재검색·빈칸 설명·다음 행동을 먼저 제공 |
| 검증된 지식 카드 | 채택 | 업무별 요약·다음 행동·현안·연락 대상에 출처와 검토 상태 부착 |
| 첫 주 안내·미결 현안 알림 | 핵심으로 채택 | 자료 기반 업무 시작 안내, 명시 기한과 기록상 상태 표시, 미상 구분 |
| 조직 상태 그래프 | 경량화 | SQLite의 업무–현안–연락 대상–문서 관계로 시작 |
| 법정 서식 HWPX 자동 완결 | 범위 수정 | 검토된 항목의 서식 초안 출력. 공식 인계·결재 완료와 구분 |
| 온나라 문서 활용 | 핵심 수집 기능으로 채택 | 대상 작성자 문서 검색·다운로드·메타데이터 보존, 로컬 분석 결합 |
| Qdrant·웹·다중 사용자·전자결재 제출 | 제출 후 보류 | 온나라 자료 읽기·다운로드는 P0, 결재 생성·상신은 별도 후속 범위 |
| 개인정보 완전 자동 마스킹 | 보장 표현 배제 | 제출은 합성 자료. 실사용 전 별도 보호 설계·기관 검토 |
| 4주→3일, 작성 행정력 80% 절감 | 효과 주장으로 사용 안 함 | 동일 과제의 수작업/도구 사용 시간과 수정량을 실측 |

오래된 문서라는 이유만으로 폐기하지 않는다. 과거 연도의 업무를 묻는 질문에는 당시 문서가 정답일 수 있다. 작성일이 최신이라는 이유만으로 법적 효력·승인권자·미완료 여부를 확정해서도 안 된다.

### 2.3 대회 및 법정 서식 해석

실제 평가 배점은 **활용성 40점·완성도 30점·확산용이성 30점**이다. Gemini의 네 가지 평가 축과 ‘지식 그래프 가점’을 공식 심사표로 사용하지 않는다. 안내서는 웹·데스크톱·문서형 등 구현 형태와 지원 파일 범위를 팀 재량으로 둔다. HWPX 출력·조직 그래프·온나라 직접 연계는 제출 의무가 아니다.

다만 사용자가 추가한 온나라 수집은 눈치코치 자체의 핵심 출하 기준으로 둔다. ‘대회 의무 아님’과 ‘본 프로젝트의 P0’는 함께 성립한다.

법정 서식 관련해서는 현 명칭인 「행정업무의 운영 및 혁신에 관한 규정」과 시행규칙을 기준으로 검토한다. 시행규칙 제45조는 별지 제12호 업무인계·인수서 작성을 규정한다. 따라서 ‘제61조만으로 HWPX 생성이 공식 인계 절차까지 완결된다’고 설명하지 않는다. 기관 적용 서식과 전자적 인계 절차를 확인한 뒤 출력 항목을 매핑한다. [국가법령정보센터 시행규칙 제45조·별지 제12호](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=252189)

## 3. 제출 버전의 범위

### 3.1 반드시 완성할 P0

여기서 P0는 **프로젝트 내부의 출하 기준**이며 대회의 공식 필수기능 목록과 다르다.

| 영역 | P0 범위 | 사용자에게 보이는 결과 |

| 온나라 문서 찾기 | 작성자 식별·소속/기간 범위, 전체 페이지·기간 구간 순회, 안정 문서 ID 목록 | 어떤 범위에서 몇 건을 찾았는지 확인 |
| 온나라 로컬 수집 | 본문·붙임·메타데이터, 큐·중단/재개·재시도·성공/누락 대조 | 직접 저장의 부담을 줄이는 수집 진행과 누락 목록 |
| 공식 출처 보존 | 기관/시스템·문서 ID·번호·작성자·상태·시점·파일 해시·관계 보존 | 공식 등록본과 개인 파일의 출처 차이 확인 |
| 두 자료원 결합 | 온나라·로컬 중복 정리, 초안/최종본 연결, 충돌·빈칸 보완 | 추가된 공식 근거가 업무·절차·답변에 사용됨 |
| 자료 읽기 | 기존 형식 유지, HWPX 우선 교정, 지원 실패를 명확히 표시 | 읽은 파일·실패 파일·실패 이유 확인 |
| 원본 보호 | 모든 출력의 입력 경로 충돌 차단, 출력 폴더 분리 | 분석·보고서·인계 작업 후 원본 불변 |
| 자동 업무 복원 | 업무 요약·처리 절차·기한·현안·다음 행동의 근거가 연결된 후보 생성 | 사전 인계본 없이 첫 브리핑과 업무 카드 제공 |
| 수행 안내·작성 지원 | 입력 자료·서식·선행 조건·처리 단계·근거가 연결된 텍스트/표 초안·완료 확인 방법 | 후임자가 과거 사례와 근거를 보며 첫 업무 수행 |
| 정보 공백 처리 | 관련 자료 재검색, 충돌 비교, 미상 항목에 필요한 자료 안내 | 전체 작업을 멈추지 않고 다음 가능한 행동 파악 |
| 선택적 사람 검토 | 전임자/후임자의 수정·보충·확인·제외, 변경 이력 | 자료에서 복원한 내용과 사람 확인 내용 구분 |
| 업무 복원본·인계본 | 생성/발행 시점 스냅샷, 미확인 목록, 이용 시작·수신 기록 | 사람의 확인 유무를 보존한 버전 열람 |
| 자료 재연결 | 상대 경로·해시 검증으로 이동 자료 연결 | 다른 PC에서도 교정과 근거 유지 |
| 후임자 시작 화면 | 자료에 근거한 다음 행동, 기록상 기한·현안, 첫 업무 안내 | 전임자 응답 대기 없이 업무 시작 |
| 수행 기록 | 단계 진행·완료 근거·새 자료·해결 내용 저장 | 이어서 수행하고 다음 담당자에게 다시 전달 |
| 질문 | 명시 범위 준수, 인용·수치 검증 교정, 근거 부족 유보 | 답변·근거 부족·실행 실패 구분 |
| 배포 | Windows 실행물, 합성 자료, 안내서, 같은 버전의 제출 문서 | 개발자 도움 없이 핵심 흐름 재현 |

### 3.2 여유가 있을 때 추가할 P1

- 검토된 인계본을 한 가지 고정 HWPX 서식으로 출력한다. 모든 기관 서식의 범용 편집은 다루지 않는다.
- 두 번째 생성 모델에서 동일 핵심 흐름을 검증한다. 대회 권장 사항으로 우선 투자하되, 검증되지 않은 모델은 지원 목록에서 제외한다.
- 승인된 내부 추론 서버 연결을 추가한다. 실제 접속 사양이 확보되지 않으면 인터페이스와 모의 계약 검사까지만 제공하고 실제 연동 완료라고 쓰지 않는다.
- 담당자·현안의 고급 개체 통합과 광범위한 관계 추론을 추가한다. 명시된 업무·절차·기한·현안의 최소 자동 추출은 P0에서 제공한다.
- 업무와 연락 대상의 관계를 간단한 목록이나 도식으로 보여 준다. 추론된 결재 권한을 확정 표시하지 않는다.

### 3.3 제출 후 P2

다중 사용자 웹 서비스, 조직 SSO/RBAC, 중앙 벡터 DB, 결재 작성·상신/메일 커넥터, OCR, 모바일, 자동 알림 발송, 고도화된 그래프 추론, DB 암호화 및 기관별 접근 통제는 별도 운영 요건을 정한 뒤 추진한다. 온나라 검색·다운로드 연결은 P0다. 제출 버전은 단일 사용자·로컬 작업을 기본 운영 경계로 명시한다.

## 4. 재사용 구조와 변경 지점

### 4.1 목표 구성

| 계층 | 재사용 | 추가·개선 |
|---|---|---|
| UI | PySide6 업무·일정·문서·질문 화면 | 온나라 가져오기·수집 현황, 자료로 시작하기, 첫 업무 카드, 수행 단계 |
| 업무 로직 | 분류, 날짜 추정, 반복 업무, 타임라인, 가이드 | 업무 복원·공백 분석·다음 행동·수행 기록, 선택적 검토·발행 |
| 검색 | SQLite FTS5, NumPy, RRF | 출처·문서 상태·시점에 따른 근거 선택, 엄격한 범위·표 문맥·검증 정책 |
| AI | Ollama 클라이언트, 프롬프트·스키마 | 생성/임베딩 분리, 모델 능력 설정, 오류·시간 계측 |
| 수집 | 파일 조사, 해시, 기존 파서, 작업 큐 | 온나라 검색/다운로드 연결부, HWPX·ODT 등 본문 구조, 안정 ID·수집 재개 |
| 저장·출력 | SQLite, 교정·감사 이력, Markdown 보고서 | 스키마 이행, 인계 스냅샷, manifest, 안전한 출력 |

공통 처리 흐름은 **온나라 문서 수집+로컬 자료 → 원문·메타데이터 보존 → 중복/버전 연결 → 근거 수집 → 업무·절차 후보 생성 → 충돌·빈칸 탐지 → 자료 재검색 → 수행 안내 → 선택적 사람 보충 → 수행 기록**이다. 사람 확인을 기다리지 않고 자료 기반 결과를 제시하되 각 항목의 근거 상태를 유지한다. 요약을 다시 요약하면서 출처를 잃지 않도록 최종 항목까지 문서 버전과 위치를 유지한다.

수집한 문서와 전임자 메모는 분석할 데이터로 취급한다. 문서에 포함된 ‘이전 지시를 무시하라’, 외부 전송·파일 변경 등의 문장을 앱 실행 명령으로 해석하지 않는다. 모델 응답도 허용된 스키마의 항목 후보로만 처리하며 파일 작업·서버 연결 설정을 직접 실행하지 못하게 한다.

### 4.3 자료만으로 첫 업무를 수행하게 하는 구현 흐름

1. **범위 파악:** 기존 업무 분류와 날짜 추출을 재사용하되 처리·미처리·실패 파일 목록을 보여 준다. 읽지 못한 자료를 반영한 것처럼 요약하지 않는다.
2. **근거 추출:** 업무별 문서·표에서 목적, 요구 입력, 명시 절차, 기한, 제출 대상, 완료 기록을 구조화한다. 각 필드는 문서 버전과 위치를 가진다.
3. **절차 복원:** 문서에 적힌 절차를 우선 연결한다. 시간순 파일 목록은 수행 사례로 제공하고, 앞선 날짜라는 이유만으로 필수 선행 절차를 만들어 내지 않는다.
4. **현재 기록 정리:** 최신 기록의 시점과 그때의 상태를 제시한다. 후속 완료 자료가 없으면 ‘이후 상태 미상’으로 표시한다. 과거 완료 사례와 현재 해야 할 업무를 분리한다.
5. **공백 보완:** 빠진 항목마다 같은 업무·관련 문서의 재검색을 1회 수행한다. 찾지 못하면 필요한 문서 종류·살펴볼 위치·구체적인 확인 질문을 제공한다. 질의 반복으로 무한 탐색하지 않는다.
6. **수행 안내:** 목표, 준비 자료, 사용할 서식, 처리 순서, 단계별 근거, 기대 산출물, 완료 확인 방법을 한 카드에 연결한다. 확정하기 어려운 단계와 지금 할 수 있는 준비 작업을 구분한다.
7. **실행과 학습 기록:** 후임자가 수행한 단계와 새 산출물의 참조를 남긴다. 새 자료를 분석해 해결된 공백을 갱신하고 다음 담당자가 활용할 복원본 버전을 만든다.

작성 지원은 자료에서 확인한 값·문구·표를 초안에 배치하고 근거를 연결하는 범위로 시작한다. 빈 값은 빈칸으로 유지하며 기존 Markdown 출력과 별도 산출물 폴더를 재사용한다. 후임자는 이를 편집하거나 제시된 기관 서식에 옮겨 실제 업무를 수행한다. 결과 파일을 등록할 때 관련 단계에 연결하고 재분석 대상인지 구분한다. 서식 엔진·자동 제출·전자결재 연동을 첫 업무 수행의 선행 조건으로 추가하지 않는다.

첫 분석에서는 텍스트·표에 명시된 필드를 자동 생성하고, 근거를 찾지 못한 필드만 비워 둔다. 사람이 전 항목을 직접 입력해야 첫 화면이 완성되는 설계는 허용하지 않는다. 필드 추출 실패 시에도 기존 업무 묶음·검색·원문 열기를 제공하고 AI 생성 실패를 자료 부재와 구분한다.

### 4.4 업무 카드와 화면 원칙

첫 화면은 ‘자료로 업무 시작하기’를 제공한다. 전임자 참여 여부는 선택 정보이며, 참여자를 등록하지 않아도 분석·열람·업무 시작·복원본 저장이 가능하다. 기존 인계본이 있으면 가져오기 경로를 함께 제공한다.

| 카드 요소 | 표시 내용 |
|---|---|
| 해야 할 일 | 업무 목적과 이번에 만들 산출물 |
| 현재까지의 기록 | 마지막 문서의 상태·기준 시점, 이후 상태 미상 여부 |
| 시작 준비 | 필요한 입력 자료·서식·접근 경로·선행 조건 |
| 처리 순서 | 문서에 명시된 절차 / 과거 수행 사례 / 시스템 제안을 구분 |
| 다음 행동 | 지금 진행할 준비·작성 단계, 확인이 필요한 특정 단계 |
| 근거와 공백 | 바로 열 수 있는 근거, 충돌 내용, 빠진 정보를 찾을 방법 |
| 수행 결과 | 진행 기록, 결과 문서, 해결한 사항과 남은 사항 |

‘미확인’ 경고만 나열해 후임자에게 분석을 다시 맡기지 않는다. 예를 들어 제출 기한이 충돌하면 두 날짜의 문서·적용 연도를 비교해서 보여 주고, 확정 전에도 진행할 수 있는 자료 취합·초안 작성 단계를 안내한다. 제안한 단계는 업무 규정에서 직접 추출한 의무 단계와 구분한다.

### 4.5 킥 기능 — 온나라 전임자 작성 문서 수집

**제품 목표는 전임자가 온나라에 남긴 작성 문서를 찾아 로컬에 확보하고, 개인 폴더만으로는 부족했던 업무 근거를 보완하는 것이다.** 단순 다운로드 버튼에서 끝내지 않고 수집 범위·누락·본문과 붙임의 관계·공식 문서 상태까지 보존해 업무 복원과 질문의 근거로 사용한다.

온나라 문서2.0 제품 안내는 통합검색·자료관리와 개방형 문서포맷(ODF) 기안을 설명한다. 현재 docs_mate의 파서에는 ODT와 온나라 연결부가 없다. 따라서 온나라의 모든 본문이 HWPX로 내려온다는 전제를 버리고 실제 다운로드 표본에 맞춰 수집·파서를 추가한다. [온나라 구축사 제품 안내](https://www.kaoni.com/%EC%98%A8-%EB%82%98%EB%9D%BC-2-0-2/)

공개 자료만으로 해당 기관의 작성자 검색 필드·API·일괄 다운로드·인증·본문 내보내기 형식을 확정하지 못했다. 아래 연결 방식은 확인 후 선택할 구현 경로다. 공통 API나 주소를 임의로 만들지 않는다.

#### 4.5.1 ‘전임자가 작성한 문서 모두’의 범위

| 범위 요소 | 수집 규칙 |
|---|---|
| 작성자 | 가능한 경우 시스템 사용자 ID로 식별. 이름만 있으면 소속·재직 기간을 함께 대조하고 동명이인 선택을 사용자에게 보여 줌 |
| 소속 이력 | 전임자가 업무를 수행한 소속·사용자 ID 변경 이력을 수집 범위에 추가할 수 있음 |
| 기간 | 확인된 담당 기간 전체를 기본값으로 제안. 기간 불명은 사용자가 정하고 화면·manifest에 명시 |
| 문서 상태 | 조회 가능한 작성 문서를 폭넓게 찾고 등록·결재·발송·초안·반려 등 실제 제공 상태를 보존. 자동으로 결재 완료만 남기지 않음 |
| 본문·붙임 | 문서 본문과 제공되는 모든 붙임을 각 파일로 수집하고 부모 문서에 연결 |
| 작성 관여 역할 | 작성/기안/공동기안 관계를 실제 메타데이터에 따라 분리. 검토·결재 참여만 한 문서를 작성 문서에 섞지 않음 |
| 접근 범위 | 후임자 계정으로 조회·다운로드 가능한 범위에서 수집. 접근할 수 없는 이력·문서의 존재와 내용을 임의 추정하지 않음 |

이 범위는 검색 시작 전에 화면에 보여 준다. ‘모두’는 **명시한 기관·작성자·소속·기간·상태 범위에서 현재 계정으로 검색 가능한 결과 전체**를 뜻한다. 기관 전체 기록의 완전성까지 증명했다고 말하지 않는다. 검색 결과가 제한되거나 전체 건수를 얻지 못하면 ‘완전성 확인 불가’로 표시한다.

관련 회신·상위 지침은 작성 문서 본문에 제공된 연결 정보를 통해 별도 참고 자료로 확장할 수 있다. 이것은 작성자 검색의 완료 기준과 분리하고 기본 수집을 끝없이 넓히지 않는다.

#### 4.5.2 연결 방식의 선택

| 연결 방식 | 채택 조건 | 구현 범위·완료 판정 |
|---|---|---|
| 기관이 제공하는 API/공식 연계 | 실제 사양·접근 가능한 시험 환경이 제공됨 | 작성자 검색·페이지 순회·메타데이터·본문/붙임 다운로드를 계약에 따라 구현 |
| 정상 사용자 화면을 통한 수집 | API가 없고 브라우저의 검색·내려받기를 이용할 수 있음 | 사용자가 정상 로그인한 세션에서 목록·다운로드를 자동화하는 기관별 어댑터 1종. 페이지·파일 단위 성공을 확인 |
| 온나라 내보내기 파일 가져오기 | 직접 연결 환경 미확보 또는 기관이 내보내기만 제공 | 목록·본문·붙임·메타데이터 패키지를 가져오는 지원 경로. 직접 검색·수집 완료로 표기하지 않음 |

기본 제품 동작은 후임자의 정상 로그인 후 수집 시작이다. 인증서·MFA 입력은 사용자가 수행하고, 인증서 비밀번호·세션 토큰을 로그나 인계 패키지에 저장하지 않는다. 전임자 계정으로 대신 접속하는 방식은 전제로 두지 않는다. 로그인할 수 있다는 사실만으로 기관의 자동 수집·다운로드 허용 조건까지 충족했다고 가정하지 않고 초기 환경 확인에 포함한다.

기관별 버전·브라우저·다운로드 플러그인 차이는 어댑터 프로필로 둔다. 첫 제출 버전은 실제 확인한 기관 환경 1종만 지원한다. 인증 방식을 새로 만들거나 기관 DB에 직접 접속하는 범용 도구를 개발 범위에 넣지 않는다.

#### 4.5.3 수집 엔진과 연결 계약

연결부의 공통 계약은 `capabilities`, `resolve_author`, `list_documents`, `get_metadata`, `list_assets`, `download_asset`으로 구성한다. 목록 결과는 문서 ID와 다음 페이지/커서, 전체 건수 제공 여부, 실제 필터 적용 결과를 반환한다. 다운로드 결과는 파일 저장 위치·실제 MIME/크기·상태를 반환하고 로그인 페이지나 오류 HTML을 문서로 등록하지 않는다.

1. 기관 프로필과 정상 로그인 상태를 확인한다.
2. 전임자의 식별자·소속 이력·담당 기간을 설정하고 검색 범위를 미리 보여 준다.
3. 작성 문서의 전체 목록을 먼저 순회해 문서 ID·본문/붙임 정보를 확보한다. 검색 상한이 있으면 허용 범위에서 기간 구간을 나눠 탐색하고 중복 ID를 제거한다.
4. 본문·붙임을 별도 큐에 넣고 문서 메타데이터와 함께 로컬 저장소에 내려받는다.
5. 임시 파일을 확인한 뒤 해시·파일 크기·형식을 기록하고 확정한다. 파일명 충돌은 문서/붙임 ID로 해결한다.
6. 검색 결과 수·고유 문서 수·본문/붙임 성공 수·거부/실패/미지원 수를 대조한다.
7. 성공 파일을 기존 분석 파이프라인에 등록하고, 실패 항목은 재시도·재개 목록에 남긴다. 하나의 실패로 전체 분석을 막지 않는다.

수집 도중 세션이 만료되면 인증 필요 상태로 정지하고 사용자 로그인 후 이어서 진행한다. 문서·파일 ID와 체크포인트를 저장해 재시작 때 성공한 파일을 다시 받지 않는다. 서버 오류는 제한된 횟수로 재시도하고 속도·동시 작업 수는 기관 조건에 맞춘 설정값으로 둔다. 검색 기준 시각을 고정하고 가능한 경우 안정된 정렬을 사용한다. 수집 중 새 문서가 추가되어 목록이 바뀌면 차이를 보고하고 한 차례 목록 재대조한다.

#### 4.5.4 로컬 저장과 완전성

제안 저장 구조는 프로젝트의 `data/onnara/<수집ID>/` 아래에 `manifest.json`, 메타데이터, 본문/붙임 파일, 수집 결과를 분리하는 형태다. 원본 파일은 수집 저장소에서 읽기 전용 자료로 취급하고 앱의 보고서·결과 초안은 별도 `outputs/`로 쓴다. 임시 파일·세션 정보·키는 최종 자료 패키지에 포함하지 않는다.

manifest에는 시스템/기관 식별자, 연결부 버전, 검색 조건, 기준 시각, 문서 ID, 작성자 관계, 제공받은 문서 상태·번호·작성/등록/결재 시점, 본문/붙임 관계, 다운로드 시각·해시·크기·형식·성공 여부를 저장한다. 제공되지 않은 필드는 미상으로 남긴다.

완료 상태는 `범위 내 수집 완료 / 일부 누락 / 완전성 확인 불가`로 구분한다. 전체 검색 결과와 파일 목록을 얻은 경우 문서 수와 파일 수를 각각 대조한다. 다운로드는 성공했어도 파싱 실패일 수 있으므로 `수집 완료`와 `분석 완료`를 따로 표시한다. 파일 해시는 수집 후 무결성 검사 수단이며 공식 문서 진본성을 단독으로 증명하지 않는다.

#### 4.5.5 공식 자료를 지식으로 활용하는 방법

- 온나라에서 확인한 등록·결재 메타데이터와 원문을 묶어 출처를 표시한다. 내보내기 파일은 메타데이터 검증 범위에 따라 ‘온나라 내보내기 자료/출처 미확인’ 등으로 구분한다.
- 같은 내용이 개인 폴더에도 있으면 파일 해시로 중복 본문을 줄이되 두 출처 연결은 보존한다. 내용이 다른 초안·등록본은 버전 후보로 연결하고 임의 병합하지 않는다.
- 업무 규칙·금액·기한의 질문에서는 대상 시점과 업무가 맞는 등록·결재본을 중요한 근거로 사용한다. 결재 상태만으로 현재 효력이나 사실의 절대 정확성을 확정하지 않는다.
- 진행 현안·구두 협의 같은 정보는 로컬 메모가 더 최근일 수 있다. 공식 문서와 메모의 충돌은 역할·시점·근거를 비교해 보여 주고 둘 중 하나를 무조건 삭제하지 않는다.
- 답변에는 문서번호·제목·기준 시점·본문/붙임 위치를 표시하고 로컬 원문을 연다. 실제 문서 상세 주소가 제공될 때만 온나라 원문 열기를 추가한다.
- 온나라 문서를 몇 건 받았는지를 넘어, 개인 폴더에 없던 근거가 복원한 업무 절차와 실제 수행에 쓰였는지 검증한다.

#### 4.5.6 외부 의존성과 실행 증거

모의 온나라 연결부는 페이지 분할·검색 상한·동명이인·첨부·세션 만료·재시도를 합성 자료로 재현한다. 개발·대회 제출은 합성 코퍼스를 사용하고 실제 공문서·세션·인증 정보를 저장소나 영상에 넣지 않는다. 실제 기관 수집 연결은 해당 환경에서 별도 검증하며, 모의 서버 통과를 실제 온나라 연동 완료 증거로 쓰지 않는다.

10/9까지 기관 환경·검색/다운로드 표본 확인, 10/13까지 소수 문서 검색→본문/붙임 수집 실증을 목표로 한다. 환경 접근이 지연되면 모의 연결부·내보내기 가져오기·로컬 분석은 계속 구축하되, **직접 수집은 외부 환경 미확보로 미검증**이라고 기록한다. 킥 기능을 장기 P2로 옮기지 않고 별도의 실제 연동 완료 조건을 유지한다.

구현 시 `docs/온나라_연결프로필.md`에 확인한 기관 사양·지원 범위·연결 방법을, `docs/온나라_검증결과.md`에 모의/실환경 결과·수집 조건·건수·누락·버전을 남긴다. `tests/fixtures/onnara/`에는 합성 목록·본문·붙임·정답 manifest를 둔다. 이 경로들은 향후 산출물 제안이며 이번 계획서 개정에서 생성한 구현 파일이 아니다.

문서 작성일, 문서가 다루는 연도, 시행 시작·종료일, 사람의 확인일을 별도 값으로 관리한다. 시행일이나 폐기 여부가 없으면 생성 모델이 날짜를 채우지 않는다. 검토자 표시명은 로컬 이력 정보이며 인증된 본인 확인을 보장하지 않는다.

작성자 검색은 온나라 수집을 이용할 때 필요한 조건이며 전임자의 현재 참여나 계정 로그인을 요구하지 않는다. 폴더만으로 시작할 때는 해당 필드를 비워 둘 수 있다. 자료원은 `local`과 `onnara`를 구분하고, 공식 문서의 등록/결재 상태와 근거 신뢰성·사람 확인 상태는 각각 별도 필드로 유지한다. 새 테이블 후보는 `connector_profiles`, `collection_runs`, `source_records`, `source_assets`이며 기존 문서·근거·버전 데이터와 연결한다.

### 5.2 상태 변화와 재분석

- **근거 상태:** `문서 명시 / 추정 / 충돌 / 자료 없음`을 필드별로 저장한다. 모델의 자신감 점수를 사실 확정 기준으로 삼지 않는다.
- **적용 시점:** `현재 대상에 적용 확인 / 과거 사례 / 적용 여부 미상`을 별도로 둔다. 문서에 명시된 과거 기한을 현재 기한으로 바꾸지 않는다.
- **사람 확인 상태:** `확인 없음 / 전임자 확인 / 후임자 확인 / 재확인 필요`를 별도 기록한다. 확인 없음이어도 문서 근거 열람·수행 안내·복원본 저장을 이용할 수 있다.
- **수행 상태:** `미시작 → 진행 중 → 완료`와 `특정 단계 대기`를 관리한다. 체크리스트를 읽었다는 이유만으로 업무 완료 처리하지 않는다. 완료는 사용자의 명시 기록과 첨부 가능한 결과 근거를 보존한다.
- **버전 상태:** 자료 기반 복원본은 자동 저장하고 이후 저장 시 새 스냅샷을 만든다. 전임자 검토 인계본은 선택적으로 발행한다. 생성·발행·수신은 내용 전체 승인과 별개다.
- 원문 변경은 관련 항목의 근거와 적용 시점만 재평가한다. 사람의 수정·기존 확인·수행 기록을 지우지 않고 영향받은 단계에 재확인 필요를 표시한다.
- 온나라 재수집으로 같은 문서 ID의 내용·상태가 바뀌면 새 수집 버전과 변경 내용을 남긴다. 검색에서 사라졌다는 이유만으로 기존 근거나 후임자 교정을 삭제하지 않는다. 권한 변경 여부와 원문 부재를 구분해 표시한다.
- 금액·기한·승인 권한이 충돌하면 두 근거를 함께 보여 준다. 해당 판단의 확정은 유보하되, 근거 수집·자료 준비 등 진행 가능한 행동을 계속 안내한다.

전임자 부재를 ‘모든 내용이 확인될 때까지 대기’ 상태로 구현하지 않는다. 시스템이 자료로 설명할 수 있는 내용을 먼저 제공하고, 실제로 비어 있는 부분에만 정보 공백을 표시한다. 이 구분을 검색 응답·화면·보고서·패키지에서 일관되게 사용한다.

### 5.3 안전한 이동과 인계 패키지

기본 패키지는 업무 복원본 또는 인계본의 스냅샷, 근거 발췌, 수행 안내·기록, 상대 경로·해시 manifest, 사람이 읽을 보고서로 구성한다. 종류와 사람 확인 상태를 함께 보존한다. 검색 인덱스는 호환되는 경우 재사용하고, 모델·파서 버전이 바뀌면 다시 구축한다. API 키·절대 개인 경로·불필요한 진단 로그는 제외한다.

온나라 문서 ID·기관·수집 시점·본문/붙임 관계도 승계하며 원 시스템의 로그인 세션은 포함하지 않는다. 후임자의 사용 환경에서 열람·보관할 수 있는 자료만 전달 대상으로 삼는다. 출처를 보존하는 것과 다른 사용자의 열람 권한을 부여하는 것은 별개다.

원문은 기본적으로 포함하지 않고 후임자가 자료 루트를 재지정하도록 한다. 원문 복사 포함 기능은 명시적으로 선택한 파일만 별도 산출물에 복사하고 원본을 변경하지 않는 선택 기능으로 둔다. 패키지 자체에도 추출 본문이 들어 있으므로 일반 공개 파일로 취급하지 않는다.

재연결은 상대 경로+해시 일치부터 시도한다. 이름이 같아도 해시가 다르면 새 버전 후보로 처리하고, 동일 해시 후보가 여럿이면 사용자에게 선택을 받는다. 매칭 실패 시 인계본은 읽을 수 있게 유지하되 원본 열기 불가를 표시한다. 가져오기에서는 압축 경로 탈출, 예상 밖 파일 크기, 스키마 버전·해시 불일치를 검사한다.

3. 잠금 의존성과 실행 기준을 기록한다. 기존 분석의 잠금 환경 결과는 901 통과·5 건너뜀이다. 검사 수를 성능 목표로 삼지 않고 건너뛴 이유와 실제 AI 검사를 구분한다.
4. 합성 코퍼스를 하나로 정하고 파일 해시와 생성기 버전을 묶는다. 기존 모의자료와 정답의 불일치를 먼저 제거한다.
5. 전임자 부재 주 시연과 전임자 참여 보조 시연을 고정한다. P0·P1, 지원 형식·장비, 라이선스 검토 책임자, 기관 제출 담당자를 작업 목록에 기록한다.
6. 전임자의 답변·기존 인계서·검토자 등록 없이 시작하는 합성 업무 3개를 만든다. 평가용 정답은 별도 보관하고 제품 입력에는 넣지 않는다.
7. 기관의 온나라 버전·브라우저·인증·정상 다운로드 조건·작성자 식별 필드·검색 상한·본문 형식·붙임·메타데이터 표본을 확인한다. 공식 API/화면 수집 중 실제 가능한 방식을 정한다.
8. 빈 로컬 폴더에 공식 본문·붙임이 빠진 통합 시나리오를 추가한다. 합성 온나라 검색 결과·파일·정답을 준비하고 실제 환경 검증과 분리한다.

**완료 기준 G0:** 실행 기준선과 코퍼스가 고정되고 기관 프로필·연결 방식·실제 표본·시험 환경의 확보 여부를 기록한다. 환경이 없으면 미확보로 표시하며 온나라 지원 버전을 확정했다고 쓰지 않는다. 수요조사·GitLab·시험 환경 담당과 의존 작업이 정리되어 있다.

**자료 기반 복원의 중간 판정:** 사전 인계서와 전임자 답변이 없는 합성 업무 3개에서 첫 브리핑·절차·다음 행동이 자동으로 나온다. 정보가 충분한 사례는 결과 초안 작성까지, 공백 사례는 수행 가능한 준비 단계와 추가 확인 방법까지 진행한다. 전임자 확인을 요구하는 필수 입력이나 대기 화면이 없어야 한다. 개인 폴더에 없는 공식 자료를 온나라에서 수집해 새 근거로 사용한 사례를 포함한다.

이어서 복원본 승계와 전임자 참여 경로를 결합한다.

첫날·첫주 가이드는 기록상 기한·현안과 연결한다. 임박·지연은 적용 시점과 미완료 근거가 확보된 경우에만 표시하고, 과거 반복 업무는 참고 일정으로 둔다. 문서에 회신이 없다는 이유만으로 현재의 실제 지연을 단정하지 않는다.

생성 모델과 임베딩 모델 설정을 분리한다. 임베딩 모델·차원이 바뀌면 관련 인덱스를 다시 만들고 기존 벡터와 혼합하지 않는다. 모델명·서버 버전·digest·생성 옵션을 기록한다. 두 번째 모델은 G3 통과 뒤 실제 장비와 가용 시간을 확인해 검증한다.

로컬 연결을 기본값으로 유지한다. 내부 서버를 추가할 경우 명시적으로 설정된 주소만 허용하고 키를 로그·패키지에 넣지 않는다. 서버 연결 실패 시 외부 서비스로 자동 우회하지 않는다.

**HWPX 출력 분기:** 온나라 수집과 전임자 부재 경로·C06~C08이 우선이다. G3 통과 후 가용 시간이 확인된 경우에만 고정 서식 1종을 최대 1인일로 검증한다. 실제 한글 호환 프로그램에서 긴 문장·표·빈 항목을 확인하지 못하면 제출 범위에서 제외한다. 기본 산출물은 화면+Markdown이며 대체 DOCX 신규 개발은 추가하지 않는다.

**완료 기준 G3:** 온나라 수집본과 로컬 자료를 결합해 첫 업무를 수행한다. 전임자 참여가 없는 경로·있는 경로가 같은 데이터에서 동작하고 다른 PC에서 근거·본문/붙임·미완료 단계가 이어진다. 사람 수정·수행 기록·공식 출처가 재분석에도 유지된다.

### 단계 4 — 평가·패키징·제3자 실행

1. 고정 평가셋으로 근거 선택, 필드 추출, 답변, 유보를 따로 측정한다. 정답셋의 연도 기대값을 실제 판정에 반영한다.
2. 인터넷 없는 상태, 모델 미설치, 서버 중지, 잘못된 모델명, 취소, 재개, 자료 이동, DB 이행 실패를 확인한다.
3. PyInstaller 실행물을 Python 없는 별도 Windows PC에서 시작한다. 모델 설치·파일 위치·필요 디스크와 RAM은 측정 결과로 안내한다.
4. 최소 지원 사양을 정한다. 8GB에서 검증하지 못했으면 8GB 지원을 주장하지 않는다. AI 없이 열람·검토·기본 검색이 가능한 범위를 분명히 보여 준다.
5. 프로젝트·라이브러리·모델의 라이선스와 재배포 방식을 확인한다. 기존 보고서에서 지적한 PyMuPDF 등은 단순 고지로 해결됐다고 간주하지 않고 조건 이행·교체·제외 중 방침을 정한다.
6. 개발자가 아닌 사용자에게 설명 없이 합성 자료 폴더와 실행 안내만 제공해 첫 업무를 수행하게 한다. 평가자가 전임자 역할로 업무 내용이나 답을 알려 주지 않는다. 별도 전임자 참여 시나리오도 확인한다.
7. 실제 온나라 지원 환경에서 범위 설정→작성자 검색→본문/붙임 수집→결과 대조→업무 복원의 실행 증거를 확보한다. 실제 파일·인증 정보는 합성 대회 시연과 분리한다. 로그인 중단·수집 실패·파일 형식 오류를 구분하고 연결이 없어도 기존 자료 열람을 사용할 수 있는지 확인한다.

**완료 기준 G4:** 깨끗한 PC의 합성 환경에서 온나라 수집→두 자료원 결합→첫 업무 수행→기록·재시작이 재현되고 실제 기관 연결의 검증 범위도 기록된다. 실제 연결 증거가 없으면 온나라 직접 수집 P0 미완료로 표시한다. 기존 인계본이나 평가자의 업무 설명에 의존하면 통과로 인정하지 않는다. 원본 변경·이력 손실·허위 확정 문제는 남기지 않는다.

## 7. 검증 설계와 품질 목표

아래 수치는 초기 프로젝트 목표다. 전체 기관 업무에 대한 정확도 보장으로 해석하지 않는다. 테스트 문항 수가 작으므로 분자·분모와 실패 사례를 같이 공개한다.

### 7.1 평가 데이터

- 실제 대회 HWPX 2건: 표·문단·제출 일정·평가 배점의 추출 검사에 사용한다.
- 온나라 수집 평가셋: 합성 문서 30건 이상·붙임 50개 이상으로 작성자 ID·소속 이력·동명이인·페이지·기간 중복·상한·본문 형식·권한 거부·세션 만료·수집 중 변경을 구성한다. 고정된 문서/파일 ID의 정답 목록으로 완전성을 판정한다.
- 파서 표본: ODT/ODF 문단·표·반복 셀·병합과 실제 내보내기 형식 표본을 추가한다. 실제 공문서의 내용을 대회 코퍼스로 사용하지 않고 구조를 합성 자료로 재현한다.
- 합성 행정 자료: 연도별 업무, 개정 전후 지침, 예산 표, 연락 대상, 현안, 누락·상충 자료를 포함한다. 원본 해시·생성기 버전을 고정한다.
- 개발용 30문항과 별도 최종 평가용 60문항을 나눈다. 여유가 있으면 최종 평가를 100문항으로 확대한다. 최종셋은 프롬프트 조정에 반복 사용하지 않는다.
- 최종 60문항은 답변 가능 40, 근거 부족·범위 밖·충돌 때문에 유보해야 하는 20으로 구성한다. 답변 가능 문항에는 연도/업무 범위, 표의 금액·단위, 기한, 역할, 다음 행동을 포함한다.
- 정답에는 답의 핵심 필드, 허용 표현, 근거 파일·위치·버전, 질문 기준 시각, 유보 사유를 담는다. 파일명 적중만으로 통과시키지 않는다.
- 질문 평가와 별도로 아래 3개 업무 수행 시나리오를 고정한다. 제품에 투입하는 것은 원문 폴더이며 사전 작성 인계본·정답 카드·전임자 설명을 포함하지 않는다.

| 자료만 남은 시나리오 | 입력 | 기대하는 실제 수행 | 오판 방지 검사 |
|---|---|---|---|
| 정기 실적 보고 | 현재 대상 업무의 요청 공문·서식·과거 제출본·집계 자료 | 필요한 수치를 찾고 보고 초안을 작성해 결과 기록 | 과거 제출일과 현재 요청 기한을 혼동하지 않음 |
| 진행 중 계약·정산 | 진행 기록·금액 표·초안, 완료 여부 일부 누락 | 확인된 단계의 자료를 준비하고 미상 단계의 확인 방법 정리 | 후속 문서가 없다는 이유로 미완료·완료를 단정하지 않음 |
| 개정된 절차와 반복 업무 | 적용 시점이 다른 안내·서식·과거 처리 사례 | 현재 대상에 맞는 절차·서식을 찾아 준비 단계 수행 | 상충 조항을 숨기거나 새 문서라는 이유만으로 우선 확정하지 않음 |

같은 업무에 전임자 보충이 있는 비교 시나리오도 둔다. 참여 모드 전환으로 자동 복원 결과·후임자 수행 기록이 사라지지 않는지 확인한다. 원문을 일부 제거한 추가 실행에서는 빠진 사실을 생성하지 않고 공백과 수행 가능한 단계가 남는지 검사한다.

온나라의 가치를 보는 별도 통합 사례를 둔다. 로컬 폴더에는 예전 초안만 있고 합성 온나라에는 대상 시점의 등록본·붙임 예산표가 있는 상태에서, 수집 전에는 근거 부족/시점 충돌을 표시하고 수집 후에는 추가 근거로 올바른 절차·금액·서식을 제시해야 한다. 공식 자료에도 초안·반려본·과거 규정이 포함된 사례를 넣어 출처 이름만으로 답을 확정하는지 확인한다.

### 7.3 성능과 효과 측정

단계 0에서 기준 장비의 CPU/GPU/RAM, 모델·서버 버전, 문서 수·청크 수를 기록한다. 단계 1 후에 질문 지연 p50/p95, 최초 인덱싱 시간, 최대 메모리, 취소 응답 시간을 측정한다. 이전 관찰의 질문 약 60초는 통제된 벤치마크가 아니므로 그대로 제품 성능값으로 쓰지 않는다.

초기 목표는 기준 장비에서 질문 p95 90초 이하, 작업 취소 후 UI 반응 3초 이내로 두되 10/13 측정 후 지원 모델·장비·컨텍스트 예산을 확정한다. 정확도를 떨어뜨려 속도 기준만 맞추지 않는다. 달성이 어려우면 지원 사양과 예상 대기시간을 명시한다.

효과 실험의 중심은 **전임자 설명 없이 폴더·검색만 사용하는 경우와 눈치코치를 사용하는 경우의 후임자 부담 차이**다. 비슷한 난도의 서로 다른 업무로 순서를 바꿔 학습 효과를 줄인다. 개발자가 아닌 사용자 3명 이상을 목표로 하며 확보하지 못하면 실제 표본 수를 명시한다.

온나라 부분은 같은 검색 조건의 수동 검색·저장과 자동 수집을 비교해 작업자 조작 시간·클릭/수동 저장 횟수·누락·재개 시간을 측정한다. 분석 지연과 사람의 작업 시간을 분리하고 새 공식 근거로 해결된 정보 공백 수를 함께 기록한다.

| 목표 | 측정 지표 | 해석 |
|---|---|---|
| 파악 부담 경감 | 첫 유효 업무 계획을 세우는 시간, 직접 연 문서 수 | 줄어든 탐색량과 시간, 잘못 선택한 절차를 함께 평가 |
| 수행 부담 경감 | 첫 결과 초안까지의 시간, 수동 입력·수정 항목 수 | 준비와 작성까지 시스템이 실제로 덜어준 작업 측정 |
| 업무 안정성 | 필수 단계 누락, 잘못된 기한·서식 적용, 중단 후 재개 성공 | 시간 단축과 함께 오류가 늘지 않았는지 확인 |
| 다음 승계 가능성 | 저장된 수행 기록으로 다른 사용자가 이어가는 성공 여부 | 첫 후임자의 경험이 다시 사라지지 않는지 확인 |

내부 파일럿 목표는 자료가 충분한 과제의 첫 결과 초안 작성 시간 중앙값 20% 이상 감소와 필수 단계 누락 증가 0건으로 둔다. 정보 공백 과제는 준비 작업 완료율과 적절한 공백 식별을 평가하며, 알 수 없는 사실의 억지 확정으로 완료율을 높이지 않는다. 수치 미달은 개선 과제로 기록하고, 조직 전체의 안정성 보장이나 보편적 절감 효과를 실증한 것처럼 발표하지 않는다.

## 8. 우선순위·중단 기준·역할

### 8.1 일정이 밀릴 때의 절단 순서

1. 관계망 시각화·자동 인터뷰 다양화·고급 개체 통합을 제외한다. 최소 자동 업무 복원은 유지한다.
2. 고정 HWPX 출력과 미확보 내부 서버 연동을 제외한다.
3. 두 번째 모델의 범위를 핵심 기능 검증으로 제한하고 미검증 기능을 명시한다.
4. 첫 주 화면은 새 대시보드 대신 기존 가이드와 현안 목록을 통합한다.

온나라 작성자 검색·본문/붙임 수집·출처·누락 대조, 전임자 없이 시작하는 자동 복원·수행 안내, 원본 보호, 근거·수정·수행 이력, 미상 표시, 복원본·인계본 재연결, RAG 검증, 제출 재현성은 유지한다. 범위를 줄이면 지원 기관/버전·연결 방식·업무 유형을 줄인다. 온나라 기능을 단순 폴더 가져오기로 바꾸거나 모의 서버만 연결하고 실제 수집 완료로 표시하는 것은 허용하지 않는다. 환경 미확보는 직접 연동 미검증으로 명시한다. P0가 11/5까지 통과하지 못하면 결함·외부 의존성과 제출 가능성을 다시 판단한다.

한 사람이 여러 역할을 맡을 수 있지만 실제 자료·기관 절차의 확인은 개발자의 추정으로 대체하지 않는다. 담당자가 아직 지정되지 않았다는 사실이 이번 계획서 작성의 중단 사유는 아니다.

이 표는 제품을 만드는 과정의 역할이다. 실제 사용 과정에서 조직 구성원에게 확인 책임을 배분하거나 공동 결재를 요구하는 기능을 뜻하지 않는다. 운영상의 주 사용자는 업무를 이어받는 후임자이며 시스템이 그 사람의 자료 해석·수행 부담을 줄이는 데 집중한다.

## 9. 시연과 심사 대응

| 평가 축 | 보여 줄 변화 | 증빙 |
|---|---|---|
| 활용성 40 | 온나라 공식 기록과 로컬 자료를 모아 전임자 부재의 인계 부담 감소 | 누락 공식 자료 수집→첫 수행, 수집/수행 시간·누락 측정 |
| 완성도 30 | 실제 한글 표, 근거 확인, 원본 보호, 실패·재개·이동 처리 | 회귀·모델 평가, 실제 안내서 사례, 깨끗한 PC 실행 |
| 확산용이성 30 | 기존 Windows 기반의 재현 가능한 설치·모델 교체·권리 설명 | 실행물, 안내서, 모델 프로필, 구성요소·라이선스 목록 |

약 5분 영상은 다음 세 흐름으로 구성한다.

1. **온나라에서 놓친 공식 기록 찾기 — 약 1분 30초:** 전임자의 작성자·범위를 선택해 전체 목록과 본문/붙임 수집을 시작한다. 건수·누락·공식 출처와 로컬 폴더에 없던 등록본을 보여 준다. 합성 시연은 모의 온나라라고 표시한다.
2. **전임자 없이 첫 업무 수행 — 약 2분 30초:** 두 자료원을 함께 분석한 업무 카드에서 추가 공식 근거·절차·서식을 확인하고 결과 초안·수행 기록을 남긴다. 상충 기한과 이후 상태 미상을 구분해 진행 가능한 작업을 보여 준다.
3. **업무 이어가기와 선택적 검토 — 약 1분:** 복원본을 다시 열어 수집 출처와 수행 이력이 유지됨을 확인한다. 참여 가능한 전임자가 일부 항목을 보충해도 기존 결과가 이어짐을 보여 준다.

두 경로의 공통 메시지는 ‘업무를 이어받는 사람의 부담을 시스템이 덜어 업무가 끊기지 않게 한다’이다. 조직 안정성은 이 업무 연속성의 효과로 설명한다.

온나라 접속이 없는 심사 환경에서는 합성 연결부/수집 패키지로 같은 파이프라인을 재현한다. 실제 기관 연결은 별도 검증 기록의 대상 범위·방식·버전으로 설명한다. 실환경 검증을 하지 못하면 직접 연동 기능의 미검증 상태를 명시한다.

제출 폴더에는 신청서, 구동안내서, 영상, 소스/실행 안내, 실행물 또는 확보된 배포 경로, 합성 자료, 버전 manifest를 둔다. 분석용 캐시·개인 DB·비밀키·민감자료는 넣지 않는다.
