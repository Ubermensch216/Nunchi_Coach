# 공문 기준 업무분석 — 진행 보고 (2026-10-29)

기준 문서: [공문 기준 업무분석 계획서](공문기준_업무분석_계획서_2026-10-29.md) · 커밋하지 않았다(작업 트리에만 있다).

## 한 줄 요약

눈치코치가 **온나라 공문을 업무의 뼈대로 삼고 PC 파일을 근거와 함께 그 업무에 붙이도록** 바꿨다(P3·P4a). 합성 자료 시험은 통과했고, 실제 온나라 자료로는 아직 확인하지 못했다.

## 1. 정한 것

| 항목 | 결정 |
|---|---|
| 전임자 PC 파일 재배치 | **사본 인계 폴더**(원본은 그대로). "원본을 수정·이동·삭제하지 않는다"는 약속을 지킨다 |
| 진행 순서 | 합성 자료로 할 수 있는 P3(공문 업무 골격)·P4a(PC 파일 대응)부터. P1(온나라 조건 검색·전체 순회)은 문서등록대장 화면 표본(G1)이 와야 끝난다 |

## 2. 바뀐 동작

분석이 업무를 찾는 순서가 이렇게 된다.

1. **공문** — 단위과제가 같거나, 제목의 알맹이가 같거나(연도·차수·"제출 요청" 같은 동작어를 뗀 이름), 본문이 다른 공문의 문서번호를 인용하면(접수 → 회신) 한 업무로 묶는다. 공문 2건 이상, 또는 단위과제가 있는 것만 업무가 된다.
2. **PC 파일을 공문 업무에 붙인다** — 근거와 확신을 함께 남긴다.

   | 근거 | 확신 |
   |---|---|
   | 공문 본문·붙임과 내용(해시)이 같음 | 높음 |
   | 파일 이름에 공문 문서번호 | 높음 |
   | 파일 이름에 공문 제목 | 보통 |
   | 위에서 붙은 파일과 같은 폴더 | 낮음 |

   두 업무에 같은 무게로 걸리면 붙이지 않는다.
3. **남은 문서**는 지금까지처럼 폴더 구조 → 내용 비슷한 것끼리 묶기로 찾는다.

함께 고친 것: 온나라 수집본의 `files/<해시>` 폴더가 업무로 잡히던 길을 막았다. 의미 색인이 없어도 공문이 있으면 업무 찾기를 건너뛰지 않는다. 꾸러미에 단위과제(`task_card`, 선택)를 받을 자리를 만들었다.

바뀐 파일: `app/core/official.py`(신규), `app/ai/discover.py`, `app/jobs/pipeline.py`, `app/connectors/onnara/contract.py`·`saide_package.py`, `app/core/provenance.py`, `app/db/schema.sql`·`repo.py`, `tests/test_official_discovery.py`(신규), 계획서·이 보고서.

## 3. 시험 결과

- 새 시험 9건 통과(`tests/test_official_discovery.py`).
- 업무 찾기·온나라 관련 기존 시험 156건 통과.
- 전체 실행: **2,424 통과 · 3 실패 · 47 건너뜀**(28분). 실패 3건은 **이번 변경 전 코드에서도 똑같이 실패**한다. 화면·안내 문구를 기대하는 시험(`test_health`, `test_regulation_regressions`, `test_template_dialog`)이며, 10월 20일 업무안내 개편 뒤로 시험이 따라가지 않은 것으로 보인다. 고치지 않았다.

## 4. 확인하지 못한 것

- 실제 온나라 공문 제목·문서번호 표기에서 규칙이 맞는지. 동작어 목록은 합성 제목과 흔한 공문 표기로 정했다.
- 앱 화면에서 새 근거 문구가 어떻게 보이는지(앱을 띄워 보지 않았다).
- 공문 수천 건 규모에서 걸리는 시간.
