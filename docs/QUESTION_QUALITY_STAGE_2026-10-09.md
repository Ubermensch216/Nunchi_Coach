# 질문 품질 후속 구현 및 검증

> 이어진 수량 부재·단위 검증의 최신 구현과 평가 결과는 [수량 질문 후속 기록](QUANTITY_ANSWER_STAGE_2026-10-09.md)에 있다. 아래 2차 최종 세트는 해당 후속 작업의 개발용으로 전환했다. 원래 동결 파일과 당시 결과는 보존했다.

2026-10-09. 통합 구현 계획의 다음 순서 1번을 진행했다. 변경은 작업 트리에 있으며 커밋·푸시는 하지 않았다. 온나라 실연동 보류는 유지한다.

## 달라진 동작

같은 업무·기간의 문서에 `제출기한: 2026. 10. 21.`과 `제출기한: 2026. 10. 24.`가 함께 있으면 하나를 골라 확정하지 않는다. 양쪽 값·문서·인용 위치를 표시하고 원문을 대조할 수 있게 했다. [실제 Qt 화면](screenshots/25-source-conflict.png)은 개발용 합성 TXT 두 건의 상충 판정을 렌더링한 것이다.

`업무명`·`사업명`·`대상명`과 질문한 속성이 원문에 명시되어 있고 값이 일치하면 이름표의 값을 그대로 인용한다. 검색 순위·문서 수정 시각으로 승인본이나 최종본을 정하지 않는다. `현재`·`최종` 등의 효력을 묻거나 기간·업무가 여러 개면 보류한다.

- 사용자 선택 문서·업무·연도 범위를 먼저 적용한다. 노트북의 선택 해제·허용되지 않은 자료가 상충 검사에도 들어가지 않는다.
- 근접 중복 축약과 상위 검색 개수 제한 전에 허용 문서의 항목을 대조한다. 최대 500개 후보 문서를 넘으면 범위를 좁히도록 안내한다.
- 직접 인용 경로는 실제 원문 SHA-256과 분석 판본이 같아야 한다. `chunk_id`·위치·이름표 원문을 인용에 남긴다.
- 날짜는 연도까지 비교하고, 완전히 명시된 원화 단위는 동치로 비교한다. `80만원`과 `800000원`은 같지만 `80천원`은 다르다. 화면에는 원래 표기를 유지한다.
- 계획·실적 등 다른 속성의 값을 섞지 않는다. 미정·추후 결정, 질문과 맞지 않는 수량 단위도 확정하지 않는다.
- 문서 속 모델 지시문은 기존 필터로 제거한 뒤 대조한다. 충돌 답변을 답변 노트로 저장하거나 검토한 지식으로 승격하는 경로는 제공하지 않는다.

추가 실모델 점검에서 `수질 관련해서 뭘 제출했어?`의 `관련해서`를 문서 항목명으로 잘못 읽어 과잉 보류하는 문제가 드러났다. `관련해서`·`대해서`·`관해서`는 연결 표현으로 처리했다. `관련서식`·`제출기한` 같은 실제 항목명 검사와 숫자·근거 검증은 유지한다.

## 평가 설계와 결과

두 차수의 합성 평가를 각각 코드 변경 전에 SHA-256으로 동결했다. 개발과 최종 문항의 업무·원문·값은 분리했다. 문항과 정답을 같은 구현 작업에서 작성했으므로 독립 작성자 평가나 기관 실자료 검증은 아니다. 점수는 기대 문서·필수 표현·금지 값·보류 여부에 대한 자동 판정이다.

로컬 `gemma4:e2b`와 `bge-m3`로 씨앗 0·1·2를 사용했다. 직접 인용과 상충 판정은 생성 모델을 호출하지 않는다. 산문 답변·일부 부재 판단은 실제 생성 경로를 사용했다. 최종 실행 JSON에는 프로필·설치 모델 digest·검색 코드 해시·각 문항 답변·진단을 기록했다. 1차 기준 실행 파일에는 모델 프로필만 있으며 digest는 포함되지 않는다.

### 1차: 명시적 항목 대조

자료: [개발 12문항](../tests/fixtures/rag_quality_2026_10_09/dev.json), [최종 24문항](../tests/fixtures/rag_quality_2026_10_09/holdout.json), [동결 원장](../tests/fixtures/rag_quality_2026_10_09/frozen_manifest.json).

| 측정 | 변경 전 개발, 3회 합계 | 항목 대조 구현 후 개발, 3회 합계 |
|---|---:|---:|
| 답할 수 있는 질문 정답 | 21/21 | 21/21 |
| 필요한 보류 | 9/15 | 15/15 |
| 상충 자료를 확정한 답변 | 6/36 | 0/36 |
| 질문 응답 중앙값 | 6.336초 | 0.040초 |

최종 24문항은 3회 모두 24/24 통과했다. 답할 질문 16개·상충/부재 보류 질문 8개이며, 합계 72회에서 근거 없는 확정은 0건이다. **이 수치는 연결 표현 수정 전의 1차 코드에 대한 기록이다.** 그 뒤 별도의 실모델 시험에서 산문 과잉 보류를 발견해 다음 차수로 진행했다. 24문항을 새 최종 성능으로 재사용하지 않았다.

### 2차: 산문 질문의 연결 표현

자료: [실패 재현 개발 3문항](../tests/fixtures/rag_focus_2026_10_09/dev.json), [별도 최종 12문항](../tests/fixtures/rag_focus_2026_10_09/holdout.json), [동결 원장](../tests/fixtures/rag_focus_2026_10_09/frozen_manifest.json).

개발 3문항 × 3회에서 변경 전은 0/9, 수정 후는 9/9 통과했다. 원문에 제출 자료가 있었지만 연결 표현을 항목명으로 읽어 전부 `focus_missing`으로 보류하던 실패다. 최종 12문항은 별도 업무의 산문 질문·이유/수량 부재·상충·기간·효력 확인을 포함한다.

최종은 **매회 11/12, 합계 33/36 통과**했다. 답할 수 있는 질문은 21/21, 필요한 보류는 12/15, 질문 적합성은 21/24였다. 같은 부재 문항 `f-q06`이 3회 모두 실패했다. 원문은 정수기 수량을 조사했다고만 말하고 실제 대수는 제공하지 않는다. `몇 대야?`에 "2026년 휴게공간 설비 현황 조사에서 정수기 수량에 대한 기록이 있습니다"라는 답이 나갔다. 숫자를 지어낸 출력은 아니지만 수량을 답하거나 부재를 보류한 것도 아니다.

기존 평가기는 보류해야 할 질문을 답한 경우를 `unsupported_assertions`로 집계하므로 이 지표는 매회 1/12(8.3%)다. 이것을 숫자 환각 8.3%로 바꿔 표현하지 않는다. 출하 권고 기준의 근거 없는 확정 1% 미만은 충족하지 못했다. **이 최종 결과를 보고 코드나 채점 조건을 다시 고치지 않았다.** 후속 작업에서 이 문항을 수정에 사용한다면 2차 최종 세트는 개발용으로 전환하고, 수정 전에 별도의 새 최종 세트를 동결한다.

## 재현

평가 도구는 동결 파일 변경과 기준 코드 변경을 감지하고 기존 결과 JSON을 덮어쓰지 않는다. 기존 업무 프로젝트는 초기화·마이그레이션 전에 거절한다. 새 평가 폴더의 합성 원문·분석 결과·벡터만 만들며 일반 질문 이력은 저장하지 않는다. 평가 원문이 변경되어도 덮어쓰지 않는다.

```powershell
# 2차 개발: 기준 측정은 동결 당시 코드에서만 가능하다.
.\.venv\Scripts\python.exe -m app.tools.rag_quality --fixtures tests/fixtures/rag_focus_2026_10_09 --suite dev --phase candidate --folder .test_runs/focus-dev-new --repeat 3 --json .test_runs/focus-dev-new.json

# 예약 최종 문항은 결과를 보고 조정하는 개발 도구로 쓰지 않는다.
.\.venv\Scripts\python.exe -m app.tools.rag_quality --fixtures tests/fixtures/rag_focus_2026_10_09 --suite holdout --phase candidate --folder .test_runs/focus-final-new --repeat 3 --json .test_runs/focus-final-new.json

$env:NUNCHICOACH_LIVE_AI='1'
.\.venv\Scripts\python.exe -m pytest -q -rs
```

로컬 결과 경로:

- 1차 기준/후보/최종: `.test_runs/quality-baseline-20261009.json`, `quality-candidate-final-20261009.json`, `quality-holdout-final-20261009.json`.
- 2차 기준/후보/최종: `.test_runs/focus-baseline-20261009.json`, `focus-candidate-20261009.json`, `focus-holdout-final-20261009.json`.
- 로그와 프로젝트는 `.test_runs/`에만 보관한다. 다른 PC에는 이 문서의 수치·동결 자료·원장을 Git 작업으로 옮길 수 있으며 원시 실행 로그는 별도 보존이 필요하다.

## 한계와 다음 작업

명시적 업무명과 동일 이름표가 있는 좁은 경로를 개선했다. 일반 산문·표에서 주장 의미가 충돌하는지, 승인본/개정 효력을 판정하는지, 문서 관계로 최종본을 찾는지는 아직 구현하지 않았다. 일반적인 과잉 보류와 고급 멀티턴 문맥도 완료로 표시하지 않는다. 직접 인용 경로의 실제 해시 확인을 기존의 모든 생성 경로에 적용한 것은 아니다.

이번 작은 합성 평가 결과로 기존 큰 평가의 정답률 69.7%·근거 없는 확정 8.9%를 대체하거나 전체 RAG의 정확도 100%를 선언하지 않는다. 기관 실자료 홀드아웃·별도 작성자 평가·큰 잡음 자료에서의 반복 측정이 필요하다. 저장소 guard의 기존 금지 추적 파일 1,981개도 남아 있어 전체 출하 판정은 보류한다.

질문 품질의 다음 작업은 수량 질문에 수량 없는 산문을 답으로 내놓는 실패를 개선하는 것이다. 별도의 새 최종 세트를 코드 수정 전에 동결한다. 그다음 노트북의 명시적 후속 질문 연결·파일/메모 추가·복제·변경 판본 재검토 화면을 진행한다. 실제 온나라 연동은 사용자의 보류 요청을 유지한다.

## 검증 기록

- 항목 대조·연결 표현·평가 도구·기존 RAG/노트북 관련 시험 172개 통과.
- 실제 Qt 상충 대조 화면을 확인했다. 양쪽 원문 근거를 선택할 수 있고 노트북 범위 밖 탭은 숨긴다.
- 최종 산문 평가: 33/36 통과, 동일 수량 부재 문항 실패 3회. 평가 CLI 종료 코드는 1이며 합격으로 표시하지 않았다.
- Windows 최종 PyInstaller 빌드 통과. 실행물 아카이브에서 `app.search.facts` 포함을 확인했다. 번들 자체 점검에서 합성 문서 77건 파싱과 복원·수행 기록·복원본·묶음·가져오기·재연결·노트북 원문 연결이 통과했다. HWP 표본은 없다.
- 실제 모델을 포함한 최종 전체 회귀: `NUNCHICOACH_LIVE_AI=1 pytest -q -rs` **1,299개 통과·1개 건너뜀·경고 1개**, 503.42초. 실제 임베딩 형태·업무 간 구분·조각 생성→의미 색인→질문 연결 시험 3개도 통과했다. 기관 실문서 표본 시험만 환경 미제공으로 건너뛰었고 경고는 기존 Qt 이벤트 생성자의 폐기 예정 안내다. 로그: `.test_runs/quality-full-final-validation-20261009.txt`.
- 잠금 환경 일치와 `git diff --check` 통과. 최종 측정 뒤 동결 자료와 검색 코드 해시가 그대로인지 확인했다.
- 저장소 guard는 기존 `.analysis_audit` 추적 파일 1,981개 때문에 실패했다. 기능 회귀 통과를 전체 CI 합격 또는 질문 품질 게이트 통과로 해석하지 않는다.
