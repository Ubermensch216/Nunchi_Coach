# 지식그래프 P0·P1 기반 구현 기록

작성일: 2026-10-11. 기준 계획: [지식그래프·온톨로지 상세 구현 계획](지식그래프_온톨로지_상세구현계획_2026-10-11.md).

계획서가 권장하는 첫 구현 묶음 P0·P1을 대상으로 평가 도구와 저장 기반을 추가했다. 첫 출시 P0~P7 전체가 완료된 상태는 아니다. 그래프 관계는 아직 자동 투영하거나 답변에 사용하지 않으며, 사람 판정 화면도 공개하지 않는다.

## 구현한 내용

- `app/core/knowledge/ontology.json`: 11개 개체 유형, 13개 관계·속성, 분리된 상태 차원, 반개구간 시간 계약과 검색 초깃값의 정본.
- `ontology.py` / `validation.py`: NFC·공백 정규화, 숫자·기관 구분자 보존, 범위·기간·조건을 포함하는 논리 주장 키, domain/range·ISO 날짜·십진 문자열 금액 검사. 금액의 동등한 소수 자릿수 표기는 통합하고 큰 십진수도 반올림하지 않는다. 생성 모델·실행 ID는 논리 키에 넣지 않는다.
- `app/db/knowledge_schema.sql` / `knowledge.py`: 계획의 11개 kg 저장 테이블, 온톨로지 어휘용 보조 테이블 2개, 조회 인덱스, 개체 binding, 다의 별칭, 불변 주장·근거 스냅샷, 누적 사람 결정·상태 이벤트, 복수 근거·세대·작업 저장 계약.
- `migrations.py` / `repo.py`: v12 추가. SQLite backup API와 기존 단계별 트랜잭션을 사용한다. 신규 DB·v11 승격의 그래프 DDL이 같으며, 실패한 신규 초기화에는 완료 버전을 남기지 않는다. UUID는 한 번 발급한다. 최초 투영은 dirty 등록만 하고 실행하지 않는다.
- 변경 트리거: 문서·파싱·조각·업무 배정·항목·단계·수행 건·실행·산출물 변경을 동일 작업 키에 병합한다. 직접 SQL·별도 DB 연결에도 적용하며 원본 트랜잭션 실패 시 함께 되돌린다. 아직 큐 작업자·세대 게시·근거 수명 재평가는 없다.
- `app/tools/knowledge_standard.py`: 같은 JSON 정의에서 로컬 TTL/SHACL을 생성한다. 개발 fixture에서 Python·SQLite·SHACL이 공통 지원하는 구조 제약을 비교한다. 자유 조건의 진실성·원문 일치·관계 의미 지지를 SHACL 통과로 확정하지 않는다.
- PyInstaller에 SQL·온톨로지 리소스를 포함하고 RDFLib·pySHACL·OWL-RL·html5rdf는 제외한다. 배포 의존성 잠금은 유지한다. 개발용 별도 환경과 잠금, Windows CI 표준 검사 단계를 추가했다.

## P0 평가 자료와 기준선

`tests/fixtures/knowledge/corpus.json`과 `manifest.json`에 합성 질문 120개와 문서·해시·위치·인용·허용 관계·업무연도 정답을 동결했다. 단순 조회 30, 별칭 20, 문서 연결 25, 연도·변경 25, 자료 부족 20이다. 업무·문서 묶음 24개 중 8개는 튜닝 40문항, 나머지 16개는 시험 80문항이며 묶음이 겹치지 않는다. Git의 CRLF 변환은 LF 기준 해시로 처리한다.

생성 기록은 `build_fixture.py`에 남겼다. 일반 시험과 평가 실행은 fixture를 재생성하지 않는다. 합성 정답은 독립 검토 대기 상태이며 실제 비식별 기관 자료는 확보하지 않았다. 이 자료만으로 실제 기관 문서 정확도를 주장할 수 없다.

실행 도구는 `python -m app.tools.knowledge_eval --json 결과.json`이다. 기존 `search_chunk_ids`에 문서 선택 범위를 적용하고 Top 10을 고정한 **모델 OFF FTS 검색 A**를 잰다. 임베딩·파서·LLM 답변을 포함한 기존 RAG 전체 평가는 아니다. 미리 선택한 업무 묶음 안에서 검색하므로 업무 발견율이나 연도 해석 정확도를 재지 않는다.

개발 장비 Windows 11, Python 3.14.6, SQLite 3.50.4, Intel64 Family 6 Model 191, 논리 CPU 20개에서 다음 기준선을 기록했다. 원시 문항별 결과와 실패 사례는 [기준선 JSON](knowledge_baseline_2026-10-11.json)에 있다.

| 질문군 | 문항 | 모든 기대 근거를 찾은 문항 | 문항별 Recall@10 평균 |
|---|---:|---:|---:|
| 단순 조회 | 30 | 30 | 100% |
| 별칭·기관 구분 | 20 | 8 | 60% |
| 여러 문서 연결 | 25 | 5 | 50% |
| 연도·변경·충돌 참고 | 25 | 25 | 100% |
| 자료 부족·보류 | 20 | 평가 대상 아님 | 산출하지 않음 |

선택 밖 문서 반환은 0건이다. 자료 부족 질문에 참고 대목을 찾았다는 이유로 보류 성공이나 답변 정답으로 세지 않는다. 연도·변경 자료를 찾았다는 결과도 기한 확정의 안전성을 의미하지 않는다. 그래프 B/C 개선, 답변의 근거 없는 확정, 전체 RAG 성능, 1,000문서 지연·추가 RSS는 아직 측정하지 않았다. 계획서의 출하 게이트는 달성으로 표시하지 않는다.

## 검증

- 관련 Python·SQLite·평가·구버전 마이그레이션 시험: **58 통과**.
- 별도 개발 환경의 TTL/SHACL 시험: **27 통과**. 사용자 실행 환경에서는 개발 라이브러리가 없어 26개 표준 검증 문항을 명시적으로 건너뛰고, 별도 CI가 모두 실행한다.
- 저장 계약 fixture 26개: 미등록 관계, 잘못된 domain/range, 개체·리터럴 동시/누락, 동일 유형 대체, 실제 달력 날짜, 0년 거부, 숫자 JSON·지수·선행 0·잘못된 금액·단위 누락 검사.
- v11→v12와 새 DB의 테이블·인덱스·트리거 정의 비교, WAL 백업의 기존 정본 보존, 중간 실패 롤백·재시도, 이전 앱 거부, 신규 초기화 실패 후 재시도. 기간의 NULL 보존·반개구간·역전/빈 기간·실제 달력 날짜도 Python과 SQLite 각각 시험했다.
- 반복 binding·주장 중복 제거, 동명 별칭 병존, 사람 결정 누적·취소 기록, 철회 후 재등장 이벤트, 조각·문서 삭제 뒤 근거 스냅샷 보존, 관계/주장 대체 순환 거부, EXPLAIN 인덱스 사용, 직접 SQL·다중 연결 변경 병합·롤백.
- 기존 `requirements.lock`과 개발 `requirements-knowledge-dev.lock` 각각 설치 환경 일치. 생성한 표준 파일 일치 검사 통과.
- Windows 실행물: PyInstaller 빌드 통과. SQL·온톨로지 리소스 및 그래프 모듈 포함, 개발 전용 4개 모듈 제외를 확인했다. 번들 EXE의 `selftest`에서 합성 파일 77개 파싱 및 복원→수행 기록→복원본→묶음→가져오기→재연결을 통과했다. 실제 HWP 표본은 없으므로 별도 검증 대상이다.
- 전체 회귀: 결과 확인 후 아래에 기록한다.

저장소 guard는 기존에 추적 중인 `.analysis_audit/` 1,981개 파일로 실패했다. 이번 변경에서 해당 파일의 추적 상태나 내용은 수정하지 않았다. 이는 전체 CI의 기존 실패 요인이며 그래프 검증 통과로 상쇄되지 않는다.

## 개발 의존성

배포 실행 환경에는 설치하지 않는다. [RDFLib 공식 배포](https://pypi.org/project/rdflib/)와 [pySHACL 공식 배포](https://pypi.org/project/pyshacl/)를 확인하고 Python 3.14의 별도 환경에서 호환 버전을 고정했다. 개발 환경에 설치된 배포 메타데이터의 라이선스 표기는 다음과 같다. 패키지 자체를 수정하거나 소스를 복사하지 않았다.

| 개발 잠금 패키지 | 버전 | 설치 메타데이터의 라이선스 표기 |
|---|---|---|
| rdflib | 7.6.0 | BSD-3-Clause |
| pyshacl | 0.40.1 | Apache-2.0 |
| owlrl | 7.6.2 | W3C-20150513 |
| html5rdf | 1.2.1 | MIT |
| pyparsing | 3.3.3 | MIT |
| prettytable | 3.18.0 | BSD-3-Clause |
| wcwidth | 0.9.2 | MIT classifier |
| packaging | 26.3 | Apache-2.0 OR BSD-2-Clause |
| pytest | 9.1.1 | MIT |
| pluggy | 1.6.0 | MIT |
| iniconfig | 2.3.1 | MIT |
| Pygments | 2.21.0 | BSD-2-Clause |
| colorama | 0.4.6 | BSD classifier |

잠금 파일은 `app.tools.lockfile --out requirements-knowledge-dev.lock`으로 만들었고 해시 없는 버전 고정이다. 배포 잠금과 같은 정책으로, 오프라인 wheelhouse를 별도 준비할 때 실제 wheel 해시를 추가한다. 개발 패키지를 다른 곳에 배포하면 해당 패키지가 포함한 LICENSE·NOTICE도 함께 다룬다.

```powershell
.\.venv\Scripts\python.exe -m venv .venv-knowledge
.\.venv-knowledge\Scripts\python.exe -m pip install -r requirements-knowledge-dev.lock
.\.venv-knowledge\Scripts\python.exe -m app.tools.lockfile --check --out requirements-knowledge-dev.lock
.\.venv\Scripts\python.exe -m app.tools.knowledge_standard --check
.\.venv-knowledge\Scripts\python.exe -c "import sys; sys.path.append(r'D:\Dev\Nunchi_Coach\.venv\Lib\site-packages'); import pytest; raise SystemExit(pytest.main(['-q','tests/test_knowledge_standards.py']))"
```

마지막 명령은 저장소 공통 conftest가 사용하는 Qt·httpx를 기존 환경에서 읽고, 표준 검증 라이브러리는 별도 환경에서 읽는다. 다른 저장 위치에서는 경로를 해당 프로젝트의 `.venv/Lib/site-packages`로 바꾼다.

## 다음 구현 경계

P0의 독립 정답 검토와 실제 자료 확보가 남아 있다. P1은 저장·구조 검증 기반을 구현했으며 기존 출하 게이트는 그대로다. 다음 묶음은 P2의 **모델 없는 구조 투영**이다. 원문 검증·같은 해시 사본의 독립 근거 중복 방지·원본 정본 불변성을 먼저 시험하고, P3에서 큐 lease·중단 재개·세대 게시·지원 근거 수명·사람 판정 재적용을 완성한다.

P4의 공통 연도 범위·RAG 결합·노트북 revision 검사, P5 UI, P6 통합 평가, P7 v2 인계 왕복은 미구현이다. 특히 저장된 내부 판정 API만으로 사람 판정 기능을 정식 공개하지 않는다. P8 모델 관계 추출과 P9 확장 시험은 여전히 별도 후속 단계다.
