## 결정적인 검사 사례

- 페이지 크기를 줄여 여러 페이지를 끝까지 읽고 동명이인을 제외한다.
- 성공 파일을 재사용하고 변경된 파일은 원 소스의 해시·크기와 비교해 다시 받는다.
- 체크포인트에 적힌 해시만 바꿔도 소스 해시 검사를 우회하지 못한다.
- 인증 만료와 사용자 취소 후 성공한 파일을 유지하며 다음 실행에서 이어 받는다.
- 접근 거부 파일은 누락 원인을 남기고 전체 성공으로 표시하지 않는다.
- 같은 커서가 반복되거나 전체 수가 검증되지 않으면 완전성을 확인하지 못한 상태를 표시한다.
- 다른 작성자 범위로 기존 수집 폴더를 재사용하지 않는다.
- 해시·크기 불일치와 문서 대신 받은 로그인 HTML을 실패로 처리한다.
- 수집 저장소를 합성 원본 폴더 안에 만들지 않고 원본 바이트가 변하지 않는다.
- 수집한 ODT/붙임을 파싱한 뒤 금액을 문서 FTS에서 찾을 수 있다.

- 수집한 본문·붙임마다 원 문서 ID·문서번호·상태·역할이 프로젝트 문서에 연결된다.
- 상태가 바뀐 재수집은 변경 내용을 감사 기록에 남기고, 목록에서 빠진 문서의 출처를 지우지 않는다.
- 접근 거부로 받지 못한 붙임은 사유와 함께 남고 문서 행에 연결되지 않는다.
- 개인 폴더의 파일은 수집본과 해시가 같을 때만 같은 내용으로 표시된다.
- 답변 근거와 생성 문맥에 합성 여부가 드러난 공식 출처가 붙는다.

공식 문서의 상태·ID·관계는 수집 manifest와 프로젝트 DB(스키마 v4)에 보존하고 답변 인용까지 전달한다. 업무 복원 카드의 출처 표시, 내용이 다른 초안/등록본의 버전 연결, 실제 기관의 권한·검색 상한·본문 형식·브라우저 다운로드는 후속 검증 대상이다. 2차 실행(공식 출처 연결 포함)은 Python 3.11 환경에서 수행했으며 잠금 환경과 다르다.
