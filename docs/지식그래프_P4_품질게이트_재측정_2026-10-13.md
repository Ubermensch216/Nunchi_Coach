# 지식그래프 P4 품질 게이트 재측정 (2026-10-13)

[P5~P7 기록](지식그래프_P5_P7_구현기록_2026-10-12.md)이 남긴 "P4 품질 게이트 충족 방법" 두 가지를 구현하고 같은 동결 질문·규모 시험을 다시 실행했다. 기준 커밋은 `5e3d238`이다.

**먼저 결론.** 동결 합성 질문에서 게이트 항목은 모두 충족했다. 그래프 검색은 **여전히 기본 off**이며 설정 화면에 켜는 항목도 추가하지 않았다. 이유는 아래 "아직 모르는 것"에 있다 — 합성 자료의 어휘 검색 기준에서 재현율이 오른 것이지, 사용자가 받는 답이 나아졌다는 측정이 아니다.

## 원인 두 가지와 수정

### 1. 별칭 후보 조회 (규모)

`search/graph.py`의 별칭 시드 쿼리는 모든 별칭을 `instr(질문, 라벨)`로 훑으면서 현재 주장·근거·세대·문서와 조인했다. 별칭 색인(`kg_aliases(normalized_label, scope_key)`)을 쓰지 못해 문서 수에 비례해 느려졌고, 변경 전에는 10,000문서 프로젝트 전체 범위에서 150ms 예산을 넘겨 300건이 모두 기존 검색으로 물러났다.

- 질문의 부분 문자열(2~64자)을 `json_each`로 넘겨 별칭을 **동등 조회**하고(`question_grams`, `alias_seeds`), 일치한 별칭에서 주장 색인(`subject_id`/`object_id`)으로 이어 간다. 라벨이 질문의 부분 문자열이라는 `instr`의 의미는 같다. 64자를 넘는 라벨은 이 방식으로 찾지 못한다(질문이 긴 파일명·문장을 통째로 인용하는 경우뿐).
- 시드 개체에 닿는 주장의 변 조회도 같은 문제였다(`documents` 전체를 먼저 훑음). 시드 개체의 주장을 먼저 모으는 `MATERIALIZED` CTE로 순서를 고정했다.
- SQLite 플래너는 두 가지를 `UNION`으로 합치면 순서를 바꿔 437ms가 되어, 주체/객체 쪽을 따로 실행해 합친다. 각 SQL에 이유를 주석으로 남겼다.
- 의미 동등성은 시험으로 고정했다 — 옛 `instr` 방식을 시험 안에 기준 구현으로 두고 질문 9종 × 범위 4종에서 같은 시드를 내는지 비교한다(`tests/test_knowledge_search.py`).

### 2. 서술문에서 항목을 읽지 못함 (재현율)

동결 문서는 "제출기한은 2026-11-10입니다."처럼 문장으로 적혀 있는데 `reconstruction.read_section`은 `제출기한: …` 이름표 줄만 읽었다. 평가 그래프에는 문서 배정 관계 51개뿐이고 항목이 0개라 모든 질문에 시드가 없었다.

`_read_statements`를 추가했다(이름표 줄이 아닐 때만 동작하므로 기존 줄은 그대로 읽는다).

- `이름표은/는 값입니다·이다` (기존 이름표 목록 그대로, 기존 `_build`·`_verified`로 값이 인용문 안에 있는지 검증)
- `…과·팀·부·처·국·실·청… 에 제출·보고·회신·송부합니다` → 제출처
- `…서식·양식·신청서를 사용·이용·작성합니다` → 서식
- 문장 경계를 넘지 않는다(한글 뒤 마침표는 문장 끝, `2024. 6. 14.`의 마침표는 값). 날짜 없는 기한·숫자 없는 금액·기관이 아닌 제출 상대는 항목이 되지 않는다. 같은 줄의 기존 일정 규칙과 같은 날짜는 두 번 세지 않는다.

이 규칙은 **그래프뿐 아니라 업무 항목 전체**(업무 홈·매뉴얼·노트북 정리본)에 영향을 준다. 이름표 없이 문장으로만 적힌 공문에서 항목이 더 생긴다는 뜻이며, 실제 기관 문서에서의 오탐률은 측정하지 못했다.

## 측정 결과 (2026-10-13, Windows 11 · 12 논리 CPU · Python 3.14.7 · SQLite 3.50.4)

### 동결 합성 120문항 (모델 OFF FTS)

| 범주 | 채점 | A 기존 FTS | B 그래프(on), tuning | B 그래프(on), holdout |
|---|---|---|---|---|
| 단순 | 30 | 1.00 | 1.00 | 1.00 |
| 별칭 | 20 | 0.60 | 0.80 | 0.80 |
| 연결 | 25 | 0.50 | **0.80** | **0.80** |
| 시점 | 25 | 1.00 | 1.00 | 1.00 |

- 범위 밖 노출 0건(세 모드). 게시 주장 147개(이전 51개). shadow는 off와 검색 결과가 같다(변경 0건). on은 120문항 중 33개 질문의 결과를 바꿨고, 13개 질문은 시드가 없어 기존 검색으로 물러났다. 그래프 p95 1.6ms.
- 추출 규칙은 tuning 질문의 문서(그룹 7·11·16)를 보고 만들었다. holdout은 규칙을 정한 뒤 처음 실행했고 이후 조정하지 않았다.
- 여전히 놓치는 3문항(tuning): 어휘 검색이 아무것도 못 찾는 질문(`시설보수을 제출할 서식과 부서는?`, `복지지원의 기관은?`)이다. 업무명으로 시드를 넓히면 풀리지만 근거 없는 질문(abstain)에도 후보가 붙을 수 있어 넓히지 않았다.

### 일반화 확인: 문체가 다른 묶음 (`tests/fixtures/knowledge_paraphrase/`, 144문항)

동결 문서는 모두 같은 문장 틀이라 위 수치가 그 틀에서만 나왔을 수 있다. 규칙을 만든 뒤 다른 틀로 쓴 묶음을 문체별로 쟀다. 이 묶음을 보고 규칙을 고치지 않았다. 연결 문항은 처음에 둘째 문서의 낱말을 문항에 넣어 어휘 검색만으로 풀렸기에(off 재현율 1.0, 여유 없음) off 기준선의 여유만 보고 문항을 한 번 고쳤다 — 그래프 결과를 보고 조정한 것이 아니다.

| 문체 | 연결 A → B | 별칭 A → B |
|---|---|---|
| 1 이름표 줄 | 0.50 → 1.00 | 0.50 → 1.00 |
| 2 다른 이름표의 서술문 | 0.50 → 1.00 | 0.50 → 1.00 |
| 3 동사형 문장 | 0.50 → 1.00 | 0.50 → 1.00 |
| 4 자유 서술 | 0.50 → 0.50 | 0.50 → 0.50 |

단순 조회는 전부 1.00 → 1.00, 범위 밖 노출 0건. **문체 4(자유 서술: "… 쪽으로 보내면 된다")는 규칙이 읽지 못하며 개선이 없다.** 실제 공문에서 이 문체의 비중은 측정하지 못했다.

## 아직 모르는 것 (그래서 기본 off 유지)

1. **재현율만 쟀다.** 그래프는 질문에 시드가 생기면 같은 업무의 다른 문서 인용을 최대 5개 더한다(가중 0.2의 별도 RRF). 합성 자료에서 이것이 재현율을 올렸지만 **정밀도(문맥에 섞이는 무관한 인용)와 LLM 답변의 정확도는 측정하지 않았다.** 근거 없는 질문에 후보가 더 붙어 답변 거절 판단을 흐리는지도 측정하지 않았다(abstain 범주는 재현율이 정의되지 않는다).
2. 연결의 실체는 **"같은 업무에 묶인 다른 문서의 검증된 인용"**이다. 업무 개체가 별 모양 중심이라 개체 간 의미 관계를 따라가는 것이 아니다. 이것이 사용자가 원한 "연결"인지는 판단이 필요하다.
3. 합성 자료다. 추출 규칙의 실제 공문 오탐률, 문체 분포, 벡터 RAG와의 A/B, P8(모델 관계 후보)·P9는 측정하지 않았다.
4. 별칭 문장("A는 'B'로도 부릅니다")은 별칭으로 만들지 않는다. 위 별칭 개선은 같은 문서의 `X의 담당은 …입니다` 항목이 시드가 되어 생긴 것이며, 질문에 별칭만 있고 어휘 검색이 못 찾으면(`복지지원의 기관은?`) 여전히 놓친다. 별칭 문장을 시드로 쓰려면 별칭 근거 규칙(현재 현행 주장의 근거와 같은 근거만 인정)을 바꾸어야 해서 이번에는 손대지 않았다.
