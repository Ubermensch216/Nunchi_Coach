# 규제개혁 비교연구 P2 화면 정리·변경 추적·지속 평가 구현 기록

작성일 2026-10-14 · 근거 상세개선계획서 2장 P2, 3장, 7장, 8장 · 앞 단계 [P1-4 구현 기록](규제개혁_비교연구_P1-4_근거검색_구현기록_2026-10-14.md)

계획서의 P2는 "적은 핵심 정보로 수행 가능, 새 문서 영향 추적"이다. 네 가지를 했다.

## 1. 바꾼 것

| 항목 | 조치 | 위치 |
|---|---|---|
| 긴 구획 접기 (R05) | 업무 매뉴얼의 한 구획에 항목이 12개를 넘으면 먼저 볼 10개만 펴고 나머지는 접는다. 지우지 않는다 — 화면에 '나머지 N건 펼치기'. 순서: 사람이 확인한 것 → 종류(서식·준비 자료·규정·유의·평가 기준·기한·제출처…, 담당 연락처와 다른 업무와의 관계는 뒤) → 지금도 적용될 수 있는 것 → 문서에 적힌 것 | `core/task_manual.py`(`Section.more`, `_ranked`), `ui/views/work_workspace.py` |
| 새 자료의 영향 | 업무 복원이 값을 맞추기 전과 후를 견주어 `restore_changes`에 남긴다(새로 생김·바뀜·사라짐, 업무마다 최근 5회). 처음 분석은 남기지 않고, 마지막 기록 요약·업무 사이 관계·사람 메모는 세지 않는다. 매뉴얼 '근거·빠진 정보'에 "지난 분석 이후 바뀐 것: 바뀜 1 · 새로 생김 1"과 내용, 기한·제출처·절차·목적이 바뀌거나 사라지면 다음 행동 "[바뀐 자료] … 2026-11-04 → 2026-11-11 … 새로 들어온 문서를 열어 확인" | `core/changes.py`(신규), `db/change_schema.sql`(신규), `reconstruction.restore`, `continuity.next_actions` |

| 품질 관문 (8장, 지속 평가) | `python -m app.tools.quality_gate --db <사본> [--truth 기준.json] [--restore --basis 날짜] [--json]` — 비교연구의 오류 꼴을 정답 없이 재는 불변 조건 8개(G1 지난 회차 절차의 진행 안내, G2 다른 기관 단계의 행동 안내, G3 서식 빈칸 값, G4 참고자료만 근거인 업무 값, G5 건별 목록 칸의 절차·준비물, G6 근거 없는 자동 항목, G7 초안 평가에 확정본 확인 없음, G8 조사 실패인데 '준비됨')와 업무별 기대 JSON(있어야/없어야 할 말, 첫 행동에 없어야 할 말). 하나라도 실패하면 종료 코드 1 | `app/tools/quality_gate.py`(신규) |

## 2. 실제 스냅샷 사본 측정

외장 드라이브(E:)가 분리돼 이번에는 원본 스냅샷을 다시 열지 못했다. P1-4 확인 때 만든 사본(원래 저장 결과 그대로, 건 목록 기록 포함)으로 쟀다. 기준 JSON 7개 업무(원문으로 정한 R01·R02·R03·R04·R07·T25·C28 기대)는 저장소 밖 `.analysis_audit/regulation_quality_truth.json`(커밋 제외)에 두었다.

| | 저장된 결과(개선 전 분석) | 현재 코드로 다시 복원 |
|---|---|---|
| G3 서식 빈칸 값 | **실패 8** (`시·도/시·군·구 0000과`, `(☎000-000-0000)`, `044-000-0000` …) | 통과 |
| G4 참고자료만 근거 | **실패 4** (추진계획·신문고의 목적·제출처) | 통과 |
| G5 건별 목록 칸 | **실패 2** (과제 제출의 절차·제출서류) | 통과 |
| G1·G2·G6·G7·G8 | 통과 | 통과 |
| 기준 7개 업무 | **7개 모두 실패** | 7개 모두 통과 |

G1·G2·G8은 저장된 결과에서도 통과한다. 관문은 사용자가 지금 보는 화면을 재는데, P0에서 넣은 실행 조건(지난 회차 절차의 확인 안내, 준비 상태 문구)이 저장된 단계를 보일 때도 적용되기 때문이다.

접기: T01(전국 검토결과)의 준비물 구획이 10줄 + 접힌 498줄, T07은 10 + 24, T06은 10 + 15.

## 3. 시험
