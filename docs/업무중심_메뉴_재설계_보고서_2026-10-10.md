# 눈치코치 업무 중심 메뉴 재설계 보고서

> **후속 사용자 결정 반영:** 별도 일정·자료 메뉴를 두지 않고 업무 홈에 카드와 연간 일정 대시보드를 배치하며, 업무별 일정·자료·매뉴얼과 노트북 소스 연결을 구성한다. 현재 적용할 계획은 [업무 홈·업무별 매뉴얼 중심 개편계획서](업무홈_업무별매뉴얼_중심_개편계획서_2026-10-10.md)다. 아래의 주 대메뉴 3개 권고는 이전 검토 이력으로 보존한다.

작성일: 2026-10-10 · 검토 기준: `dee8898` 작업 트리 및 사용자 피드백

제품의 최우선 상황: **업무를 전혀 모르는 후임자가 전임자 없이 첫날 눈치코치를 실행한다.** 목적은 맡을 업무의 전체 그림을 이해하고, 무엇부터 해야 하는지 판단하여 첫 행동을 시작하게 하는 것이다.

이 보고서는 [기존 최종 통합 계획](UIUX_최종통합_개선계획서_2026-10-10.md)의 메뉴·첫 화면·사용자 흐름 권고를 대체한다. 실행 수명, 근거·승인, 업무 맥락, 산출물 연결의 기술 원칙은 이어받는다. 이번 작업은 설계 보고이며 제품 코드 변경이나 사용자 시험은 수행하지 않았다.

## 1. 결론: 업무를 이해하는 순서가 정보구조의 기준이다

**주 대메뉴는 `업무 · 일정 · 자료`로 구성하고, 노트북은 상시 접근 가능한 보조 도구로 둔다. 첫 화면은 업무다.**

```text
[인수인계 프로젝트]    업무    일정    자료       [노트북] [분석 상태] [설정]
                       ↑                          ↑
                 첫 화면·가장 높은 비중      보조 도구, 항상 접근 가능

업무
 ├─ 전체 업무 / 챙길 일
 └─ 업무 하나 선택
     ├─ 업무 안내       무슨 일이고, 왜 하며, 무엇을 만들어야 하나
     ├─ 진행하기        이번 건은 어디까지 왔고, 다음은 무엇인가
     ├─ 관련 자료       무엇을 읽고 어떤 서식을 참고하나
     └─ 지난 기록       이전에는 어떻게 했고 무엇을 남겼나

일정                  전 업무의 시기·확정 기한·과거 반복 패턴
자료                  전 자료 검색·판본 확인·만든 문서 찾기
노트북                자유 조사·여러 업무 비교·자료 정리·초안 작성
```

주 대메뉴 세 개와 보조 진입 하나라는 정보 위계를 정한다. 노트북은 설정이나 숨은 더보기 안에 넣지 않는다. 자료 폴더 없이도 노트북을 시작하거나 재개할 수 있는 기존 경로를 유지한다. 현재 단축키의 업무·일정·자료·노트북 대응을 활용할 수 있다.

업무 화면 안의 ‘챙길 일’은 전체 업무를 대상으로 기한·승인·실패·진행을 모은다. 개별 업무를 고르기 전에도 접근할 수 있다. 이를 위해 ‘오늘’을 별도 대메뉴로 승격할 필요는 없다.

## 2. 앞선 판단을 바꾸는 이유

앞선 통합안은 이미 업무를 아는 담당자의 일상 관리와 실행 상태에 더 큰 비중을 두었다. 사용자가 지정한 핵심 상황에서는 **업무를 이해하는 일이 실행을 관리하는 일보다 앞선다.**

‘승인 대기 2건’, ‘새 제안 5건’은 업무를 아는 사람에게 의미가 있지만, 첫날의 후임자는 무엇에 관한 승인과 제안인지부터 설명을 들어야 한다. 오늘 중심 화면에 시작 안내를 덧붙이는 방식으로는 이 우선순위가 뒤집힌 채 남을 수 있다.

| 기존 통합안 | 이번 결정 | 이유 |
|---|---|---|
| 오늘을 맨 앞에 두고 일반 프로젝트는 항상 오늘로 진입 | **업무가 첫 화면**, 기본은 전체 업무 | 어떤 일을 맡았는지 먼저 이해해야 다음 행동의 의미를 알 수 있다 |
| 일정은 업무의 내부 전환 | **일정을 주 대메뉴로 유지** | 전체 업무의 연간·월간 흐름도 업무 파악에 필요한 독립 질문이다 |
| 업무·자료·노트북을 오늘과 동등한 대메뉴로 배치 | **업무 중심, 일정·자료 지원, 노트북 보조** | 첫 사용자가 먼저 도구를 선택할 필요를 줄인다 |
| 지금 할 일·준비 작업 중심의 업무 상세 | **업무 안내를 먼저**, 진행·자료·과거로 연결 | 목적과 결과물을 이해한 뒤 행동하게 한다 |
| 인수인계 확인률을 진행 판단에 사용 | **자료 확인과 사용자 이해·수행을 구분** | 내용을 열어 본 것, 이해한 것, 사실을 확인한 것은 다르다 |

이번 구조는 메뉴 수를 줄이기 위한 결정이 아니다. 사용자가 먼저 볼 정보, 업무 하나를 이해하는 단위, 실제 행동으로 이어지는 경로를 정한 결과다. 일정·자료·노트북을 전부 업무 하위로 숨기면 연간 계획·원문 탐색·자유 조사에 불필요한 제약이 생기므로 독립 접근은 보존한다.

## 3. 첫 화면: ‘자료에서 파악한 업무’를 한눈에 설명한다

첫 화면의 주제는 **‘어떤 업무가 있고, 각 업무에서 무엇을 해야 하며, 무엇부터 살펴보면 되는가’**다. 카드 수와 파일 수를 알려 주는 데서 끝내지 않는다.

화면의 읽는 순서는 다음과 같다.

1. **전체 그림:** 분석한 자료에서 파악한 업무와 범위. AI가 발견한 항목을 확정된 담당 업무처럼 단정하지 않는다.
2. **업무별 설명:** 목적, 주요 결과물, 시기, 자료에서 확인한 현재 상태를 짧게 보여 준다.
3. **먼저 살펴볼 업무:** 하나를 추천하고 그 이유와 첫 행동을 알려 준다. 나머지 업무에도 바로 들어갈 수 있다.
4. **근거와 다음 길:** 대표 자료, 업무 안내, 전체 일정, 추가 자료 연결로 이어진다.

다음은 실제 분석 결과가 아닌 **화면 구성 예시**다.

```text
업무 한눈에
연결한 자료에서 다음 업무들을 파악했습니다.
담당 범위가 아직 확인되지 않은 항목은 ‘업무 후보’로 표시합니다.

업무                 어떤 일인가                         주로 남기는 결과
행정사무감사         요구자료를 부서별로 받아 검토·제출   제출자료·취합표
분기 실적 보고       분기 실적을 모아 보고               실적 보고서
보조금 정산          집행 내역과 증빙을 대조·정리        정산서·증빙 묶음

먼저 살펴볼 업무: 행정사무감사
선정 이유: 최근 요구 공문과 제출자료가 있어 업무 흐름을 확인할 수 있습니다.
첫 행동: 지난 제출본을 보며 어떤 결과물을 만드는지 살펴보세요.
[업무 안내 보기]

[전체 일정 보기]       [챙길 일 보기]       [자료를 더 연결하기]
```

표·카드 중 구체적인 표현 방식은 시안에서 검증한다. 업무가 많으면 근거 있는 범주와 펼치기를 사용하고 전체 목록에 접근 가능하게 한다. ‘업무 지도’는 이런 전체 구조를 뜻하며 복잡한 관계 그래프를 반드시 그린다는 뜻이 아니다.

### 추천 순서와 불확실성

- 올해의 확인된 임박·초과 기한이나 실제 미완료 인계 건이 있으면 먼저 드러낸다. 현재 상태의 근거도 같이 보여 준다.
- 그런 근거가 없으면 대표 원문과 결과물이 있어 이해하기 좋은 업무부터 추천한다. ‘급한 업무’ 대신 ‘먼저 이해하기 좋은 업무’라고 이유를 구분한다.
- 문서가 많다는 이유만으로 중요 업무로 정하지 않는다. 과거 반복만으로 올해 마감을 만들지 않는다.
- 오래된 이름·전화번호·부서 표기는 자료 작성 시점과 함께 제공하고 현재 담당자로 단정하지 않는다.
- 자료가 부족하면 ‘업무가 없습니다’가 아니라 ‘아직 파악할 근거가 부족합니다’와 필요한 자료 유형을 안내한다.

분석 진행 중에는 먼저 파악된 업무를 제공하되 부분 결과임을 알린다. 분석한 범위 밖의 업무까지 빠짐없이 찾아냈다는 표현은 쓰지 않는다. 새로 들어온 결과 때문에 읽던 카드나 선택 업무가 계속 이동하지 않도록 한다.

## 4. 업무 하나를 열면 제공할 정보

기본 탭 **‘업무 안내’**에서 핵심 설명과 첫 행동을 이어서 읽을 수 있어야 한다. 목적·시기·결과물을 알아내기 위해 여러 탭을 오가게 하지 않는다.

| 순서 | 설명할 내용 | 후임자가 얻는 답 |
|---|---|---|
| 1 | 쉬운 업무 설명과 목적 | 무슨 일이고 왜 하는가 |
| 2 | 주요 결과물과 실제 예시 | 결국 무엇을 만들어 어디에 전달하는가 |
| 3 | 시작 계기·시기·기한 | 어떤 일이 생기면 시작하며 언제 하는가 |
| 4 | 전체 처리 흐름 | 무엇을 준비하고 어떤 순서로 진행하는가 |
| 5 | 자료에서 확인한 현재 위치 | 마지막 기록은 어디까지며, 이후는 무엇을 모르는가 |
| 6 | 첫 행동과 준비물 | 지금 내가 바로 할 수 있는 일은 무엇인가 |
| 7 | 중요한 공백과 확인 방법 | 어떤 정보가 없으며 어디서 무엇을 확인해야 하는가 |

‘처리 흐름’은 공식 자료에 적힌 절차, 과거 문서에서 복원한 사례, AI의 제안 단계를 구별한다. 일반적인 업무 설명이나 빈칸을 채운 추론을 실제 기관의 절차처럼 표시하지 않는다. 현재 상태도 ‘최근 문서 이후 기록 없음’을 ‘업무 미처리’로 단정하지 않는다.

확인할 정보는 이유와 다음 행동으로 표현한다. 예를 들어 ‘기한 미확인’에서 끝내지 않고 ‘현재 선택 자료에는 올해 요구 공문이 없습니다. 올해 공문을 연결하면 제출 기한을 확인할 수 있습니다’라고 안내한다. 확인 경로를 자료에서 찾지 못했다면 특정 담당자나 조직을 만들어 내지 않는다.

‘업무 안내’의 첫 행동에서 관련 탭·자료·실행으로 직접 이어진다. 같은 화면에 모든 원문·단계·상태를 길게 펼치기보다는 요약과 첫 행동을 먼저 제시하고 세부 내용을 확장한다.

### 나머지 상세 탭의 책임

- **진행하기:** 선택한 연도·수행 건의 단계, 준비 작업, 승인, 체크리스트, 생성 결과. 첫 업무 이해와 실제 수행을 연결한다.
- **관련 자료:** 먼저 읽을 자료와 읽는 이유, 서식, 원문 전체. 읽기 순서를 주되 모든 파일을 읽어야 시작할 수 있다는 인상을 주지 않는다.
- **지난 기록:** 이전 연도의 사례·결과물·수행 기록·변경점. 현재 수행과 과거 사례를 섞지 않는다.

산출물은 수행 건에 연결된 같은 객체를 여러 화면에서 조회한다. 노트북·업무·자료에 각각 복사본을 만들어 별도로 관리하지 않는다.

## 5. ‘확인시키기’보다 ‘이해시키기’가 먼저다

현재 `app/core/guide.py`의 첫 항목은 ‘이름이 맞는지 보고 확인 표시를 합니다’이고, 안내 단계 진행은 확인 상태를 사용한다. 이 구조는 정답을 아는 사람의 검수에는 적합하지만, 아무것도 모르는 후임자의 학습 단계를 대신하기 어렵다.

기존 사실 확인·검토 기록은 보존하면서 사용자 안내 상태를 별도로 둔다.

| 구분 | 의미 | 설계 원칙 |
|---|---|---|
| 안내 열람·다시 보기 | 업무 설명을 열어 보았거나 안내를 이어 보는 상태 | 이해·정확성의 증거로 취급하지 않음 |
| 업무를 진행하기로 선택 | 사용자가 그 업무의 수행 화면으로 들어가려는 의사 | 자료의 모든 추정을 확정하는 동작과 분리 |
| 사실 확인·수정 | 사용자가 근거를 검토해 특정 값을 확인·교정 | 기존 검토자·근거·판본 기록 유지 |
| 업무 수행 완료 | 해당 수행 건의 처리 결과 | 문서를 읽거나 초안을 내보낸 상태와 구분 |

첫날에는 ‘이 업무가 맞습니까?’보다 **‘이 업무는 이런 일입니다. 먼저 이 결과물을 보면 이해하기 쉽습니다’**가 앞선다. 확인하지 않아도 안내·원문·준비 작업을 사용할 수 있어야 한다.

‘이해도 80%’처럼 클릭 수로 이해도를 계산하지 않는다. 인수인계 확인률이 필요하면 설명 가능한 보조 지표로 두고, 아직 확인하지 않은 많은 항목을 첫 화면의 실패 경고처럼 표시하지 않는다. 다만 실제 임박 기한이나 중요 정보 공백은 감추지 않는다.

## 6. 일정·자료·노트북의 역할

### 일정: 전체 업무를 시간순으로 이해한다

처음에는 연간·월간 흐름을, 일상 수행에서는 확인된 기한을 볼 수 있게 한다. 한 업무의 시기는 업무 안내에서도 요약하지만 전 업무의 시간 배치는 일정에서 제공한다. 확정 기한·준비 권고·과거 반복 패턴은 공통 데이터를 사용해 구별한다.

### 자료: 설명을 검증하고 필요한 원문을 찾는다

업무 설명에서 누른 근거는 공통 패널로 보여 주고, 자료 메뉴에서는 전체 검색·판본·원문·만든 문서를 탐색한다. 후임자가 먼저 파일을 해석해야 업무가 무엇인지 알 수 있는 순서를 줄인다.

### 노트북: 업무에서 필요할 때 이어 쓰는 도구

업무 안에는 ‘이 업무 자료에 질문’, ‘지난번과 비교’, ‘초안 만들기’처럼 목적이 분명한 진입을 제공한다. 실제 처리 경로는 기존 질문·비교·초안·실행 기능에 연결하며, 같은 기능을 여러 곳에 새로 구현하지 않는다. 업무·대상 연도·자료 선택 범위를 전달하고 결과를 해당 수행 건에 연결한다.

노트북 보조 진입은 여러 업무를 비교하거나 업무와 무관한 자료를 조사할 때 사용한다. 후임자는 노트북이라는 개념을 먼저 배우지 않아도 업무 안내와 수행 지원을 받을 수 있어야 한다.

## 7. 첫날 이후에도 일관된 구조

업무 메뉴 안에 `전체 업무 | 챙길 일` 전환을 둔다. 첫 사용은 전체 업무로 시작하고, 익숙해진 사용자는 챙길 일을 기본 보기로 직접 선택할 수 있게 한다. 안내는 언제든 다시 볼 수 있다.

설치 후 며칠이 지났다는 이유나 확인 표시 개수만으로 사용자를 ‘숙련’ 단계로 자동 전환하지 않는다. 제안 유무에 따라 진입 메뉴가 바뀌지도 않는다. 긴급한 항목은 전체 업무에서도 요약 경고와 정확한 업무로 가는 링크를 제공한다.

사용 흐름은 다음과 같다.

```text
첫날: 전체 업무 파악 → 업무 안내 → 대표 결과물·처리 흐름 → 첫 행동
수행: 챙길 일 확인 → 해당 업무·수행 건 → 진행 → 결과 기록
막힘: 업무 안내/근거 확인 → 질문·비교 → 필요한 정보 확인 → 수행 재개
```

## 8. 구현 우선순위 재조정

| 우선순위 | 작업 | 재사용 기반 | 확인할 결과 |
|---|---|---|---|
| 1 | 업무 설명의 내용 계약과 대표 업무 표본 작성 | `core/workcard.py`, 업무 항목·원문·처리 순서 | 처음 보는 사람이 목적·결과물·첫 행동을 설명할 수 있는가 |
| 2 | 전체 업무 첫 화면과 업무 안내 시안 | `views/tasks.py`, 업무 카드·대표 자료 | 무엇을 맡았고 무엇부터 볼지 선택할 수 있는가 |
| 3 | 안내 상태와 사실 확인의 분리 | `core/guide.py`, 기존 확인 기록 | 검수하지 않아도 이해·탐색·시작이 가능한가 |
| 4 | 주 대메뉴·보조 도구 배치, 상세 탭·이동 개편 | `shell.py`, 기존 일정·자료·노트북 화면 | 초보자의 기본 경로와 숙련자의 직접 접근이 모두 유지되는가 |
| 5 | 실행 수명·정확한 연도·노트북 맥락·산출물 연결 | 이전 통합계획의 공통 기술 작업 | 첫 행동을 시작한 뒤 진행과 결과가 끊기지 않는가 |
| 6 | 설명서·키보드·배율·회귀·실사용 검증 | 기존 UI·코어 시험과 사용자 과제 | 근거·현재성·승인·자료 범위가 유지되는가 |

내용 계약은 모든 필드를 반드시 AI로 채우라는 뜻이 아니다. 확인된 자료로 채운 내용과 비어 있는 정보를 함께 표현하는 규칙이다. 정확한 단순 설명과 대표 결과물을 먼저 만들고, 근거 없는 풍부한 설명은 허용하지 않는다.

기술 기반은 의존성에 따라 병행할 수 있지만 화면 개편의 성공 판정은 **실행 건수보다 업무 이해와 첫 행동**을 우선한다. 기존 계획의 오늘 승격·일정 하위화 작업은 실행 대상에서 제외한다. 공통 챙길 일 조회·실행 서비스·데이터 이전·근거 보존 작업은 계속 유효하다.

## 9. 성공 여부를 확인하는 방법

‘메뉴를 찾았는가’와 함께, 전임자 없이 처음 맡는 업무의 표본을 사용해 다음을 관찰한다.

1. 후임자가 자료에서 파악된 업무의 전체 그림과 담당 여부가 아직 불확실한 항목을 설명한다.
2. 업무 하나의 목적과 최종 결과물을 자신의 말로 설명한다.
3. 첫 행동을 선택하고 실제로 그 자료·화면·준비 작업에 도달한다.
4. 올해 확인된 기한과 과거 반복 시기를 구분한다.
5. 아직 모르는 정보와 다음 확인 방법을 찾는다.
6. 근거가 부족할 때도 도움이 되는 안내를 받으며, 사실을 억지로 확인할 필요가 없다.
7. 이후 사용에서는 진행 중인 일을 재개하고 결과를 다시 찾는다.

사용 시간·도움 요청·되돌아가기와 사용자 자신의 막막함 변화를 함께 기록한다. 임의의 이해도 점수나 클릭 수를 업무 숙련의 대리 지표로 삼지 않는다. 사용자 시험 전인 현재는 설계 가설이며 실제 개선 효과를 측정했다고 보고하지 않는다.

**첫 화면을 본 후 사용자가 “어떤 일을 해야 하는지 알겠다”, 업무 하나를 본 후 “무엇부터 하면 되는지 알겠다”라고 말하고 그 행동으로 이동할 수 있는가가 이번 개편의 기준이다.**
