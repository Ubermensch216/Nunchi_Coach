# 지식그래프 P2 구조 투영 구현 기록

작성일: 2026-10-11. [상세 구현 계획](지식그래프_온톨로지_상세구현계획_2026-10-11.md)의 P2를 [P0·P1 저장 기반](지식그래프_P0_P1_구현기록_2026-10-11.md) 위에 구현했다.

아래는 P2 완료 시점의 기록이다. 자동 큐 실행·삭제·중단 재개·세대 경쟁과 최신 검증은 이후 추가한 [P3 구현 기록](지식그래프_P3_구현기록_2026-10-11.md)을 따른다.

## 구현 범위

`app/core/knowledge/projection.py`의 문서·업무 단위 투영은 모델을 호출하지 않는다. 기존 정본을 읽고 그래프 테이블과 그래프 전용 메타데이터에만 기록한다. 같은 입력을 다시 처리하면 기존 게시 세대를 재사용하며 반복 예약도 완료로 정리한다. 입력 지문에는 원본 해시, 파서·파싱 결과, 현재 조각 식별자, 색인 revision, 사람 결정 revision을 구분해 포함한다.

- 문서 판본: 프로젝트 내 문서 UUID와 원본 내용 해시로 식별한다. 같은 해시의 다른 문서는 선택·출처를 보존하고, 같은 문서의 재파싱은 원본 판본을 추가하지 않는다. 현재 인용 조각 참조는 재색인 시 갱신한다.
- 업무–문서: 실제 `task_docs` 배정과 origin·confidence를 구조 근거로 연결한다. 모델 배정의 추정 상태를 사람 배정과 구분한다.
- 실제 수행 건: 기존 `work_cases`만 Case로 만들고 업무·연도·label·수행 상태를 보존한다. 과거 문서나 `task_steps`로 실제 Case를 생성하지 않는다.
- 단계: `work_steps`, 과거 `task_steps`, 실제 `action_steps`를 각각 다른 binding으로 투영한다. 명시적인 `after_step_id`만 PRECEDES로 연결하고, 다른 업무의 선행 단계는 진단한다. Task의 모든 단계를 모든 Case에 붙이지 않는다. Case–Step은 실제 체크리스트·실행 연결이 있을 때만 만든다.
- 실행·산출물: 원장의 Case/Step–Artifact 연결과 명시적인 `supersedes_id`를 투영한다. 실행 상태는 별도 캐시로 보존하며 승인·완료·산출물 파일은 수정하지 않는다.
- 항목: 기존 제출처·담당·서식을 Organization/Role/Form 후보로 연결한다. 이름만 같다고 전역 병합하지 않는다. 기한은 이미 완전한 ISO 날짜인 값만, 금액은 명확한 십진수·통화/단위인 값만 투영한다. 연도가 없는 기한·조건부 금액은 채워 넣지 않고 진단한다. 동일 리터럴도 서로 다른 원본 슬롯의 기간·상태를 합치지 않는다.

## 근거·사람 판정 보존

`evidence.py`는 기존 근거의 문서 해시·문서 위치를 확인한 뒤 파싱 문자열의 공백 정규화와 원문 위치 사이의 매핑을 만든다. 실제 정확한 인용과 section ordinal·문자 범위를 저장한다. 표는 실제 구간과 머리글 구조를 보존한다. 본문 앞부분을 대체 인용으로 쓰지 않는다.

인용 일치 결과는 `quote_matched`이며 관계의 의미를 검증한 `semantic_supported`로 승격하지 않는다. 없는 인용·다른 판본·사라진 원본은 비활성 invalid 근거와 진단으로 남긴다. 사람이 확인했다는 이유로 원문 불일치를 통과시키지 않는다. 사람의 독립 진술은 원문 인용과 다른 kind로 보존한다.

같은 인용은 재색인 후에도 같은 anchor를 사용하고 chunk ID만 갱신한다. 동일 내용 사본은 `independent_quote_sources()`에서 해시별 한 번만 센다. 기존 근거 ID·교체 시각은 논리 anchor로 사용하지 않는다.

세대 게시 때 이전 파티션 support만 비활성화하고 다른 활성 근거를 재평가한다. 주장·인용 스냅샷·사람 결정은 삭제하지 않는다. 안정된 주장 키의 거절과 취소를 재적용하고, 별도 사람이 추가한 별칭도 유지한다. 상태 이벤트는 그 변화를 관측한 세대를 가리킨다. 동일성 merge/separate의 canonical view와 사람 판정 UI는 P3/P5 이후 범위다.

## 파이프라인 접점과 실행

일반 분석은 `_restore` 완료 뒤 업무 투영을 **예약**한다. 노트북 `write_parse` 및 이미 분석한 문서 재사용도 문서 투영을 예약한다. 노트북 업로드를 기존 업무에 자동 배정하지 않는다. 앱 시작에서 전체 투영을 실행하지 않는다.

현재 투영은 개발용 명령으로 실행할 수 있다. 큐 lease 작업자·중단 재개·사용자 예산·파티션 종속 갱신의 자동 연결은 P3에서 구현한다.

```powershell
.\.venv\Scripts\python.exe -m app.tools.knowledge_project --project D:\경로\기존프로젝트
.\.venv\Scripts\python.exe -m app.tools.knowledge_project --project D:\경로\기존프로젝트 --task 1
```

명령은 기존 `project.db`만 열고 문서/업무 하나씩 처리한다. 원본 정본·원본 파일·승인·완료 상태는 그대로 유지한다. JSON으로 세대·관계 수·재사용·진단을 출력하며, 진단이 있으면 종료 코드 1을 반환한다. 이를 자료 전체의 의미 이해 완료로 표시하지 않는다.

## 검증 및 남은 사항

관련 회귀 **217건 통과(79.50초)**. 지식그래프·마이그레이션·노트북 업로드·파이프라인·업무 수행/편집·새로 읽기·재색인·인계·강제 종료 재개 시험을 함께 실행했다. 시험은 합성 SQLite 정본·합성 문서 기준이다. Windows 실행물은 새 접점 모듈을 포함해 다시 빌드했다.

최종 Windows 검증은 `PyInstaller --clean --noconfirm NunchiCoach.spec`로 캐시를 초기화해 수행했다. 번들의 최신 저장 API와 큐 예약 모듈 포함, 개발용 RDF/SHACL 모듈 제외를 코드 객체에서 확인했다. 번들 EXE의 `selftest`는 합성 파일 77개 파싱과 복원→수행 기록→복원본→묶음→가져오기→재연결을 통과했다. 실제 HWP 표본 및 실제 기관 자료 정확도는 이 결과에 포함하지 않는다.

투영 반복 시 ID·주장·근거·세대·이벤트 수가 같은지, 정본이 불변인지, Case를 만들지 않는지, 단계가 다른 Case에 자동 확산되지 않는지, 승인·수행 상태가 유지되는지 확인한다. 인용 위치·표 머리글, 거절·취소·사람 별칭, 재색인 ID 변경, 동일 해시 다중 사본, 재파싱과 원본 판본 분리, 합쳐진 업무의 이전 Case, 잘못된 인용의 보류와 서로 다른 슬롯의 적용성 보존도 검사한다.

P3의 삭제 tombstone·문서 변경의 종속 업무 갱신·강제 종료 후 lease 재개·세대 게시 경쟁·동일성 canonical view가 남아 있다. 기존 관계를 뒤집는 단계 재정렬은 오래된 관계 이력의 순환 제약과 활성 세대의 순환 검사를 구분하는 P3 보강이 필요하다. P2에서는 순환 제약을 우회하지 않고 진단한다.

P4의 선택 범위·연도 공통 해석·그래프 검색·RAG 결합과 P5 UI, P6 품질·규모 평가, P7 인계 v2는 아직 미구현이다. 현재 일반 RAG 결과에 그래프를 섞지 않는다. P0 정답의 독립 검토·실자료 확보 및 계획의 출하 게이트도 남아 있다.
