# 노트북 개편 구현·검증 기록

기준: 2026-10-09 / 시작 커밋 `25eb845` / 이 문서의 변경은 작업 트리에 있으며 커밋·푸시는 하지 않았다.

노트북을 "선택한 원문으로 탐구하는 보조 화면"에서 **자료를 모아 묻고, 정리하고, 문서로 내보내는 작업 공간**으로 바꿨다. 화면 구성은 Gemini Notebook(카드 홈 → 출처 | 대화 | 스튜디오)을 따랐고, 검색·법령 조회는 `myAI`, 서식 모델은 `onNara.sAIde`를 참조해 Python으로 옮겼다. 두 프로젝트의 코드는 수정하지 않았다.

사용법은 루트 [README 7-6절](../README.md#7-6-노트북--자료를-모아-묻고-정리하고-문서로-남기기)에 있다. 이 문서는 무엇을 어떻게 만들었고 어디까지 확인했는지를 적는다.

## 데이터 계약 (스키마 v6 → v7)

`project.db.bak-v6`을 만든 뒤 트랜잭션으로 올린다. 기존 행은 바꾸지 않는다.

- 열 추가: `notebooks`(icon·updated_at·last_opened_at·layout), `notebook_sources`(origin·added_at·summary·topics), `notebook_messages`(thread_id·standalone_question·law_citations·mode·rating), `notebook_notes`(kind).
- 표 추가: `law_cache`, `doc_templates`, `notebook_outputs`, `output_files`.
- `chunks`·청킹 규칙·파서 판은 건드리지 않았다. 동결한 질문 평가 세트의 기준을 지키기 위해서다.
- 올린 파일은 `<프로젝트>/uploads/<해시 앞 16자>/<이름>`에 사본으로 두고 `sources.kind='upload'`로 등록한다. 이 자료원은 `Database.work_sources()`에서 빠진다 — 자료 폴더 목록·폴더 훑기·문서 벡터(업무 발견의 재료)에 들어가지 않는다. 출력 보호는 계속 `sources()` 전체를 본다.
- 법령 인증키는 프로젝트 DB가 아니라 사용자 폴더(`%LOCALAPPDATA%\\NunchiCoach\\settings.json`)에 둔다. 켜짐 여부(`law_enabled`)만 프로젝트 메타에 있다.

## 지킨 원칙과 그 자리

| 원칙 | 구현 |
|---|---|
| 과거 AI 답변은 근거가 아니다 | 후속 질문 풀이는 앞선 **질문**만 본다. 문서 초안의 재료는 대화가 인용한 **원문 대목**이다 |
| 선택 밖 자료는 보이지 않는다 | 자료 선택이 달라지면 지난 답을 가린다. 인용 원문도 지금 선택한 자료의 것만 편다 |
| 문장마다 근거, 규칙으로 재검증 | 전체 정리의 사실·엮은 문장, 법령 답변, 문서 초안 모두 `verify_sentences`를 지난 것만 남긴다 |
| 모르면 비운다 | 근거 없는 문서 항목은 `확인 필요`. 법령 조회 실패는 실패로 알린다 |
| 밖으로 나가는 것은 최소로 | 법령 조회는 기본 꺼짐 → 인수인계마다 켬 → 질문마다 고름. 닿는 주소는 `www.law.go.kr` 고정. 조문 인용이 있으면 법령 이름·조문 번호만, 없을 때만 그 질문 문장을 보낸다 |
| 법령 이름에 앞말을 싣지 않는다 | `refs.tail_name`은 짧게 고르는 쪽으로 틀린다("김 주무관 건인데 지방계약법" → 지방계약법만) |
| 원본은 읽기만 | 올린 파일의 원래 자리와 온나라 수집 폴더를 바꾸지 않는다(시험으로 바이트 대조) |
| 질문 화면의 검색은 그대로 | 질의 확장은 `ask(…, expander=)`로 노트북 경로에만 준다. 규칙으로 답하는 경로에서는 부르지 않는다 |

### 확인하지 못한 것

- **실제 law.go.kr 호출.** 응답 모양을 본뜬 대역으로만 시험했다. 특히 질문 문장으로 조문을 찾는 `target=aiSearch`의 실제 응답 모양은 myAI의 파서를 따랐을 뿐 직접 받아 보지 않았다. 설정의 **연결 확인**은 법령 이름 검색(`target=law`)만 확인한다.
- **한글에서 HWPX 열기.** 꾸러미 구성·XML 정합·자체 파서 되읽기만 확인했다. 한글 프로그램이 여는지, 글꼴·줄간격이 의도대로인지는 사용자가 확인해야 한다. 표본은 `data/notebook-demo/`에 두었다(저장소에 올리지 않는 폴더).
- **검색 다듬기의 정확도.** 질의 확장·후속 질문 풀이가 정답률을 올리는지 동결 평가 세트로 재지 않았다. 노트북 경로에만 켜 두었고 `notebook_query_expansion=0` 메타로 끌 수 있다.
- **실제 기관 문서·스캔본.** 모든 확인은 합성 자료다. 손글씨·도장·저해상도 스캔에서의 그림 판독 정확도는 모른다.
- **깨끗한 PC·PyInstaller 번들.** 이번에 다시 빌드하지 않았다.

### 실제 모델 실행에서 본 한계

- 전체 정리와 문서 초안에서 모델이 문장의 근거 번호를 넓게 붙이거나(한 문서의 사실에 다섯 문서를 모두 근거로 댐), 단계 이름을 다른 문서의 것과 바꿔 쓰는 일이 있었다. 숫자·날짜는 규칙 검증이 잡지만 이런 서술은 잡지 못한다. 화면과 README에 근거를 대조하라고 적었다.
- 같은 문장을 대목마다 되풀이하던 것은 코드에서 합치고(`compose._distinct`), 앞 항목에서 쓴 문장은 뒤 항목에서 뺀다.
- Pretendard로 만든 PDF는 화면은 맞지만 글자를 긁으면 쌍점이 다른 글자로 나왔다. PDF는 이 PC의 맑은 고딕을 먼저 쓰고 쓴 글자만 추려 넣는다(없으면 Pretendard).

- `pytest -q -rs`: **1,424개 통과 · 4개 건너뜀 · 경고 2개**, 523초. 위 표의 시험 93개가 여기에 들어 있고, 기존 시험 가운데 노트북 화면 2건(`test_notebook_ui.py`, `test_rag_facts.py`의 상충 대조 화면)은 새 화면에 맞게 다시 썼다.
- 건너뛴 4개는 실제 모델 접속 시험 3개(`NUNCHICOACH_LIVE_AI`)와 기관 실문서 표본 1개로, 이전과 같다. 경고는 pytest 설정 항목과 기존 Qt 마우스 이벤트 생성자 안내다.
- `python -m app.tools.lockfile --check` 통과 — 새 의존성을 더하지 않았다.
- 실제 `MainWindow`에서 노트북 메뉴 진입, 법령 조회를 켠 뒤 상단 띠 표시와 입력칸의 `법령`, 자료 폴더가 없는 프로젝트에서 노트북만 열리는 것을 스크립트로 확인했다.
