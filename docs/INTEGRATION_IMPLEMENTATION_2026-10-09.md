3. 업무 합치기·나누기는 문서만 옮겼다. 복원 항목·수행 기록·검토 기록이 따라가지 않고 각 SQL이 자동 커밋되므로 부분 실패에도 일관성을 보장하지 못했다.
4. 모델이 없으면 조각은 생성되지만 질문 UI와 RAG는 검색을 차단했다. 보고서 NB-02/03의 모델 OFF 동작과 어긋났다.
5. 독립 노트북·소스 선택·노트 수정 이력·지식 승격·업무 게시 계층은 없었다. 기존 프로젝트나 업무 범위와 노트북을 동일하게 취급하면 소스 격리가 깨질 수 있다.

7. `.analysis_audit` 1,981개 파일이 여전히 추적되고 있어 저장소 guard는 통과할 수 없다. 기존에 정한 사용자 직접 Git 작업 방침에 따라 인덱스·이력을 바꾸지 않았다.

## 데이터 계약과 마이그레이션

- 기존 `documents`/`chunks`/`tasks`가 원장이다. 원문 파일은 복사·수정하지 않는다.
- 스키마 **v5 → v6**: `notebooks`, `notebook_sources`, `notebook_messages`, `notebook_notes`, `notebook_note_revisions`, `knowledge_cards`를 추가한다. 기존 표의 데이터 변경은 없다. 기존 SQLite backup API로 `project.db.bak-v5`를 먼저 만든 뒤 트랜잭션으로 이행한다.
- `SourceRef`: `doc_id`, `chunk_id`, `version_hash`, `locator`, `exact_quote`. 같은 위치의 긴 본문이 여러 조각으로 나뉘어도 `chunk_id`로 실제 인용한 조각을 보존한다. 노트의 JSON 근거에는 해당 판본의 원문 구절이 저장된다. 이것은 원본 파일 복사본이 아닌 인용 스냅샷이다.
- `Notebook`: 원문 링크와 선택 상태. `doc_ids=None`은 프로젝트 전체, `[]`는 허용 문서 없음이다. 빈 선택을 전체 검색으로 넓히지 않는다.
- `Answer`: 매 턴 선택 소스 스냅샷·질문·답·인용·모델·진단을 저장한다. 벡터와 FTS는 소스 범위를 먼저 제한한다. 다른 노트북·범위 밖 문서는 생성 문맥이나 관련 문서로 노출하지 않는다.
- `Note`: AI 초안으로 저장하고, 수정할 때 판과 이유를 추가한다. 저장 자체로 검증 지식이 되지 않는다.
- `KnowledgeCard`: 특정 노트 판·원천 근거·검토자·적용 조건·선택 만료일·게시 업무를 연결한다. 본인 인증이나 공식 행정 승인을 보장하지 않는다.
- 원문 해시·인용 위치·인용문을 기계적으로 대조하고, 적용 조건을 사람이 검토한다. **주장 단위 의미 검증이나 법적 효력 판단은 이번 구현이 아니다.**
- 노트북 검색은 선택한 원문 파일의 실제 SHA-256도 확인한다. 원문이 변경됐지만 재분석 전인 경우에도 이전 인용의 승격·게시·내보내기를 차단한다.
- 노트북의 대화 문맥은 같은 소스 스냅샷에서 직전 질문만 사용한다. 과거 AI 답변을 독립 증거로 검색에 넣지 않는다. 모호한 지시어의 완전한 해석이나 일반적인 멀티턴 대화 완성은 후속 작업이다.
- 노트를 검색 소스로 다시 추가하는 기능은 아직 제공하지 않는다. 따라서 현재 구현에는 파생 노트를 독립 증거로 재인용하는 경로가 없다.

## 업무 편집 정합성 정책

합치기는 항목·단계·공백의 ID를 유지해 근거·검토·수행 기록을 보존한다. 같은 slot의 값은 덮어쓰지 않고 별도 이름으로 보존한다. 기존 주기·과거 처리 기록과 게시 지식·노트북 업무 연결도 옮긴다.

나누기는 근거와 참조로 연결된 항목/단계/공백을 하나의 묶음으로 판단한다. 모든 원문 근거가 선택한 문서에 속하는 묶음만 이동한다. 양쪽 자료에 걸치거나 근거가 끊긴 묶음은 기존 업무에 보존하며 재확인한다. 선택하지 않은 문서·문서가 아닌 ID·모든 문서를 떼는 선택은 거절한다. 편집으로 옮긴 기록은 사용자 기록으로 보존해 재분석이 삭제하지 못하게 한다.

전체 변경·복원본·감사 기록이 하나의 트랜잭션에 들어간다. 중간 실패 시 모두 원복한다. 외래키 및 검토 대상 참조를 사후 검사한다. 복원본은 전체 DB 되돌리기 버튼이 아니라 기존 복원 결과 스냅샷이다. 전체 프로젝트 백업/복원 UI는 P1-04 후속 작업으로 남는다.
