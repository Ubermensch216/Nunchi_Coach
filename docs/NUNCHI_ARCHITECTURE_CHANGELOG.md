# 구조 변경·승격·롤백 기록

기준일 2026-10-10. 기준 커밋 `73145c2`. 변경은 기존 Python/SQLite/Qt 구조 안에서 수행했다.
기존 파서·RAG 부모/자식·재색인 전환·노트북 인용 저장 구조를 교체하지 않았다.

중단 후 재개 기준은 `09de9c6`이다. 다른 작업이 앞선 개선을 `211b7eb`에 커밋했고 실행 엔진을
추가해 현재 스키마는 v10이다. 이 작업은 v10을 v9으로 되돌리지 않으며, 미커밋 soft-IDF 개선도
보존한다. 아래 v9 설명은 앞선 진단 구조 추가의 기록이다.

## DB v8 → v9

기존 승격 경로가 SQLite backup API로 `project.db.bak-v8`을 먼저 만든다.
v9은 조사 실행·항목, 문서별 처리 오류, 단계 결과, 분류 근거, 보류 군집 표를 추가한다.
기존 문서·업무·사람 교정·수행 이력·노트북 데이터는 승격 과정에서 변경하지 않는다.
승격 단계는 트랜잭션이며 실패하면 버전을 올리지 않는다. 신규/구버전 승격 시험으로 검증한다.

앱의 실제 사용자 프로젝트를 이번 작업에서 열거나 승격하지 않았다. 모든 승격 시험은
임시 합성 DB에서 수행했다. 사용자가 새 버전으로 기존 프로젝트를 열 때 승격된다.
현재 앱은 후속 실행 엔진의 v10까지 승격한다.

## 롤백

앱을 닫고 현재 v9 프로젝트 폴더 전체를 별도 보존한다. v8 백업을 **새 복구 폴더**에
`project.db`로 복사한 뒤 기준 코드로 연다. v9 DB의 버전 문자열만 8로 바꾸지 않는다.
백업 시점 이후 v9에 남긴 사용자 교정은 v8 백업에 없으므로, 현재 프로젝트를 덮어쓰지 말고
복구 프로젝트와 비교해야 한다. 기존 색인 전환의 `app.tools.reindex --rollback`은 조각
전환만 되돌리는 기능이며 DB 스키마 롤백과 다르다.

소스 원본은 `.test_runs/nunchi-upgrade-originals-20261010/`에 보존했다. 후속 수정이 있는
파일을 이 백업으로 일괄 덮어쓰지 않는다. 커밋/푸시는 수행하지 않았다.

## 운영 영향

- 원본 쓰기 경로는 추가하지 않았다. 진단 출력도 기존 안전 내보내기 정책을 사용한다.
- 조각을 먼저 준비하므로 최초 업무 카드 생성 시점은 기존보다 늦어질 수 있다.
- 기존 조각 임베딩을 재사용한다. 별도의 전 문서 생성 모델 호출은 추가하지 않는다.
- 작명 호출은 군집당 1회다. 최대 6문서에서 선택한 발췌만 주며 나머지를 검토했다고 표시하지 않는다.
- 모델 호출 동안 DB 쓰기 잠금을 잡지 않는다. 저장 직전 내용 판본·교정 보호 집합을 다시 확인한다.
- 조사 기록은 실행별로 누적된다. 보관기간·정리 UI는 아직 없다.
- `scan_verify_hash=1`은 크기/시각이 같아도 전체 해시를 다시 읽으므로 대규모 조사 비용이 늘어난다.
- 평균 유사도 계산의 n×n 임시 행렬은 제거했으나, 군집 후보 탐색은 여전히 대략 이차 시간이다.
