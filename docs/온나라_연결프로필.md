## 1. 운영 원칙 및 수집 경로

1. **눈치코치는 온나라 서버에 직접 접속하지 않는다.** 전임자 계정·인증정보를 앱에 입력받지 않으며, 확인되지 않은 내부 URL을 호출하지 않는다.
2. **합성 연결부와 실환경 미확인 표시 유지:** `FixtureConnector`는 `simulation=true`, `live_verified=false`를 유지하며, `SaidePackageConnector`도 실제 기관 온나라 검증(V1/P6) 전까지 `live_verified=false`를 유지한다.
3. **세 가지 가져오기 경로:**
   - **최초 시작(온보딩) 화면 (`app/ui/views/onboarding.py`):** `+ 온나라 자료 가져오기`로 이미 받은 꾸러미·수집본 폴더를 등록하거나, 브리지로 연결된 `onNara.sAIde`에 조건(기안자·기간·키워드·생산/접수)을 담아 **온나라 수집 요청**을 보낼 수 있다.
   - **설정 › 자료 폴더 (`app/ui/views/settings.py`):** `+ 온나라 자료 가져오기`로 꾸러미(`package.json`)나 수집본(`manifest.json`)을 프로젝트 자료원으로 추가한다(`app/core/onnara_import.py`의 `add_to_project`).
   - **노트북 (`app/ui/views/notebooks/sources_panel.py`):** `+ 자료 추가 → 온나라 수집본 가져오기`로 노트북 출처로 바로 연결한다.
   - **명령줄 도구:** `python -m app.tools.onnara_demo`(합성 수집) 및 `python -m app.tools.onnara_package --package <꾸러미> --output <수집 폴더>`.

## 2. 공문 기준 업무 복원 및 비교 고도화 (2026-10-30 반영)

- **공문 기준 업무 골격 (`P3`):** 수집된 공문(`source_records`)의 단위과제(`task_card`) → 제목 알맹이 → 본문이 인용한 문서번호를 기준으로 업무 골격을 먼저 세운다. 단건 공문이라도 대응된 로컬 PC 파일이 있으면 업무로 승격한다.
- **PC 파일 5단계 대응 (`P4a`):** 로컬 PC 자료는 ① 공문 파일과 해시 일치(`high`) ② 파일 이름에 공문 문서번호(`high`) ③ 파일 이름에 공문 제목 알맹이(`medium`) ④ 대응된 파일과 같은 폴더(`low`) ⑤ 공문 본문과 임베딩 코사인 유사도 0.72 이상(`low`) 순으로 공문 업무에 배정한다.
- **공문 ↔ 로컬 비교 (`P5`):**
  - 같은 업무·연도의 로컬 초안과 온나라 등록본을 한 판 묶음(`version_groups`)으로 묶고 온나라 등록본을 대표(`latest_doc_id`, `"온나라에 등록된 판"`)로 삼는다.
  - 시간표(`timeline.py`)와 연간 주기(`repo.py`)에서 공문의 기안·시행·접수일(`authored_at`)을 최우선 날짜 근거로 사용한다.
  - **공백 3종 감지 (`continuity.py`):** 회신·결과 공문 미확인(`unanswered_official`), 시행 등록 미확인(`unregistered_final`), 공문 붙임 누락(`missing_attachment`)을 감지하고, 값 충돌 시 공식 기록과 `개인 폴더 자료(PC 파일)`을 명시적으로 대비한다.
- **사본 인계 폴더 (`P4b`):** 인수인계 화면에서 `<출력루트>/<업무>/<연도>/공문/` 및 `PC자료/` 구조로 원본을 건드리지 않고 사본 인계 폴더와 `00_인계_안내.md`·`00_업무안내.md`·`manifest.json`을 생성한다(`app/core/handover_folder.py`).
